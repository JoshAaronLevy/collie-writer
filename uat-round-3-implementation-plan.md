# UAT Round 3 — Direct, readable AI conversations

October 12, 2026. **Plan updated with Josh's approved decisions; implementation has not started.**

This plan addresses all six items in [uat-notes.md](uat-notes.md) and all five supplied `AI Chats` screenshots. It is based on the current working tree, including the existing uncommitted Import/RF12 corrections. It does not assume those corrections, earlier AI stages, or native runtime behavior have passed user acceptance.

## Context and intended experience

The current problem is structural: an imported conversation is presented through a technical transcript preview inside the ordinary chat pane. Opening the title reveals a history button; that reveals a preview with another Read button; its messages expose excerpts with yet another Read button. The screenshots show the resulting blank space, repeated decisions, raw dates, message numbering, and provenance metadata. This behavior makes protected local reading feel like a multi-step operation.

The finished interaction should be:

1. Select a conversation title and immediately see its messages, with the newest at the bottom and in view.
2. Read the complete message body with formatting. User messages sit on the right; assistant messages sit on the left, with restrained, distinct background colors.
3. See a small, readable timestamp and a Research icon only when that message has actual linked Research. No numbered role headings, historical/import labels, original-text buttons, or origin/variant panels appear in ordinary chat.
4. Type the next message. **Search the web** is an actual checked checkbox by default, and can be unchecked. Only Send starts AI work.
5. Scroll upward to read older content without being pulled back down while reading. Selecting a chat afresh starts at the latest message; a deliberate source-origin link opens its exact message instead.
6. See available images inline automatically, including images at public HTTPS addresses. Play direct audio/video through native inline controls. PDF documents and hosted players such as YouTube remain ordinary links.

Apply the presentation consistently to imported messages and native Collie messages. Imported records must remain imported records; they do not acquire fabricated request attempts, completion states, or user/assistant pairing.

The stages below are deliberately limited to three cohesive changes. There is no separate framework, redesign, cleanup, or acceptance implementation stage. Each stage removes the code it replaces and includes its own documentation, required code checks, and user-owned manual guide.

## Implementation decisions and limits

- **Keep the retained owner.** `ConversationProvider`/`conversationState.ts` continue to own selection, drafts, operations, native responses, source review, and project identity. Add only bounded local read state needed for imported messages. Do not create a second conversation store or job system.
- **Keep one visible timeline.** Imported messages precede native continuation. Preserve stored sequence/ordinals even when timestamps are missing or inconsistent. Preserve consecutive same-role messages. Never reorder by import time or force alternating pairs.
- **Separate reading from recall.** Exclusion from AI context is not permission to erase retained history. Respect existing visibility rules; do not expose internal reasoning or make an excluded record eligible for recall through presentation changes.
- **Open at the latest message.** A deliberate title selection resets to the latest content, including selecting the same chat after returning to the list. Keep position while the user is actively reading upward. A targeted Research/recovery navigation takes precedence over bottom scrolling.
- **No new search feature.** Remove title search and Find from the chat surfaces. Preserve project-wide Search and any genuinely live non-chat consumers. Remove dead controller/UI code after tracing callers; frozen historical data readers are not disposable UI code.
- **Readable dates without invented facts.** Use relative time for recent messages, Yesterday with local time, and a short localized date/time for older messages. Use actual message time, never import time as a substitute. Preserve date-only precision; omit an absent/invalid timestamp rather than inventing a time or showing “Historical time.” Show exact available time in a tooltip/accessibility description where useful.
- **Web-search defaults are UI intent.** New/opened chat sessions start checked unless the user has an explicit in-session choice for that chat. Preserve unchecked choices while moving between chats in the same project session; resetting on application restart is sufficient. Keep this small state with the existing controller. Do not rewrite saved captures, silently fall back, or send anything on opening/checking. Explicit “Try without web search” must still produce an unchecked new draft.
- **Automatic images and direct media are approved.** Display supported public HTTPS images automatically when their messages are shown, without a Read/Load step or repeated consent. Retained local images work offline. Include direct audio/video files when usable retained bytes or public HTTPS URLs exist, with native controls and no autoplay. Keep PDF documents and hosted website players as ordinary links; embedded webpages are outside this round. Unavailable media gets a short inline fallback while the message text remains readable. Media hosts receive no ChatGPT credentials, app cookies, or manuscript/message text. Remote display bytes remain temporary; loading a URL does not automatically retain it in the portable project.
- **Native actions remain contextual.** Copy, reuse-prompt, and sent-context actions belong in an accessible message context menu. Keep selection-triggered Save reference and put Add to Research/Cite/source navigation inside the source disclosure. Messages with active linked Research expose its small icon; unsaved web references remain reachable through a Sources item in the context menu without pretending they are saved Research. Stop and actual failure/recovery actions remain visible only when relevant.
- **No routine technical explanation.** Remove imported-history counts/instructions from the message area. Loading and actionable errors are contextual, short, and do not require approval to read local content.
- **Use established UI.** Mantine controls, Tabler icons, theme tokens, and semantic feature-scoped CSS. Keep keyboard access, role announcements, high contrast, reduced motion, and narrow-window readability. Bubble alignment must not be the only accessible indication of authorship.

### R3-01 — Open chats directly and make the basic controls clear

**Status:** Not started. **Model:** Sol 6.1. **Effort:** High.

**Outcome:** A conversation title opens real message content immediately, at the newest message, with no intermediate Read/Find screens. Web search is visibly checked by default.

1. Remove the list's Search and history block, title-search input, Find menu action, `ConversationFind` mounting, and their now-unused state/callbacks/styles. 2. Replace `importedOpen` and the nested preview with direct imported-prefix loading coordinated by the existing controller. Keep native turns on their established streaming/recovery path. Introduce a small read hook only if it clearly isolates imported read paging and cancellation; it must not own another selected chat, draft, or provider.
3. Extend the existing transcript reader with a narrow imported-prefix range for this consumer, validated through shared/main/worker boundaries. Display both as one ordered timeline without duplicating native entries from the combined transcript projection.

Load only the displayed window with bounded in-flight work; do not load every message in a large conversation. Long text must continue automatically, with a brief loading/error state in its bubble rather than another Read or Next text button. Retry appears only after a real failure.
6. Extend scroll anchors to stable imported and native message identities. 5. Keep web citation badges attached to their original canonical ranges and preserve existing external-link handling. Support incomplete Markdown during streaming without throwing, losing received text, or resetting scroll/focus. Delete the superseded regex parser in this stage; do not keep parallel permanent renderers for old and new chats.
6. Load imported linked-source information automatically for the bounded displayed window using the existing `imported-links` owner. A small capped set of reads is sufficient; do not introduce a background project-wide index or persistent link-count cache. Keep inline web citations as links. A Sources item in the message context menu opens the same source disclosure for unsaved references, including Add to Research; the icon remains conditional on actual linked Research. Put Cite and source navigation in that disclosure. Distinguish “Sources used in this answer” from “Saved in Research” where needed. Do not fabricate accepted relationships from the presence of a URL.
9. Remove permanent Copy/message-option rows and expanded source lists from routine message layout. Put Copy, reuse-prompt, and sent-context in an accessible message context menu, reachable by pointer and keyboard with correct focus return. Preserve source review's retained draft and pending operation, selection-triggered Save reference, and deliberate Cite. Keep Stop and genuine running/failed/unknown/protection notices and relevant recovery actions visible only when applicable; simplicity must not conceal unfinished work.
10. Remove replaced message styles and duplicated source disclosures in this stage. Keep styles in `Conversations.module.css` or with a genuinely shared message component. Update the current chat presentation documentation and mark older off-by-default/search-preview descriptions as historical.
