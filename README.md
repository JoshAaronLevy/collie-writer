# Collie Writer

Collie Writer is an offline-first, permanently ad-free desktop workspace for research and writing, built with Electron, React and TypeScript. Projects are portable `.collie` files; working data and recovery stay on the user's device. A new project starts without a file destination. **Save** chooses or updates the selected file, while normal close protects local work without silently saving that file. See the [current Save and recovery record](docs/validation/save-and-local-recovery.md) and [user guide](docs/manual-testing/save-and-local-recovery.md).

The current workspace has a retained editor and focused Write, Research, Notes, History, Search and Export views. Research keeps original sources, excerpts, citations and evidence relationships. Export uses options → Export → result, with guarded DOCX, PDF, Markdown and text output. Local drafts, recovery, version choices and exact pending operations remain behind these direct actions. The [refactor report](refactor-report.md) explains the simplification and links each stage's record.

Import into an existing project follows **files + categories + optional instructions + model → Submit → summary → Accept**. Supported content is extracted locally; an explicitly selected own-account ChatGPT model is used only for bounded unfamiliar structure mapping or necessary interpretation. Only **Accept** adds findings to Chats, Research or Notes. Originals and unfinished findings remain project-owned; Save does not Accept them. RF12 separates dialog presentation, retained selection/recovery and stored review admission while preserving this flow. See the [integrated import contract](docs/formats/import-recovery-v1.md#ih07--integrated-routing-and-compatibility), [RF12 record](docs/validation/refactor-RF12.md) and [user guide](docs/manual-testing/refactor-RF12.md).

The current owner-only, unpackaged AI route uses app-owned ChatGPT sign-in and direct, reviewed requests under the user's own account. It has no developer API key, hosted proxy or billing fallback. Conversation responses and retained AI work have project-scoped recovery; proofreading Run is unavailable on this route, while saved reviews remain readable. [RF16](docs/validation/refactor-RF16.md) records the removal of unreachable Codex and registered authoring while preserving historical readers and protected outcomes. Provider eligibility, commercial AI approval and packaged access remain unresolved.

## Working in this repository

Read [AGENTS.md](AGENTS.md) for the standing implementation, simplicity, styling and user-owned testing rules. For current data and compatibility work, start with the [refactor report](refactor-report.md), [hybrid Import plan](import-hybrid-implementation-plan.md), [current Import contract](docs/formats/import-recovery-v1.md) and dated records in [docs/validation](docs/validation). The matching user-owned guides live in [docs/manual-testing](docs/manual-testing). Historical records explain older formats and stages; they do not override the current routes above.

The user may launch the development app with `npm run dev` for manual review. The assistant does not launch the app, run tests or perform runtime verification. After code changes, the assistant runs `npm run format`, `npm run lint` and `npm run typecheck` in that order; documentation-only work does not require these checks. See the full policy in [AGENTS.md](AGENTS.md#user-owned-manual-testing--standing-instruction).
