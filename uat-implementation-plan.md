# Initial UAT implementation plan

October 6, 2026. Based on [uat-notes.md](uat-notes.md), all eight supplied screenshots, and source review of the affected renderer, main, preload, worker, persistence, and export paths.

**Status: planning complete and revised to incorporate Josh's decisions. No implementation stage has started.** Implement only a subsequently requested stage, then stop for user testing. UAT01–UAT05 are separate from the MVP, I, UI, CA, CD, DP, and PS stage numbers.

## Context and intended result

The first UAT shows a writing workspace whose normal operation explains too much at once. Project switching, outline selection, file checking, local protection, AI setup, and conversation management all compete with the manuscript. The requested direction is a calmer editor with familiar controls, reliable navigation, and contextual detail only when needed.

The goal is to keep the current manuscript stable while the user writes, saves, switches applications, and returns to previous work. Routine Save should communicate progress in one control. Chapters and Sections should both be directly writable and support the user's chosen hierarchy. Outline actions should belong to their rows. AI conversations should be easy to start and find. The toolbar wand should open options for a future AI review. Subtitles should be real project metadata, including persistence and the export behavior below.

This remains five cohesive implementation stages. UAT02 now includes the necessary document-model, history and export changes for directly writable Chapters and flexible nesting; it is more substantial than the originally proposed navigation fix. The other stages stay bounded. No general router replacement, all-editor cache, UI framework migration, provider rewrite, or unrelated storage redesign is included.

### Settled product decisions

| Area | Agreed behavior |
| --- | --- |
| Chapters and Sections | Both have their own editable text and may contain multiple Chapters or Sections. Projects may contain only Chapters, only Sections, or a mixture, including Chapters inside a Section and Sections inside a Chapter. Creating or opening a Chapter opens that Chapter's own editor; no automatically created child Section is required. Parts remain optional grouping items. |
| Resume writing | Remember the active Chapter/Section, caret/selection and reading position per local project; retain pane widths, focus mode and the open companion preference. Remember the selected saved chat where valid. Reopening returns to Write, with the existing local writing recovery and draft guards. Reopening dialogs, unfinished metadata forms, provider execution, or undo stacks across restarts is outside this plan. |
| Subtitles | Optional during creation and in Project details; a subdued line beneath the title in Write; below the title on enabled DOCX/PDF/Markdown/text title pages. Library rows and DOCX/PDF title properties keep the main title only. Subtitle remains a separate portable project/compilation field. |
| Conversation grouping | Save the exact Chapter or Section where a chat starts as its stable origin. Show “This chapter” or “This section” first, then “Other conversations.” Match the item itself, without aggregating descendants. Later attachments/navigation do not reassign origin. Older chats with no recorded origin remain in Other conversations. |
| Wand in this plan | Open a dialog with selectable checkboxes for writing quality, source use, research faithfulness, citation gaps, repetition and other defined review options. This is an options UI only: no capture/submission to a provider, analysis, findings or manuscript changes. Codex submission, instructions, context assembly and result handling belong to a separate future feature plan. |

In the implementation steps, **editable item** means a Chapter or Section with its own document ID/body. Existing internal `text` remains the Section kind; do not rename every AST or domain use of “text.” The approved chat-origin and resume policies apply equally to both editable kinds.

## Shared implementation decisions

### Compact controls and icons

Use **Tabler's React icons** for the touched editor controls. Its individual SVG components allow consistent size/stroke without remote assets; the official [React integration](https://docs.tabler.io/icons/libraries/react) supports importing only the needed icons. This is a design recommendation for the calm existing UI, not a claim that Phosphor would be unsuitable.

Add one exact compatible `@tabler/icons-react` dependency and its license attribution during UAT03. Do not install both candidate libraries. Replace Lucide only in components actually touched by these stages; leave unrelated surfaces alone and retain its dependency while still used. Do not introduce a generalized icon registry or new design system.

| Location | Intended control |
| --- | --- |
| Formatting | Compact bold B, italic I, underlined U and strike S glyphs; familiar Undo/Redo arrows. Keep active formatting visible. |
| Save | A joined disk-icon primary button and separate chevron menu button, with one visual boundary and unchanged Save As/Backup/Locate/file-details actions. |
| Outline | Plus for Add item; ellipsis at each row's right edge; chevrons for branches. Keep item titles readable. |
| Writing toolbar | Wand as the last command, opening UAT05's functioning review-options dialog. Its future Submit action remains visibly unavailable in this plan. Ship the button with its dialog in UAT05. |
| Other writing controls | Search, focus-mode expand/restore, and close-panel X are suitable icon controls. Keep Research, Export, Notes, Sources, AI, Details and ambiguous menu choices as short text or icon-plus-text where that improves recognition. |

Use a small shared icon-button/tooltip wrapper only where it reduces actual duplication. Give every control a programmatic name, visible focus indication, appropriate pressed/expanded/busy state, and an adequate hit area. Keep text labels inside menus. Hover tooltips should appear after roughly 1.5 seconds, and keyboard focus must also reveal the description. Do not rely on browser `title`, color, or hover as the only access path. Show row ellipses on hover, keyboard focus, while open, and on devices without hover; reserve their space so titles do not jump. Disabled controls still need an understandable reason where applicable. Respect reduced motion, high contrast, zoom, static CSP, and existing Mantine theme/scoped semantic CSS.

### Preserve ownership and product contracts

- `WorkspaceSessionProvider` and `useWorkspaceController` retain editor/protection/navigation ownership. `RetainedRegion` and the feature providers retain drafts while hidden. Do not remount editor owners to refresh status or to open a menu/dialog.
- Preserve explicit Save, native first-Save selection, retained previous copies, changed-during-Save refusal, and exact outcome reconciliation. Local protection remains separate from the selected `.collie` file. No destination autosave or Save-on-close returns.
- View hints never grant file access, editing rights, or provider execution. Guard replacements and close with the existing draft/access/IME owners.
- Add portable fields through the existing retained-copy migration and exact-reader paths. Keep old SQL definitions and historical request/digest readers intact. A new field must not silently change the bytes or digest of an already-submitted operation.
- Subtitle and chat origin are project data; caret, scroll, pane state and selected-chat hints are device-local presentation. Neither view state nor unsent text is silently added to `.collie` archives.
- Keep actual errors, consent, uncertain outcomes and recovery actions discoverable. Removing routine explanations is not permission to weaken operation safety or hide actionable failures.
- No new account/API-key flow, billing fallback, autonomous inference, provider activation, cleanup authority, or release-readiness claim is included.

## UAT01 — Keep focus and Save visually stable

**Model: Sol 6.1. Effort: High.** The changes are small visually but affect multiple asynchronous file states. Scope includes the two flicker reports, routine Save feedback, and removing Back to writing from the editor.

### Implementation

1. Separate routine file activity from actionable attention in `WorkspaceStatus`. `checking` and an ordinary running Save must not expand `Project file needs attention`. Retain the worker's focus-triggered check and all resulting error/conflict/unavailable/interrupted/consent paths.
2. Derive a scope-matched Save presentation state from the existing explicit request and file-job lifecycle. Cover local flush, first-Save picker, dispatch, worker progress, acknowledgment, cancellation, and failure. Broad `busy`/`acting` flags alone cannot identify Saving because other operations use them. Do not create a second authoritative job owner.
3. Show a stable-size disabled Save control with spinner/busy label during its actual pending interval. Restore it after authoritative completion or confirmed cancellation. Keep an unconfirmed request attached to its existing retry/reconcile action; a caller error or timeout must not produce a success indication or silently dispatch a fresh Save.
4. Avoid success banners, transient attention sections, route changes, and editor-key changes for ordinary Save. A compact persistent unsaved/saved indication can remain in the header disclosure. When typing continues after the captured head, keep the newer-unsaved state truthful after the older capture is saved. Native File → Save and the button must share this behavior.
5. Keep bounded progress/Cancel for long file jobs available through the Save control/menu or details disclosure, including from other destinations. Errors and required choices may open attention UI; exports and unresolved AI work retain their existing actions.
6. Remove the Back control from `WritingWorkspace`. Keep useful Research/inspector/Settings return paths and the app header's Return to work. Ensure those return to the current writing location rather than turning Section history into a visible editor navigation link.
7. Follow any remaining source-supported route/focus changes through `RetainedRegion`, native picker return, and account startup prompting. The demonstrated file-panel shift is the first correction; do not claim it proves the full flicker report resolved or add delays to mask a different problem. User observations after this stage determine any residual defect.

**Primary files:** `WorkspaceStatus.tsx`, `SaveMenu.tsx` and its CSS, `WritingWorkspace.tsx`, `useWorkspaceController.ts`, `project-file-presentation.ts`. Inspect `FilePanel.tsx`, `RetainedRegion.tsx`, `main/index.ts` and `project-files-ipc.ts`; change their behavior only where the identified problem requires it.

**Persistent format impact:** none. Preserve the Save/local-recovery contract and the worker's operation owners.

### User acceptance after implementation

1. Launch the updated source with `npm run dev` and open a disposable saved project. Switch to another app and back several times. Expected: the same manuscript and reading position remain visible; routine checking does not expand a page-sized panel.
2. Edit and click Save, then repeat using the native Save command. Expected: only the Save control shows routine progress, then becomes available again; there is no editor navigation, success banner, or layout jump.
3. In a disposable project without a destination, click Save and cancel the native picker. Expected: writing stays present, the project remains unassigned, and Save becomes usable again.
4. Navigate between Sections and then visit Research/Settings. Expected: Write has no Back to writing link; contextual return navigation still reaches the intended work.
5. If a real Save error or retained unresolved action occurs during normal use, review it. Expected: the error and the correct recovery/retry action remain visible. Do not manufacture failures or interrupt filesystem writes to exercise this step.

## UAT02 — Make Chapters and Sections writable and remember the user's place

**Model: Astra 6. Effort: High.** Both Chapters and Sections have their own rich-text body and may contain either kind. This joins the Chapter bug, flexible hierarchy, cursor placement and reopening because they share document identity and editor ownership. History, citations, search and exports must understand the same model before this stage is complete.

### Implementation

1. Define one shared editable-item/hierarchy policy: Chapter and Section each own a body, both can be root items, and either may contain multiple Chapters or Sections. Support Chapter-only and Section-only projects. Keep Parts as optional grouping items under their existing placement rules. Replace the fixed three-level assumption with a documented maximum of eight outline levels, counting a root item as level one. Reject cycles, self/descendant moves, excessive resulting subtree depth and cross-project parents before mutation, with a clear reason. Apply the same rules to readers, commands and UI eligibility.
2. Add Chapter creates one writable Chapter with an empty body and selects it immediately after the transaction succeeds; Add Section does the equivalent for a Section. Selecting either opens its own body, even when it has children. Existing empty Chapters therefore open an empty editor, not a descendant or previously viewed document. Keep branch expand/collapse separate from opening the body. Part selection remains grouping navigation. Protect the outgoing draft first; failed/blocked navigation keeps the previous writing and reports the reason. Row menu/focus targets remain independent of the active document.
3. Extend existing create/read/commit/move/status/history commands to both editable kinds, preserving IDs, expected head/revision checks, checkpoints, capacity bounds and atomic exact retries. The minimum-content rule requires an active editable item, not an active Section specifically. Moving a branch preserves its body and descendants. Splitting affects only the open item's own body, creates a sibling of the same kind and leaves children attached to the original item. Keep merge bounded to eligible leaf items; refuse a merge involving child-bearing items rather than discarding or silently reparenting children. Preserve anchors, replacement links and archive/trash/restore consistency throughout.
4. Make new book templates create a real writable Chapter for “Chapter 1.” Preserve existing outlines, item kinds, IDs and text; a Section named “Chapter 1” remains a Section. Do not move child text into an existing Chapter or manufacture an initial child. Freeze the original behavior and digest of already-submitted setup/outline requests, versioning new command/template inputs where semantics change. Retained creation receipts and their opening behavior must remain recoverable.
5. Introduce the new portable hierarchy/body contract through retained-copy migration, tentatively SQL/minimum reader 14. Reusing existing document columns does not make the change compatible with old readers, which reject Chapter content and deeper/reversed nesting. Preserve original manuscript snapshot/history validators and stored request/capture digests; version newly written snapshots and convert old history only at an explicit compatible restore boundary. Update portable inspection, manifest/snapshot admission, independent-copy/rekeying and Save/Backup/Restore/retention comparisons so all own bodies and hierarchy survive. Keep editor AST and archive container 1.
6. Replace text-only outline eligibility in manuscript commits/history, block anchors, managed-media references, citation occurrences, research/source/note associations, search and current-item AI context capture. Use a domain predicate; AST text nodes and plain-text formats are unrelated. Each association/capture targets the exact item's own body; a parent is not implicit permission to collect descendant bodies. Preserve old captured contexts and their validation/digests, with compatible versioning for new captures if required. Rebuild an obsolete search index through the existing cache owner on explicit Search use so Chapter content becomes discoverable. This adds no provider route, review execution or cleanup authority.
7. Update compilation selection and preparation to include both editable kinds. Default manuscript export follows outline order, emitting a parent's own body before its children and each included body's text once. Preserve explicit item selections, custom recipe ordering, ancestor-heading options, citations and source maps; checking an individual parent selects its own body unless a separately labeled existing control selects its subtree. Avoid duplicate ancestor headings when a parent is also an included writing item. For nesting beyond the existing three heading styles, map deeper headings to level three and show that flattening in export preflight without dropping content. Version the changed frozen compilation contract, tentatively compilation 4, preserving older recipes/captures and their original meaning.
8. Add a small, bounded view-position owner keyed by project ID, workspace ID and editable-item ID. Capture caret/selection and a scroll anchor before accepted item/project changes and during ordinary position changes; flush the latest hint on normal close. Use a short debounce for storage writes. Store no manuscript text, editor objects, paths, grants or undo history. Document entry/byte bounds and evict only old presentation hints, never content. Reuse the existing profile-preference mechanism.
9. Restore selection against the exact saved document revision where possible. A block ID plus text offset can provide a conservative fallback when a block still exists; invalid/missing hints fall back to the end of that item's body. Preserve selection direction where supported, keep offsets valid for rich text, and handle nested tables/footnotes safely. Do not reuse or weaken the exact-target dialog bookmark helper. Explicit search/citation/history anchors take precedence over generic remembered positions.
10. Restore the actual scrolling container after layout/editor initialization, without stealing focus from a dialog, composition, another destination or a newer user click. On unchanged content, resume the same place; on changed/missing content, prefer a safe nearby/end position. Ordinary same-document status/metadata changes must not remount the editor and lose selection/undo. Reuse existing pane-width, focus-mode and open-companion preferences. Reopening returns to Write; it does not reopen dialogs, unfinished metadata forms or provider execution. UAT05 adds the selected saved-chat hint. Returning to an item does not promise restoration of its previous editor's undo stack.
11. Fix startup Open to pass only `{ projectId, workspaceId }`. Consolidate selection across startup, Projects, native archive opening and normal return-to-work: acquire a trusted scope first, resolve its stored editable-item hint against current documents, then select. New independent copies use their own workspace identity; they do not inherit another project's cursor by title or file path. Missing/inactive items fall back to a valid active editable item without changing content.
12. Preserve resumable setup precedence and the existing acquisition fix. A creation receipt identifies initial setup work, not an instruction to reset every future reopen to Introduction. Read the existing last-project v1 hint compatibly; store per-project positions separately or use a documented versioned replacement. Missing/retired/archived scopes still follow existing library/recovery rules, and unreadable preferences cannot prevent project access. Existing explicit draft/recovery guards remain in force.

**Primary files:** renderer `OutlinePanel.tsx`, `HistoryPanel.tsx`, `WritingWorkspace.tsx`, `useWorkspaceController.ts`, `last-project.ts`, `useWritingPreferences.ts`, `RichDraft.tsx`, `editor/anchors.ts`, `RetainedRegion.tsx`, research/source/notes/search panels and `DocxExportPanel.tsx`; `shared/outline.ts`, `shared/citations.ts`, domain `projects/templates.ts` and `compilation/model.ts`; worker `projects/outline.ts`, `manuscript.ts`, `repository.ts`, `citations.ts`, `citation-occurrences.ts`, `evidence.ts`, `search.ts`, `conversations.ts`, `proofreading.ts`, `interchange.ts`, `portable-db.ts`, schema/migrations, snapshot/manifest/incoming and `exports/prepare.ts` plus affected format writers. Follow actual consumers of the changed contracts; do not globally replace every `text` check.

**Persistent format impact:** portable SQL/minimum-reader increment for writable Chapters and hierarchy semantics; versioned manuscript/history and changed request/capture readers as needed; compilation increment; bounded device-local view hints. Preserve old definitions and digests. Document hierarchy/body ownership, history compatibility, export ordering and the view-hint format together. This is the largest stage because partial consumer support could lose or hide writing.

## UAT03 — Simplify the writing chrome and outline actions
