# UAT Notes

This document contains notes and observations from the User Acceptance Testing (UAT) of the application, highlighting general thoughts, specific issues, and feedback for improving the user experience. I included corresponding screenshots in the `tests/uat/screenshots` directory.

For this task, I want you to thoroughly review everything below, including the general thoughts, specific issues, and feedback, and thoroughly review the existing codebase. Then, create a file in the root with a detailed implementation plan for addressing the issues and feedback noted in this document. The plan should have detailed context at the top, and be broken into manageable, yet detailed stages for implementing the code changes. Each stage should include the model and effort level recommended for that stage (Codex-specific model and effort), with the model choices of either Sol 6.1 and Astra 6, and the effort level choices between Medium, High, Extra High, and Ultra. NOTE: Do NOT use the maximum or highest model just because. I have often found that using an unnecessarily overpowered model or effort can often cause Codex to over-engineer the feature or bug fix, which can cause pretty big issues and headaches of their own. So please recommend the model and effort that is appropriate for the complexity of each task. Also, for the item list of specific issues below, you don't need to do 1 stage per item. If an item requires multiple stages, you can set it up as such. But don't do so for the sake of it. I feel like thus far there have been a few times where we took a relatively simple feature or bug fix and ended up generating an 8 stage plan for something that could have been done with a simpler implementation and just 1 or 2 stages. Also, it's possible more than one thing mentioned below can be done in a single stage. The point is, the code changes need to accomplish what is needed. The updates still need to work. But don't go way overboard. Finally, if you have any clarifying questions about what is being asked in the list below, or anything about the expected UX is unclear, please create a section at the top of the file with the clarifying questions. I will then answer them and have you review the answers and revise the plan according to those answers.

## General Thoughts

The UX is degraded by a very "busy" UI. Efforts to make different things clear actually cause more confusion and cognitive load for the user. The UX could benefit hugely by a handful of relatively minor changes, along with introduction and use of icons and icon buttons over text-heavy buttons and labels.

## Specific Issues/Feedback

### Bugs

- When I added a chapter, it added it in the menu on the left. But when I click on it, it shows the editor from the previously viewed chapter instead of the newly added chapter. This does NOT happen when adding a new Section. That works fine. But it does happen when adding a new Chapter. I tried taking a screenshot to demonstrate this as best as possible. It's located in `tests/uat/screenshots/New_Chapter_Bug.png`.

- When I switched between sections on the left, by default, the cursor is placed at the very beginning of the section. Ideally, the cursor should retain its previous position within the section, so the user can continue editing seamlessly from where they left off. But if that introduces unnecessary complexity or potential issues, at the very least, the cursor should be placed at the end of the section to allow for quick continuation of writing.

- When I change to a different app or window, then return to the application, when the application regains focus, it flickers to some page then back to where I was. It's so fast that I unfortunately can't capture exactly what is happening or provide any additional helpful details on what it says or anything like that. However, it is still noticeable and would definitely irritate a user very quickly, as this is something that doesn't happen in well-designed applications today.

- When a user clicks the Save button, the app flickers/jumps very quickly to what looks like a different page then back to the editor, then very quickly flickers/shows a section above the editor that I'm assuming is a save status section or something like that (it appeared then went away so quickly that I couldn't tell what it was saying or anything else that would be helpful in describing it). This is a bad UX in general, and contains a lot that is simply not necessary. The save action in the UI should be a much simpler UX. Something like when clicking Save, the project state goes into "saving" mode, the "Save" button is disabled with a spinner or some other visual indicator, and once the save is complete, the button state is restored. If that happened, that's enough for a user to understand that their changes have been saved without unnecessary visual noise. The only instance where an alert section should appear is if there was an issue or error during the save process.

- When I change chapters or sections, in the project title bar (or whatever it's called), a link shows that says "Back to writing", which is weird because I am writing where I want to be. No matter where I am, if I click on it, it takes me back to the Introduction section. This link is unnecessary and confusing and just adds clutter to this editor view. Please remove this link from the editor page. If it appears in other pages like settings, and actually is useful there contextually, you can keep it. Otherwise, it should be removed entirely. You can see an example here `tests/uat/screenshots/Project_Title_Bar-Back_to_Writing.png`.

### Improvements

- The application needs to support subtitles for projects. Many nonfiction books and academic studies include subtitles that provide important context and information. The app currently only allows for a title, author, and description.

- When opening previous project, it should open exactly where the user left off, including the editor state, cursor position, and any other relevant context, rather than resetting to a default view or losing the user's place. When tested, I closed the app while viewing "Chapter 1". But when I reopened the project, it opened at the "Introduction" section.

- In the Chapter/Section Title and editor toolbar sections (not sure what we're officially calling them) that you can see in the screenshot in `tests/uat/screenshots/Chapter_Title_and_Editor_Toolbar.png`, this is one place that can be simplified.
  - The toolbar doesn't need buttons saying "Bold", "Italic", "Underline", etc. Instead, it should use a more compact design with things like a bold "B" for bold, an italic "I" for italic, and a "U" with an underline for underline, etc. This would make the toolbar cleaner and more visually appealing while still providing the necessary functionality. And Undo and Redo should be icon buttons. NOTE: For icon buttons I reviewed your recommendations you gave me in a prior conversation and I liked Tabler and Phosphor. I will defer to you regarding which of those you use. Just please review all updates in this file to get an idea of all the various icons needed in the UI to decide which library to use.
  - Also, below the chapter/section title, where it says draft, that should be removed entirely. We might add something there instead like an indicator of when it was last saved (if there have been changes since it was saves last). But for now, just remove it.
  - On the right, where it says "Section details", change it to just say "Details" with the same functionality when clicked.

- The editor toolbar should have a button at the end of the toolbar of like a wand or something that will serve as the AI proofreading feature, allowing users to quickly check their text for grammar, style, and other improvements. This feature isn't fully implemented as needed yet. However, I want this button specifically to be the one to trigger the AI proofreading functionality when clicked.

- The left sidebar while in the editor view is too busy and could be organized better. The current UI is captured in the screenshot in `tests/uat/screenshots/Project_and_Chapter_List_Sidebar.png`.
  - In this sidebar, near the bottom where it says "Introduction - active" is unnecessary. I can see which chapter is active based on the styling of the selected item in the sidebar. That should be removed entirely.
  - The drop-down form field at the bottom with the label "Selected item" should be removed entirely as well. The options in that drop-down are valuable. But we can just add an icon of three dots (vertical or horizontal) in each list item aligned right that shows when hovered over the list item. When clicking the 3 dot icon, it will show the drop-down list options for that list item.
  - The section at the top to switch project or browse projects should also be removed entirely. The app has a link in the very top navbar of the app to view projects, which is good enough for navigation purposes. Also, it's unlikely that most users will be switching between projects often enough for it to make sense to have this section in the sidebar. Lets simplify the sidebar by removing this section entirely.

- The right sidebar needs to be completely rewritten for the AI tab. The current screenshot is in `tests/uat/screenshots/AI_Sidebar.png`.
  - The "Return to manuscript" button/link, along with the entire AI assistance section at the top should be removed. It's no longer necessary, since the AI wand button we're adding to the editor toolbar will be handling the proofreading features.
  - The remaining content of the AI tab in that sidebar needs to be replaced with a simpler conversation interface. It should show a list of conversations, but have them grouped. A user should see the conversations pertaining to (or started in) the current chapter or section first, followed by all conversations from other chapters or sections. At the top, above the list of conversations, it should have a button to start a new chat.

- At the top of the editor view, where it has the project title and the toolbar to the right with "Save", "Save options", etc. the "Save" and "Save Options" should be joined in one split-button, with an icon (like a floppy disk) representing the save action. Clicking the floppy disk performs a standard save. While clicking the drop-down portion of the split-button should reveal additional save options.

- Anywhere else in that editor page/view that would benefit from replacing text labels with icons or more compact representations should be updated similarly to improve the overall visual appeal and usability.
  - NOTE: It would be helpful to be able to have a tooltip/popover functionality implemented. So a user can hover over an icon for a couple seconds to see a brief description of its function, if they need.
