## Confirmed refusals and protection

New mapping and semantic operations use execution/binding **12** and import handoff **7** (`ai-handoff-v7`). This operation version wraps either existing mapping framing **8** or semantic framing **9** with a new operation digest; it does not alter their prompt bytes, packet/output validators or capture/run versions **3/4**. Earlier operation/binding/handoff readers stay frozen. Version 12 alone has the required `importRefusal` slot in its protected operation view; older journal versions reject that slot.

`ImportRefusal` v1 retains only kind, bounded machine code, HTTP status and an optional minimum retry timestamp. The exact structured code `subscription_sharing_usage_limit_exceeded` means a confirmed plan/app usage refusal, including terminal streamed failure with HTTP 200. HTTP 429 without that code is a temporary request refusal, not proof of a five-hour/weekly/account-wide limit. Structured `rate_limit_exceeded` and `slow_down` also identify temporary request limits. Authentication, capability, invalid-output, incomplete, timeout, transport-unknown and local protection outcomes do not acquire retry eligibility. No provider prose, credentials, full headers or account percentages are retained by this contract.

A valid `Retry-After` on an HTTP refusal becomes its minimum retry time. It is neither shortened to a local retry interval nor labeled a quota reset; a missing/invalid value produces no invented deadline. Confirmed quota refusals have no inferred reset timestamp. See OpenAI's [errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery), [stream failure contract](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) and [temporary rate-limit guidance](https://developers.openai.com/api/docs/guides/rate-limits).

The protected own-account owner carries this typed cause through its HTTP wrapper and encrypted journal. Worker settlement atomically saves a digest-bound portable refusal beside the exact terminal run. Admission compares the refusal to its capture digest, failed state, reason and sequence; the handoff compares it to the protected operation. A known typed refusal may finish its acknowledged local handoff automatically after protection, without accepting any content or authorizing a retry. Uncertain/unprotected outcomes continue through the existing explicit recovery owner. No raw output inspection is required.

## Explicit continuation and bounds

Task readers distinguish unread, successful, invalid, pending, interrupted, quota-paused, rate-limited and retry-exhausted. Only unread tasks and newly typed confirmed refusals enter a fresh explicit Submit/Continue grant. Each task allows **three lifetime attempts**, including its initial attempt. A new attempt/capture identity is allocated on each retry. A valid result remains selected; it cannot be resent as a refused task. An old generic `quota-exhausted` string has no typed refusal proof and is never retroactively retryable.

Main owns one serial mapping/semantic coordinator. Each grant admits at most **8 mapping tasks** or **32 semantic tasks**, counts retries within that ceiling, reserves before dispatch and pauses on the first failed result. Worker capture preparation rechecks the exact prior attempts, typed refusal, minimum retry time and settled local binding. Pending handoffs, unknown outcomes, local protection and changed scope/account/model/catalog/review stamps prevent fresh dispatch. No automatic retry, new grant, fallback model or quota probe exists.

The existing **1,024 lifetime attempts per selection**, **256 MiB derived storage**, wire/output limits, five-minute request deadline and 90-second network-idle guard remain. Retry refusal does not erase these bounds or successful work. Copies retain evidence but carry no dispatch grant or another working copy's binding. Fresh Continue uses the user's current explicit account/model choice.

## Partial summary and reopening

Explicit **View available results** creates a local summary from protected valid tasks and independent local findings. It sends no inference request. Derived summary graphs remain linked to their immutable source graph; source evidence can still be used for explicit continuation while the active graph is a proven descendant with exactly matching files/settings and no accepted receipt.

Session mutations **6/7** explicitly select that retained source for semantic/mapped preparation. The new revision's parent is the current revision; graph provenance still identifies its original source revision. Portable admission checks this special parent/source relationship only for these newly versioned commands. Frozen graph, revision, review and manifest encodings stay unchanged.

The read-only `hybrid-progress` selector walks bounded graph ancestry to restore the original task plan after a partial preview, Save/reopen or independent copy. It neither prepares a request nor restores a grant. Cancel returns to setup; Continue can reuse completed work. The summary states that **Accept finalizes the selection**. A user wanting to finish later should Cancel and keep it paused. After partial acceptance, omitted material needs a new deduplicated import; completed selections cannot resume.

## Older unfinished selections

Explicit **Use new importer** issues mutation **5**, `transition-hybrid`, only after old pending results/bindings have settled and before acceptance. It appends a new intake/evidence revision with the same retained file selection and settings, clears the active graph and runs the normal local/mapping/semantic preparation on Submit. No picker repetition, original deletion, legacy result rewrite or receipt overwrite occurs.

Earlier manual choices, summaries and manifests stay immutable historical evidence. The UI states that the new importer reads the retained files again and creates a fresh summary; it does not silently translate old edited choices into new automatic choices. Existing ready summaries remain usable before a transition; exact pending commit/output recovery stays with its original owner.

Ordinary legacy recognition dispatch/review offers, batch grants and renderer continuation authoring have been removed. Historical packet/partition/output decoders, saved-plan/proposal/review readers, summary preparation and exact operation/handoff/commit reconciliation remain for concrete older projects. IH07 owns the final compatibility and unused-code pass.

## IH07 — Integrated routing and compatibility

October 11, 2026. Current implementation and [integrated acceptance](../validation/import-IH07.md) preserve SQL/minimum reader 37 and all IH06 durable versions. This section describes routing/presentation and the surviving compatibility obligations; it introduces no new persisted format.

Submit retains originals and builds the graph locally. With blank instructions, known records use deterministic extraction; unfamiliar JSON uses bounded mapping and full-file local application. Necessary prose interpretation follows either route. Nonblank instructions require complete admitted semantic context; an unsupported condition does not fall back to unfiltered findings. Every route feeds local/mapped/interpreted review 3/4/5, the same automatic choices and exact manifest, then atomic Accept. Disconnected imports may finish locally when no interpretation is necessary; otherwise preparation pauses with a contextual account action. Merely managing the account, opening/copying a project or reading findings never sends.

A phase bar measures processed structure/content tasks. Valid, invalid, interrupted and exhausted tasks are settled; pending/unread and quota/request-refused tasks remain unfinished. A settled task may have unusable output. The denominator is the full phase task plan, not messages or the current finite grant. Mapping and interpretation have separate denominators, so progress can reset at a phase change. The current run separately shows reserved request attempts and its limit; reservation can precede network dispatch. Streamed characters/time indicate activity only. Local reading/extraction/summary preparation has no invented percentage or stale AI bar.

Results contain exact manifest counts and titles/message totals, a short partial notice when necessary, and retained attempt count or the zero-request local note. Retained attempt totals include not-sent/preparing and failed attempts and any earlier attempts in that selection. They cannot determine billable provider requests, tokens, remaining allowance or percentage savings. Healthy results Cancel returns to the populated form without routine recovery controls. The same unchanged Submit reopens saved findings. Paused/partial/uncertain work exposes only the applicable recovery actions.
