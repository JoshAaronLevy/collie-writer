# CD01 local compatibility contract

October 2, 2026. Device-local contracts only. Portable SQL/minimum reader **12**, AST/archive **1** and compilation **3** are unchanged. No migration runs in CD01.

This is the historical CD01 boundary. CD04 subsequently delivered the separate [operation v2 contract](codex-operations-v2.md), preserving the v1 identities below. CD02's [account metadata v2](codex-local-v2.md) has a separate version lifecycle.

| Record / boundary                        | Current contract                                                                                                                                                                                  | Local-route treatment                                                                                                                                                                                                                                                                              |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ai/credentials-v1.json`                 | Exact registered OAuth v1 payload, inside existing version-1 encrypted envelope. Host ID, active ID and registered accounts retain their existing semantics.                                      | Preserve it. Never populate fake registered client IDs or convert Codex-managed credentials into `Tokens`. Existing accounts are not selected/advertised as local Codex accounts.                                                                                                                  |
| `ai/operations/<UUID>.json`              | Exact `{version:1,input,view}` within existing encrypted envelope; 64-operation cap; retained interrupted candidates.                                                                             | Read/reconcile/protect using original v1 identities without login. Current reader continues refusing unknown versions; no implicit defaults, rewrite, rebind or cleanup.                                                                                                                           |
| Registered operation digest              | `operationDigestV1` retains the original canonical JSON order and SHA-256 UTF-8 hashing. Scope keys, operation ID, connection ID, model, action, prompt and ordered context fields are unchanged. | Refactored to a named frozen function used by startup and prepare. No route, policy, session epoch, model default or framing field may be appended to v1.                                                                                                                                          |
| `ai/codex-local-session-v1.json`         | New **declaration only** in `local-session-metadata.ts`: exact version/route/policyRevision/profileId and nullable account `{connectionId,label}`.                                                | CD02 owns encrypted persistence using the existing protected storage owner and original/candidate retention. Contains no token, provider subject/workspace, path, client ID or runtime handle. A saved label is a resume hint, never permission. No reader/writer or file is activated in CD01.    |
| Stable Codex home                        | Not created by CD01. Future profile derives from trusted working root and the bounded profile UUID, never a serialized arbitrary path.                                                            | CD02 must canonicalize/contain it and select the supported isolated keyring backend. Credentials remain Codex-owned, outside portable data. Moving the home changes the keyring namespace; require explicit reconciliation/sign-in, never copy the global profile.                                 |
| Route-bound operation v2                 | **Reserved for CD04, not a readable/writable format today.** Separate discriminant and canonical digest domain, retaining v1 records and original bytes.                                          | Must capture route/policy, profile, authenticated account/workspace identity, fresh session generation, runtime pin, model/action, output-contract revision and exact reviewed request/framing. Define exact v2 keys/order and all readers before dispatch. Never hash v1 input using v2 defaults. |
| Transient route/session/funding/features | Exact shared status validator; same named response validator in main and preload; events use the exact status schema.                                                                             | Window-memory only. No route-selected-by-renderer input, new generic IPC, credential URL or executable/config path. Current feature contract has no ready branch.                                                                                                                                  |
| Connection-only reasons                  | `AiConnectionReason` in `shared/ai-route.ts`.                                                                                                                                                     | Never pass through `AiReason` or persist into conversation/proofreading outcomes. Durable local refusals continue mapping to accurate existing `development-access-unavailable`, `isolation-unresolved`, `runtime-unavailable`, etc.                                                               |

On a future metadata change, retain original encrypted files and interrupted candidates, distinguish unsupported versions from signed out, and fail without provider work. Do not overwrite a record just because its policy revision is old. A live session generation must be newly established after explicit resume/account adoption and invalidate unsubmitted prepared grants; a cached account cannot inherit execution authority.

CD04 must keep commit intent → prepare → persist local binding → dispatch → protect real output → settle. Exact replay returns existing results before considering new session eligibility; local protection retry cannot send inference. Independent project copies retain portable history only. No operation capacity is released here; CD08/C07 still owns shared durable receipts and both main/worker retention limits.

All compatibility, native credential, migration and recovery behavior awaits user observation. Source inspection is not passed testing.
