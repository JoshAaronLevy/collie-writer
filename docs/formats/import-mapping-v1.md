# Constrained import mapping v1 — IH03

October 11, 2026. SQL/minimum reader **34**. This is an internal prerequisite for IH04. No new provider purpose, mapping editor, ordinary Submit route or accepted-content format is enabled by IH03.

## Structure profiles

The strict existing UTF-8/JSON parser admits the selected managed original, retaining lexical numeric values and refusing duplicate object keys. Profiling visits every admitted value. Typed field paths record type/count distributions; array paths record total items and minimum/maximum lengths; immediate field/type signatures group structural variants. Each variant retains bounded first/last examples with exact original JSON pointers and an explicit `omitted` flag. Nested arrays are represented by counts and small examples, never copied into a profile as complete collections. Shape equality makes no claim about field meaning.

A profile is bound to its original file ID/hash and the immutable source graph. Its canonical digest covers every retained count, path, signature and sample. Reprofiling the complete managed original must reproduce that digest and profile identity. Profiles may be prepared for an explicit subset of selected files, permitting IH04 to keep already recognized files on the existing local path.

The finite limits are 16 path steps, 2,048 distinct field paths, 256 array paths, 256 variant/path groups, 512 UTF-16 units per example and 120,000 units per profile. The existing limits of 25 MiB per file, 100 MiB per selection, strict JSON depth/value/string admission, and managed import capacity still apply. An over-budget profile fails with a limit reason; it does not certify a sampled prefix as a complete file.

## Declarative operations

`ImportMapping` contains version 1, ordered profile IDs and up to 32 ordered rules. Its serialized program is bounded to 32,000 UTF-16 units. Every object has an exact property set; unknown operators/properties are rejected.

Paths consist only of `{ field: string }`, `{ index: nonnegativeInteger }` and, for collection/body traversal, `{ each: true }`. Empty scalar paths refer to the current item. Access is restricted to own properties of the expected object/array type. Unsafe keys (`__proto__`, `prototype`, `constructor`), control characters and overlong keys are refused. There are no expressions, generated code, regex operators, arbitrary JSONPath, object wildcard traversal, recursion operators, plugins, modules, shell commands or external fetches.

Rules declare conversation, message, source or note records. `from.profiles` selects the admitted originals to which that rule applies; nested rules cannot expand their containing rule's file scope. This lets separate selected files use different roots without treating another file's absent root as a failed mapping. `from.parent` names an earlier rule for nested current-item traversal; `from.path` selects the applicable collection. Optional variant hashes must occur in the rule's bound profiles. Each traversed object is checked again; profiles and samples cannot prove that later records match.

- Optional original identity, title and time fields retain their exact locators. Original IDs remain literal and receive a stable file-hash/record-kind namespace; absent identities receive deterministic identities from that namespace and the original pointer. Changing mapping titles or aliases does not manufacture a fresh original identity. Present but malformed or duplicated identities remain unresolved. Destination fallback labels do not become original titles or bibliographic facts.
- Messages declare original body-part traversal, role/channel fields, finite role aliases, conversation grouping and ordering. Array order is valid only within one proven original array; numeric order requires unique nonnegative integer values. Selected-parent ordering requires an original current-node field and a complete, unique, acyclic parent chain. Alternate branches remain retained and excluded; broken alternate chains receive unresolved notices. Multiple rules/arrays without a proven combined order remain unresolved.
- Parent links use either the exact containing rule item or a unique original scalar ID. File-scoped links stay in the same original; explicitly selection-scoped links can resolve only among admitted selected originals. Missing, ambiguous or unresolved parents never gain guessed links. Embedded paths and URLs are data and never file/network authority.
- Sources map a finite list of original CSL-style fields through the same original metadata adapter and normalization used by known imports. A decision is either fixed for a declared collection or read through an original scalar field and a finite exact alias list; an absent/unrecognized decision stays unresolved. This preserves mixed kept/rejected/search/cited records without programmable filters. Rejected/search occurrences stay excluded, reference links retain the exact originating message, incomplete facts remain incomplete, and no source is fetched or verified. An empty source without a title or supported identifier remains unresolved.
- Notes keep original body-part references and optional original label/authorship fields. No model-generated transcript or note body is accepted by this interpreter. Historical roles, original content and profile examples supply no execution authority.

Malformed/missing required collections, non-object items, uncovered variants, unsupported body parts and ambiguous order/grouping produce retained unresolved/unsupported records. Per-file descriptor or extraction limits roll back that file's derived records and report unread coverage rather than silently retaining an apparently complete prefix. Traversal exhaustion can refuse the whole operation. The full selected original remains protected.

## Normalized evidence and retention

The interpreter emits the existing `GraphRecord`, `GraphRelation`, original text/fragment references and file coverage shapes. Original mapped facts use `mapped.original.*`; the applied rule is identified separately by `mapping.rule`. Shared original-reference helpers preserve deterministic locator/text/fragment IDs, text digests, original numeric/date precision and existing graph bounds. The shared graph validator checks the complete result across pages, including identities, order, fragment continuity and member/reference/parent endpoints.

`MappingNormalization` is explicitly `kind: mapping-applied`, version 1. It binds the source graph/revision, exact settings, ordered profile/original bindings, mapping program, complete record/relation digests, file coverage, text units and protected page descriptors. Settings are retained literally; the interpreter itself does not interpret free-form instructions. IH04/IH05 own their routing and semantic treatment. Mapping evidence must never be presented as IH01's `local-reader` evidence or as an old AI recognition result.

Profiles, normalization manifests and graph-shaped result pages use separate `mapping-v1` descriptors in the **existing** `import_artifacts` table and managed blob owner. Descriptors bind batch, source graph/revision, content hash/bytes, asset ID, owner and part. Normalizations and profiles own themselves; every page has one normalization owner. There are at most 32 retained normalization bundles per batch, with existing per-artifact/derived/project capacity and database reserves. Page and manifest limits can refuse a very large derived descriptor set independently of original file size. No transcript bodies are copied into conversion files.

Internal preparation stages blobs, checks the surviving head/current selection, then installs a complete family atomically and advances the existing project head. Content-derived identities allow an exact stored normalization/profile to be read and reused without another write. Stale selection/head, cancellation, accepted/discarded selection or conflicting content refuses installation. Cancellation checks occur before reads/staging/commit, and traversal yields to the worker event loop every 1,024 steps under a finite 1,000,000-step budget. Synchronous strict JSON decoding/parsing finishes its bounded current operation before a newly delivered cancellation can be observed. IH04 must wire these internal functions to the retained main/worker operation and cancellation owners.

Portable SQL admission requires exact row/asset/batch/graph/revision bindings and rejects unknown artifact families. Blob admission regenerates every profile and reapplies every mapping against the whole retained originals, then compares every saved record, relationship, page, coverage count and digest. Orphaned/shared result pages, changed originals and mismatched results are rejected. Reopening performs local evidence admission; it grants no provider dispatch or content acceptance authority.

## Compatibility and downstream boundary

Schema 33 DDL is frozen; schema 34 reuses it unchanged and extends artifact semantics. Migration occurs on the existing retained database copy, changing the format tags after admission. Save/snapshot/archive, independent-copy outer-project rekeying, retention proofs and conservative import-bearing removal use the existing complete table/blob owners. Mapping artifact bodies contain no outer project ID to rewrite. Earlier intake, known graph, local review/manifest, provider, accepted transcript/origin/context and receipt contracts remain unchanged.

IH04 must supply its distinct protected mapping discovery/capture/evidence and automatic review/acceptance integration, including mapped original metadata/note readers and accepted transcript/origin/context consumers. IH03 installs no fake local review, proposal, acceptance receipt or native attempt. Known-format IH02 Submit remains the only new ordinary authoring route. IH05 owns semantic extraction; IH06/IH07 own remaining legacy transition and cross-layer cleanup.
