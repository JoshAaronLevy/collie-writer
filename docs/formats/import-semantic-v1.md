# Import semantic interpretation v1

IH05, October 11, 2026. SQL/minimum reader **36** preserves frozen schema-35 DDL and extends the existing managed import evidence, protected own-account operation and automatic acceptance owners. See [the hybrid plan](../../import-hybrid-implementation-plan.md), [discovery](import-discovery-v1.md) and [local evidence](import-local-evidence-v1.md). Runtime acceptance remains user-owned.

## Classification and authority

Known conversation bodies, structured bibliography fields and literal note records are copied locally. With blank instructions, selecting Conversations alone does not request AI recognition. Selecting Sources additionally examines visible message/note prose for reference-like content; plain text/Markdown is interpreted for sources, while structured source rows stay local. Existing structured source identifiers are masked during classification, but their presence does not suppress additional inline references. Notes embedded under recognizable note headings in message prose can receive literal-span extraction. This is bounded classification, not universal prose detection or a guarantee of recall.

Every nonblank instruction is treated as requiring interpretation. IH05 implements selection of existing original records and extraction of literal original spans, not rewriting, summarizing, generating notes, web enrichment or arbitrary transformations. A selection request includes all admitted visible original text and metadata relevant to its candidates, not sampled rows. It is refused before inference if that context exceeds **50,000 serialized packet characters**, has more than **128 destination candidates**, or includes unread/unsupported/unresolved input. Unknown JSON plus instructions is explicitly limited until its structure and instruction condition can both be supplied safely; IH05 does not combine sampled discovery with instruction compliance. Originals and instructions remain retained, and unfiltered candidates cannot be accepted as if the instruction succeeded.

Packets disclose unknown field names without claiming their omitted values are known. The model must mark conditions depending on missing facts or omitted/unsupported content unresolved; absence from the packet cannot prove a negative condition. Alternate/internal original material retains its earlier reader exclusion and cannot acquire execution authority.

Only explicit Submit/Continue grants inference, using the actual dropdown model and current own-account connection/catalog/review stamp. File text and metadata remain untrusted data. No additional project context, tools, URL fetch, Files upload, API key route, automatic repair or model fallback is added. Reading, reopening, Save/copy, protected handoff and acceptance confer no inference grant.

## Plan, packet and output

A compact immutable `semantic-plan-v1` artifact freezes the source graph/digest/revision, selected settings, deterministic tasks/range descriptors and any limitation. It contains no duplicate full bodies. Artifact/plan/packet v1 digest domains are distinct from frozen discovery/multipart domains. The existing managed asset writer retains it alongside the source originals/graph.

Prose tasks use original text ranges of up to **24,000 UTF-16 units**, with **512 units** of overlap where more text follows. Each range declares its record/text identity, original-relative start/end and total text size; the packet adds only its exact literal text. Context includes the original record and conversation envelope when present. A record crossing a range boundary is not assumed complete. Plans admit at most **1,024 tasks**, subject to existing storage/capture capacity. Excess or overlarge context remains a disclosed limitation; it never starts a full-file recognition fallback.

`project-import-semantic-v1` packets carry source graph/plan/task identity and digest, category settings/instructions, target IDs, original context metadata/unknown field names and exact range text. Packet maximum is 50,000 characters; final transport retains the **80,000 character / 320,000 UTF-8 byte** wire bounds. Response maximum is **32,000 characters**. Five-minute per-request and 90-second network-idle guards remain unchanged; there is no new overall import deadline or account-usage estimate.

The response is exactly `{version:1, partId, captureDigest, supported, decisions, extractions, unresolvedRanges}`. Selection mode must decide every target once as include/exclude/unresolved; prose mode has no target decisions. Extractions identify source/note spans and named field spans within the same supplied range. They return offsets, not generated bodies or metadata values. At most 200 extractions and 15 fields per extraction are admitted. Sources require an original title or URL; notes accept only a literal title field. Missing author/date/identifier facts remain missing. Unsupported instructions require `supported:false`, all target decisions unresolved, no extractions and all ranges unresolved.

Local validation checks strict keys/bounds, exact task/capture digest, target coverage, category, range ownership and UTF-16 boundaries. Each field must lie within its extraction span and be at most 1,000 units. Original text is resolved locally, not trusted from an AI-generated value. Invalid output remains protected but unusable; no repair request is issued.

Capture/run **4**, execution/binding **11**, framing **9** and handoff **6** reuse the existing encrypted operation journal, streaming, cancellation and terminal protection/retirement. Earlier versions keep frozen prompt bytes, readers and digests.

## Local composition and acceptance

Session mutation/revision **4** (`prepare-semantic`) installs a derived graph **3** / reader **3** with source graph identity, exact selected valid attempts and unresolved task count. It retains original records/relationships and copies full included bodies unchanged. Excluded records lose eligibility; unresolved conditions cannot silently become included candidates. A valid extraction creates a deterministic original-span record/text with distinct identity, original locator/hash/offsets and literal field/span facts. Repeated exact spans are deduplicated locally. Extracted source occurrences retain the original message relationship even for source-only imports; literal notes retain original locators and unspecified authorship.

Review/manifest **5** uses distinct `ai-interpretation` evidence: source/derived graphs, selected attempts, settings, page/record/relationship digests, coverage and unresolved count. Existing source normalization/matching, automatic choices, exact confirmation artifacts, atomic Accept and receipt recovery remain the only destination writer. Source metadata is resolved from protected original spans before ordinary normalization. No field becomes verified and no source attachment is fetched. Notes remain literal; conversation/message bodies are never reconstructed by ChatGPT.

The two-modal UX remains unchanged. Processing shows real completed request counts and protected streaming activity. Summary counts include usable findings only; unresolved work gets concise context, and actual retained attempt totals determine whether the zero-request message is true. Cancel returns to setup; unchanged Submit reuses saved findings; Accept writes the frozen subset and closes on confirmed success. Re-Analyze stays disabled.

## Finite work, recovery and portability

The IH04 coordinator handles both discovery and interpretation, with one request in flight. Each explicit semantic Submit/Continue permits at most **32 unread tasks**; reservation precedes dispatch and the exact protected terminal handoff precedes advancement. Finishing a grant with unread tasks pauses for explicit Continue. Completed captures remain retained across portions. IH05 prepares interpreted results after tasks are settled; early partial-finalization and confirmed quota-refused retry remain IH06. Failed, uncertain or invalid responses do not enter unread continuation and are never resent automatically.

Cancel latches before provider cancellation and prevents subsequent scheduling. Check status reconciles saved work only; local mutation/confirmation recovery takes priority over interpretation polling. Reopening reads retained plans/results or the derived summary and grants no inference. Successful discovery may be followed by semantic work under the same explicit submission; saved discovery/interpretation phases are not a second queue.

Migration 35 → 36 changes format tags on the retained candidate. SQL admission checks artifact/assets, captures/runs, source/revision/settings bindings, selected outputs and new graph/review/schema discriminators. Blob admission regenerates plans and packets from complete protected originals, revalidates raw model output, and proves each derived graph equals deterministic composition of its source and selected responses, including zero-result graphs. Existing full-table Save/archive/copy/rekey/retention and accepted transcript/origin/context readers preserve these records. Copies grant no inference or acceptance authority. Working-copy/original/history protections remain in force.

Provider extraction/selection accuracy, range-boundary coverage, native Save/reopen/copy, interruption/protection and accessibility await user observations. These limits are application safeguards, not provider quota measurements. IH06 owns quota/legacy transitions; IH07 owns final integrated cleanup and polish.
