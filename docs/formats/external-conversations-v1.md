# IM05 external conversations and unified transcripts

October 9, 2026. This stage extends [IM04 graphs](import-graph-v1.md) with imported-history storage/read contracts and a staged transcript preview. **SQL/minimum reader 24**; external origin, external message and transcript projection **1**. Native conversation records remain 2, messages 1, captures 1–5 and direct execution/bindings 4–6. Existing import graph/page/session contracts and their digests remain frozen.

## Storage and admission

`external_conversations` is a one-to-one extension of a normal `conversations` header, with a foreign key to its protected input graph. Its immutable v1 body contains conversation/revision IDs, batch/graph IDs and graph digest, the exact chosen conversation `GraphRecord`, same-identity variant record IDs, import time, the real acceptance commit ID and an explicit exclusion flag. Original archive/no-recall flags and historical dates remain graph facts, distinct from Collie's current archive state and import timestamp. An imported header has null manuscript origin and its creation timestamp equals import time; no historical date is invented to fill that field.

`external_messages` has project/message identity, conversation ownership and a unique nonnegative sequence. Its v1 body contains message/revision/conversation/graph IDs, sequence, visible/excluded status, the exact chosen message `GraphRecord`, variant IDs and `orderRecordId`. The latter names the same-identity record in the chosen conversation representation that proves ordering. Body selection can therefore preserve a curated variant while order remains tied to a reviewed original path. Historical role/participant, node/message IDs, dates, text references, branches, issues and unknown-field notices remain in the exact graph descriptor. There is no attempt, provider, capture, user/assistant-pair constraint or execution grant.

Sequences are contiguous from zero and may contain any number of consecutive assistant or user messages. A conversation is limited to 50,000 imported messages; the project to 100,000 external messages and 10,000 external origins. Descriptors are at most 64,000 UTF-16 units, with at most 128 same-identity variant IDs, including the chosen record and order witness. Each accepted message has at most 1,000,000 total text units, resolved from immutable original text references rather than duplicated text blobs. Internal reasoning cannot be an external message. Unknown/system/developer/tool roles remain exact labeled external material and are excluded; only eligible visible user/assistant candidates may be marked visible. No oversized record is silently shortened for acceptance.

SQL validation checks strict canonical bodies, scope, graph/batch/revision links, unique IDs across native/external messages, contiguous sequence, one identity per prefix, header/import-time agreement and commit ancestry. The graph's protected revision head must precede the acceptance commit; any native capture in a suffix must descend from that acceptance commit. Cross-page graph admission compares chosen descriptors exactly with authoritative graph records, checks every retained variant identity, and proves increasing order through same-conversation/source-representation order witnesses. A fabricated descriptor cannot replace the original evidence.

Schema 23 DDL/readers stay frozen. The retained-copy 23→24 migration adds empty tables; it does not convert existing chats, create messages, accept candidates or change native attempts. Full database snapshots, retained-version hashes and archive database copies include both tables. Portable graph artifact admission carries their evidence claims and checks them alongside the original graph pages. Independent copies rekey only outer project ownership; internal IDs, external IDs, timestamps, commit/graph references, descriptor bytes and digests remain unchanged. Existing import-bearing working-copy removal refusal remains in effect.

IM05 deliberately exposes **no accepted-content writer or acceptance command**. IM10 must supply the confirmed transaction, exact operation receipt and destination checks; a table or projection is not authorization to populate it. V1 permits one immutable prefix only, never later insertion of imports around a native suffix. Imported continuation and imported context/memory versions remain IM11; current Send/review and prior-chat recall fail closed for an external conversation rather than silently providing native-only context.

## Projection and cursors

`transcript-read`, `transcript-text` and `transcript-find` are strict read-only actions. The existing Import boundary admits only a staged source `{kind, batchId, graphId, recordId}`. The existing Conversations boundary admits only an accepted source `{kind, conversationId, revisionId}`. Worker ownership still requires the exact open project/workspace. Neither route selects paths, writes content, probes an account or calls a provider.

An entry has a typed key `{segment, sequence, messageId, messageRevision}`. Imported keys precede all native keys; native ordinals keep their original values. Each entry contains normalized and original roles, original historical time/precision/zone information, distinct nullable import time, visibility, a bounded excerpt and full text-unit count. An imported entry has external graph/record/variant evidence and `native: null`. A native entry has its actual attempt ID/state and context-preparation label, with `external: null`. Historical messages never acquire a live-request outcome.

Page cursors bind conversation ID, conversation revision and the exact segment/key. Forward and backward continuation are exclusive of the cursor. Exact-target navigation includes the target message. Staged conversation identity for navigation is the selected conversation record ID, and its revision is the immutable graph ID; this keeps two raw/curated representations distinguishable. Accepted revisions change under existing conversation owners. A missing, wrong-scope, wrong-segment, changed-message or stale-revision cursor fails rather than redirecting to a nearby message. No physical row order or imported timestamp determines transcript sequence.

For staged reads, the chosen conversation record selects one original representation. Messages with its conversation identity and source file are ordered by graph order, grouped by identity within that representation and linked to all retained same-identity variants. Alternate branches remain in the graph; internal bodies are omitted and counted. The preview does not splice extra messages from another representation or claim that a preview choice is an acceptance decision. An unresolved/unsupported message can appear only as labeled excluded material. Accepted reads use the committed prefix sequence followed by native messages; the same external-entry projector supplies both paths.

Pages return at most 20 entries and 100,000 serialized units, with 1,500-unit excerpts. Large descriptors may reduce the number of entries on a page. Text reads return at most 8,000 units and explicit continuation, never splitting a surrogate pair. Source files are hash-checked regular managed blobs, decoded with strict UTF-8 and the bounded JSON reader. The exact original field/span and per-part text digest are checked before display. One decoded original and one resolved message are cached per request; no cross-project/global text cache is introduced.

Display mapping v1 is **identity mapping**: text parts concatenate without inserted characters, marker removal, Markdown/HTML rewriting or invented prose. Each returned slice includes its display range, original text-reference ID and original decoded-field range. This supports future exact selections without treating rendered links/images as provenance. Non-text/unknown structure remains at its original locator. Staged over-limit content remains inspectable under IM04 bounds; accepted message bounds remain stricter.

Find searches visible messages in at most 32 slices per request, at most 8,000 units per slice, and returns at most 20 matching messages. Overlap retains matches across slice boundaries. Literal Unicode case-insensitive matching preserves original offsets. Continuation binds the exact query, transcript cursor and within-message offset; it reports unfinished scanning honestly. Excluded material and native context preparation do not participate. Selecting a result uses its exact key. Find and paging do not reconstruct or dispatch a conversation.

## Existing consumers and boundaries

List/grouped-list/summaries retain their native shape and add optional imported summary metadata only for an external origin: import time, original historical date, original archive/no-recall flags, exclusion and prefix count. Without a native suffix preview they say “Imported history” and give the count rather than inventing a recent live reply. The new unified read/Find contracts are ready for accepted consumers; IM11 integrates them into the ordinary retained chat UI. The existing native paired-history and Find interfaces remain unchanged for current chats.

The existing explicitly requested transcript export prepends the imported prefix using the same external projection and protected original resolver. It writes each message separately, with original role/date, import/provenance/variant information and visible/excluded labels. It creates no outcome/provider line for external history. Actual native history, sent context, web references, memory and source receipts retain their established export behavior. The existing 64 MiB limit, native destination owner and complete-before-publication behavior apply; overflow refuses rather than truncating. A plain-text transcript is not a replacement for the `.collie` file containing whole originals and other variants.

The staged Import UI offers **Preview ordered transcript → Read transcript**, earlier/later paging, Find, exact result navigation, original text slices and origin/variant details. It stays within the existing dialog, with generation guards and composition-aware search. It creates no fake accepted chat to demonstrate the schema. Actual corpus coverage, native migration/persistence/export and accessibility remain user-owned checks in the [IM05 manual guide](../manual-testing/import-IM05.md).
