See [the hybrid plan](../../import-hybrid-implementation-plan.md), [mapping v1](import-mapping-v1.md) and [local evidence](import-local-evidence-v1.md). Runtime acceptance remains user-owned.

## Scope and authority

New blank-instruction imports first use the existing recognized readers. Unfamiliar JSON without usable local candidates receives bounded structural discovery; recognized files, their message bodies and unrelated project material are not included in these requests. The existing setup/model selection, retained operation owner, protected own-account transport, cancellation, summary and atomic Accept remain the owners. File contents, filenames, URLs and embedded paths are data, never instructions or execution authority.

A deterministic discovery task binds a source graph, selected settings, original file hashes, full retained profiles and representative examples. Grouping is conservative: both structure and first/last representative evidence must agree, not only object shape. Different counts or examples can require independent groups. All group members remain individually bound and must be admitted by local application. No global mapping registry, parser choice or mapping editor is added.

At most **8 admitted structure groups** are planned for a selection, one request in flight. Each group is attempted once in IH04; a confirmed failure, invalid mapping or uncertain request is not automatically retried. Explicit Continue processes unread groups only. Confirmed quota retry is IH06. Extra groups or profiles/programs exceeding limits remain omissions with retained originals and a bounded limitation. There is no full-record recognition fallback or model substitution. Nonblank instructions still require IH05 semantic interpretation; they are kept and explicitly refused rather than silently ignored.

## Request, capture and output

`project-import-mapping-v1` packets contain contract version 1, task `partId`, exact `captureDigest`, batch/source graph identity and digest, blank-instruction category settings, only that group's file descriptors, protected profile IDs/digests and bounded structure strings. Each string contains counts, field types, collections and sampled first/last variants with explicit omissions. Full profiles remain local. Packet maximum is 60,000 characters; profile wire examples are at most 50,000 characters each. The final transport separately enforces the existing **80,000 character / 320,000 UTF-8 byte** wire bound, so a syntactically admitted packet can still be refused before dispatch. Responses are capped at **32,000 characters**. Existing five-minute request and 90-second network-idle guards remain; no overall import deadline or account-usage percentage is invented.

Portable capture **3** records source `none`, the exact prompt/context, source graph revision head and digest. Only main's explicit ephemeral grant, the current account/model/catalog/review stamp and surviving active project scope authorize dispatch. The actual dropdown model is used. Opening, reading, protection retry, Save, independent copy and restart confer no inference grant. A model preference alone is not required for local work.

The response is exactly `{version:1, partId, captureDigest, mapping}`. It must echo the task/digest and supply an IH03 mapping whose profile IDs match the packet in order. Unknown operators, extra keys, executable logic, invented bodies and original-reference mismatches are unusable. `mapping:null` is an explicit unusable refusal, retained as raw output, never import evidence. No automatic repair request is issued.

Capture/run **3**, direct execution/binding **10**, framing **8** and handoff **5** use the existing encrypted operation journal, streaming, local protection and exact terminal handoff. Historical capture/run 1–2, execution 1–9, framing 1–7 and handoffs 1–4 retain their validation rules, prompts and digest domains. Raw terminal output is protected before local application. The finite coordinator waits for the exact terminal handoff before starting another request.

## Full-file extraction and normalized evidence

A valid mapping is applied by the IH03 interpreter to all bound originals. Its immutable `mapping-v1` normalization/pages preserve exact text locators, original fields, identities, roles, order witnesses, source decisions, relationship evidence, coverage and omissions. A saved identical valid mapping/normalization is reused without another request. Invalid application cannot replace independent recognized-file results or promote sampled coverage to whole-file compliance.

Import mutation/revision **3** (`prepare-mapped`) uses the existing exact session receipt and uncertain-write recovery. It installs a graph **2** / reader **2** alongside its immutable source graph. The graph declares `sourceGraphId` and exact `{normalizationId, attemptId}` selections. It combines unaffected recognized-file records with mapped-file records, preserving record/relationship/text IDs while assigning the single graph's contiguous record order. One file cannot belong to two selected normalization families. Only proven original relationships survive; no links are guessed across unrelated groups. Original graphs, profiles, responses and history remain retained.

Review **4** and confirmation manifest **4** distinguish `mapping-applied` evidence from local-reader review/manifest 3. Evidence freezes source graph/mapping selections, settings, pages/records/relations digests and complete coverage. There are no fabricated recognized-record AI proposals or local AI attempts. The existing automatic choices, source matching, original-identity duplicate detection, partial summaries, frozen head/artifacts and atomic commit/receipt are reused. Only Accept creates destination conversations/messages, Research sources or literal notes.

Mapped metadata is resolved from the original file at every admitted `mapped.original.*` locator before existing bibliography normalization and note-label/authorship handling. Accepted transcripts, source-only message origins, note origins and later imported conversation context continue to consume the same exact protected graph records/text references through the extended graph reader. Generated summaries are not imported original bodies; authorship and verification are never inferred.

## Portable admission and recovery

Migration 34 → 35 occurs on the existing retained candidate and changes format tags only. Managed tables, assets, archive inventory, Save/copy, outer-project rekey, retention and working-copy protection preserve new records through the existing owners.

SQL admission validates source/revision/settings/file bindings, new schema gates, capture/run versions and digests, selected response/mapping ownership, review/manifest identities and existing receipts. Blob admission regenerates each profile from its whole original, compares captured examples/digests, replays each mapping locally, compares all normalization pages/records/relations/coverage, and proves the combined graph equals the source's independent records plus selected normalized results. Selected mapping programs must equal their protected valid responses, including empty-result graph families. No admission step sends inference or accepts content.

Progress uses actual structure-task outcomes and protected streamed character/activity/time observations. Partial findings never display an unconditional zero-request claim. Cancellation stops scheduling before provider cancellation, retains preparation/findings and returns to the same setup. Check status reconciles/protects existing work only. A reopen restores discovery separately from legacy analysis and requires explicit Submit/Continue before further inference. Failed/refused tasks and unknown outcomes remain distinguishable from unread work. Local protection recovery uses existing contextual controls; no technical payload dashboard is added.

IH05 owns semantic instructions and prose extraction; IH06 owns confirmed quota retry, usage links and legacy transition; IH07 owns final compatibility cleanup and integrated acceptance. Native persistence, provider mapping quality, corpus coverage, focus/accessibility and release acceptance are not established by code checks.
