# Working project schema 7

Schema/minimum reader 7 extends [schema 6](working-project-v6.md). Archive container and editor AST remain version 1. Existing working copies migrate 6→7 through a retained same-volume backup and validated candidate; earlier copies use the registered chain. An unsuccessful migration retains the original. Older schema-2/3/4/5/6 archives migrate in the local workspace, never in place in the selected archive. New archives declare schema and minimum reader 7.

Five strict project-scoped tables are added: `research_questions`, `research_claims`, `evidence_links`, `research_decisions` and `research_revisions`. Questions and claims store text, active/archived state, optional section/note IDs, the associated section revision, their own revision ID and timestamps. Evidence links store source/excerpt and claim-or-section ownership, target revision, role, human origin, review state and active/removed state. A unique identity key prevents duplicate logical source/excerpt/target/role links. Decisions have one current candidate/kept/rejected state and reason per question/source pair. Before mutation, prior rows are retained in revision snapshots without the project ID. This lets independent copies rekey all five tables without retaining the previous project's identity in history.

The worker checks excerpt/source ownership, live targets, expected revisions and duplicate identities before atomic changes. The portable graph includes the new tables, ownership and revision snapshots. A source reimport changes the active version selection without retargeting old excerpts. A section or claim change does not claim unchanged support; the stored target revision allows the panel to flag it. Manual links, Stage 11 source-library section links and actual citation occurrences are distinct data and projections.
