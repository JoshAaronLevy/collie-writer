# Project import analysis v1 — IM07

October 9, 2026. Implements one explicitly authorized, bounded request from an inspected import selection. [Plan](../../import-implementation-plan.md), [design bounds](project-import-v1.md), [manual guide](../manual-testing/import-IM07.md). Implementation is separate from pending live acceptance.

## Versions and ownership

SQL/minimum reader **26** adds `import_analysis_captures` and `import_analysis_runs`. Schema 25 and earlier DDL remain frozen; migration uses the existing retained-copy owner. Import packet, capture, run and proposal are version **1**; execution/binding is **7**, direct framing **4**, import handoff receipt **2** (`ai-handoff-v2`). Conversation/proofreading use their original execution versions, instructions, digests and v1 receipts. Archive/editor, import graph, external messages and imported-content origins do not change.

The import adapter uses `AiContentService`, `AiService`, `DirectPlanSession`, the serial project worker, encrypted execution journal and existing result handoff. It has no independent provider queue, credential owner, API key, tool runner or file-upload transport. Worker/main/preload inputs use exact shape validation; renderer cannot supply proposal writes or acceptance commands. Account/model/catalog/session are frozen by the existing main-owned authorization and v7 execution. Main invalidates sharing review on account/model/catalog/route changes and expires it after five minutes; renderer retires the displayed review after four minutes.

The two SQL tables keep immutable capture bytes and one retained run per capture. Every first submission and changed protected outcome advances the project head; exact submission replay only reads the existing attempt. Capture head is the graph revision's committed head, so unrelated manuscript saves do not replace or invalidate original evidence. Selection/settings changes clear the graph selector and make earlier results stale. Neither saved attempts nor copied execution descriptions authorize sending.

## Request and disclosure

An explicit local sharing review reads the current graph and the protected originals. It selects **every** eligible candidate record, copies exact record metadata and full original text parts in order, and includes evidenced relationships touching those records. Internal, rejected, search, unsupported and ineligible records remain in originals/graph; they are not primary transmitted fragments. Relationship endpoint IDs may refer to excluded records without transmitting their bodies. Exact file IDs, original names/hashes, graph/digest, category/instruction settings, record/text locators and exclusions are disclosed.

Each `project-import-analysis-v1` packet has version, partId, captureDigest, batchId, graphId, graphDigest, settings, projectContext, files, fragments, relations, excluded and outputContract. In IM07, `projectContext` is explicitly null: no manuscript, existing Research, other chats or implicit workspace context is added. Fragment ID equals the exact input record ID; one part covers the whole eligible selection. The packet digest includes its complete content excluding its own digest plus the frozen instructions. The enclosing capture digest additionally covers the immutable capture fields and the exact serialized context. Scope lives in SQL ownership/commands, outside portable evidence.

Local admission requires 1–128 eligible records, no more than 55,000 original text units before metadata framing, at most 256 evidenced relationships and the complete packet within 60,000 UTF-16 units / 240,000 UTF-8 bytes. Full request JSON including model, instructions, escaping, framing and flags stays within 80,000 units / 320,000 bytes. There is no prefix truncation, first-part fallback, or hidden second request. Empty, excessive or capacity-exhausted selections are refused before dispatch. IM08 owns general partitioning and explicit finite continuation.

The HTTP body uses the current route's model, frozen instructions, one text input item, `store:false` and `stream:true`. It supplies no tools, web policy, previous response, Files attachment, or unsupported provider JSON-schema/output-limit field. Strict JSON is requested in instructions and validated locally. This follows the route's [published preview requirements](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations), inspected October 9; it does not establish account eligibility or successful live analysis.

## Proposal validation

The model must return exactly `{version, partId, captureDigest, coverage, entities, links, issues}`. No Markdown wrapper, trailing prose, duplicate JSON keys, coercion or repair request is accepted. Terminal output is bounded to 128,000 units / 512,000 bytes, with finite parse depth/value count. The normalized proposal must also fit 128,000 serialized units.

- **Coverage:** exactly one outcome for each supplied record/fragment: identified, unresolved, unsupported or no-selected-content, with a bounded explanation. Identified needs an entity mapping. Unresolved coverage remains visible, even in a syntactically valid proposal.
- **Entities:** at most 128 unique UUID candidates, only chat/message/source/note/label. Every record reference must be supplied and the kind must match, except labels. At most 32 unique, supported fields per entity and at least one field; messages need role/body/order, notes need body, chats need title.
- **Fields:** exactly one original value reference or inferred string suggestion. Reference-only original bodies use `record:<id>:body` for all original text parts in order, or `text:<id>` when the record has one text part. `record:<id>:title` means the graph's display label; exact original title metadata may instead use the corresponding fact reference. Role/order and `record:<id>:fact:<index>` refer to exact original fields, with field-name compatibility checked. Suggestions require input evidence and `inferred:true`, and are restricted to titles or label name/kind. They cannot invent author/publication/identifier/quote/body facts or verified status.
- **Links:** at most 256, exact known kind/endpoints and matching supplied relation evidence. Kept/rejected/search/cited decisions and grades stay in their immutable graph evidence; a model cannot overwrite them.
- **Issues:** at most 128, from a fixed code vocabulary, scoped input references, boolean blocking flag and bounded explanation. No SQL, arbitrary destination IDs or executable mutations.

Validation is a proposal-shape/evidence check, not a claim that metadata is accurate, all material was identified, conflicts are resolved, or anything was accepted. IM09 owns human corrections/coverage review; IM10 alone will own confirmation and atomic domain writes.

## Protection, recovery and portability

The provider parser requires a genuine terminal completion. Streamed text, EOF, Stop, network errors, invalid output and uncertain outcomes never become a valid proposal. The protected complete raw response is retained even when local validation fails. The worker settles raw output plus validation/proposal in one transaction. Only a protected terminal, validated result can receive usable presentation; local protection/handoff failures remain actionable and no repair/retry is automatic.

The retained renderer owner spans intake and progress dialogs. Analyze closes intake and waits for exit before progress opens. Closing progress keeps the operation and exact uncertain submission. Check saved outcome/reconcile, Stop and Retry local protection reuse existing owners and cannot send a new request. An explicitly chosen Retry exact submission may send only if no attempt was stored and the original authorization is still valid; a stored attempt can never dispatch on replay. Saved analyses page 20 rows; exact content and retained response presentation page 12,000 units. Shared AI work notices route import actions to the same owner. Account diagnostics remain in Manage ChatGPT. No inference occurs on file selection, local inspection, history reads, project opening or restart.

Admission reserves a conservative **2 MiB per retained attempt**, together with intake/graph bytes under the existing 256 MiB derived batch ceiling, at most 1,024 attempts and remaining discard-artifact room. This bound is conservative: the byte ceiling usually admits fewer than 1,024. Database and available-volume checks reserve additional growth before append; they cannot promise future free disk space. Actual write failures retain existing encrypted output and exact local retry. Graph/intake mutations count analysis reservations too.

Portable validation checks table scope, IDs, graph/batch membership, capture head/settings/file names/hashes, packet/capture digests, exact graph records/relations, complete original text-part hashes and exclusion counts; it revalidates terminal proposals against retained output. Snapshot/archive/open/retention graph validation and full-row comparisons include these records. Independent copy rekeys outer project columns only; execution/bindings stay device-local and are never copied as authority. Active records without a local binding become honest unknown outcomes on acquisition; already refused not-sent outcomes stay not-sent. Original import-bearing working-copy deletion remains refused.

Native migration, Save/reopen/copy, actual provider output quality, refusal/Stop/recovery and accessibility await user observations. Installed/commercial provider gates and release NO-GO are unchanged.
