# Imported sources, notes and provenance v1

IM06, October 9, 2026. SQL/minimum reader **25**. Implementation complete — awaiting user testing. [Plan](../../import-implementation-plan.md); [manual guide](../manual-testing/import-IM06.md).

## Ownership and compatibility

`imported_content_origins` adds immutable v1 occurrence/note origin descriptors beside the existing sources and notes. Schema 24 DDL is frozen; retained-copy 24→25 migration adds this table and reader floor only. No old body, request digest, AC07 live reference receipt, external-message record, original file or graph page is rewritten. Native note creation still produces `origin: human`; only the internal imported-content writer can create `origin: imported-v1`. Authorship remains unspecified unless the input explicitly declares `authorship: human` or `authorship: ai`, and these declarations are unverified. Model-generated notes require a distinct future reviewed proposal contract and cannot masquerade as imported originals.

The table binds project, graph, original record, nullable destination source/message/note, acceptance commit and strict canonical descriptor. Unique graph/record prevents duplicate occurrence receipt insertion; note origin is unique. An immutable descriptor contains the exact graph record, exact reference relation if present, graph digest/batch, original labels and declared authorship, conversion losses, acceptance time/commit, and the initial note revision/body digest. Receipt descriptors are bounded to 100,000 units each and 20 million units/100,000 rows per project. Historical author/time/grade/decision fields remain in the exact graph evidence and protected original. Import time does not replace original dates.

A reference may have no accepted source and no accepted message. A rejected/search occurrence remains retained-only even when another occurrence of the same source has an eligible destination. An accepted message must be an external message from the same graph whose retained variants include the exact originating graph message. No fake native attempt, AC07 receipt, inspected excerpt, research decision, evidence link or verification flag is manufactured.

## Local destination preparation

`content-preview` is a read-only, project-scoped request naming an existing batch/graph. It returns a current project-head witness, bounded pages and whole-graph counts. It uses only selected protected originals and graph records. Original reads use existing contained, no-follow, single-link, length/hash-checked blob access and bounded strict JSON. One original is cached at a time. Source fields are read from originals, not truncated graph facts. Bibliography parsing and canonical metadata normalization reuse the existing source owner. Preview performs no provider request, URL fetch, disk-path traversal, source creation or acceptance.

Source candidates preserve independent occurrence decisions/grades/locators. Work type mapping to webpage is disclosed when missing/unsupported; missing titles, invalid dates/identifiers and oversized metadata remain unresolved. Missing authors/dates stay missing. Attribution is not an inferred author. Search snippets and grades remain unverified annotations. Source normalization is disclosed and originals remain unchanged.

Strong normalized DOI/ISBN/URL matches connect proposed destination groups across selected representations; identical complete metadata groups records without strong identifiers. Conflicting metadata within a group is explicitly unresolved. Similar title/author matches are existing-source suggestions only. Canonical matching follows bounded merge chains and shows removed matches without restoring them. An existing destination is never silently updated, merged or marked verified.

The preview counts source **groups**, not promised new Research rows. Final review can choose existing destinations, resolve conflicts or omit groups. Counts for unusable/unselected records are retained-only; the graph inventory still owns overall unsupported-file/branch coverage. Ten candidates per page, dynamically constrained to about 90,000 serialized units; source metadata is capped at 50,000 units, losses at 16,000, labels at 100, note bodies at 1,000,000 and text previews at 1,500. Long original text remains available through the existing graph text slices. No input is silently represented by just its preview excerpt.

Notes are explicit note records or selected text/Markdown files under Notes scope, never arbitrary chat prose. The conversion creates a plain paragraph containing exact original text. Markdown/HTML/table/image/citation syntax remains literal text; no links, images or URLs execute or fetch. Unsupported controls/size prevent a destination. Supported tags/categories become proposed labels; unknown/oversized structures and foreign links stay in the original with loss notices. Original author fields do not authenticate authorship. The initial note body digest and text-part hashes remain verifiable after ordinary note edits, because normal note revisions preserve the initial body.

## Dependency groups and category combinations

| Selection           | Destination dependencies                                                                        | Retained evidence                                                                                                  |
| ------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Chats only          | IM05 conversation/message candidates; zero source or note destinations                          | Reference occurrences and originals stay in the graph; no Research creation                                        |
| Sources only        | One reviewed destination per connected source group; each eligible occurrence can link to it    | Exact input message locator/relation remains sufficient; visible chats are not required                            |
| Notes only          | Each note body, initial revision, origin and supported label links form one atomic group        | Exact note text/metadata/foreign links remain in the original; no implicit sources                                 |
| Chats + sources     | Same source groups; accepted message link is optional and must match the exact retained variant | Unaccepted messages can still be retained-only origins                                                             |
| Any mixed selection | Independent category scopes; all reviewed groups settle in IM10's transaction                   | Rejected/search/unsupported occurrences never become accepted evidence merely because a related destination exists |

`ContentCommitChoice` carries an explicit destination per original record, optional accepted message ID, exact existing-source revision, and explicit chosen metadata record for new-source groups. All choices in a source group must resolve to the same destination. Notes accept explicit project-local document IDs only; original foreign IDs cannot create links. Active normalized labels may be reused; archived labels are not restored. IM09 owns editing these choices; IM10 owns the final immutable reviewed proposal, confirmation and replay identity.

## Internal writes and preservation

`prepareContentWriter` returns a closure over worker-read protected content. It is not registered as IPC and has no UI call site. It requires an already-open transaction, the unchanged prepared head/current graph and a new child commit. It does not open/commit a transaction, advance the project head, create a domain-operation receipt or accept a batch. Its eventual IM10 caller must revalidate the exact reviewed proposal/account-independent acceptance intent, bind the receipt and advance all owners atomically; failures must roll back the enclosing transaction. Same-operation replay belongs to that owner, not this primitive.

New sources are unverified. Explicit existing-source links require an active exact revision and write no metadata or verification updates. Note text/labels/explicit links and origin rows are written inside the caller's transaction. Limits, IDs, graph/message membership, group consistency and note body validation remain production safeguards. There is no source/note acceptance route in IM06.

SQL admission validates descriptors, table/body identity, project boundaries, source/message/note existence, commit ancestry, initial note revision/body hash and exact original text spans. Graph artifact admission checks exact records and relationships across pages. `.collie` Save, incoming validation, snapshot/export, retained-copy migrations, independent-copy project rekey and full-database retention digest include the table and existing protected originals/graph assets. Retained note revisions are not pruned. Import-bearing working-copy removal remains refused.

`content-origins` provides bounded read pages by accepted source/note ID; merged-source aliases retain original receipts without rewriting them. Native bibliography exports explicitly disclose omission of imported decisions, grades and message origins, alongside other project-only provenance. The portable project is the lossless provenance export. Notes' normal read contract accepts the versioned origin label; normal note editing preserves it. Accepted-source/note presentation and round-trip acceptance remain gated on IM10's real confirmation path; staged previews are the user-visible IM06 surface.
