# Working project schema 5

Schema/minimum reader 5 extends [schema 4](working-project-v4.md). The archive container and editor AST versions remain unchanged. Existing schema-1 through schema-4 working copies migrate through a same-volume, retained backup and a new candidate SQLite file. Only a validated candidate becomes active; failures preserve the original and migration copies. Schema-2/3/4 archives remain readable through their declared manifest/version pair; new archives declare schema and minimum reader 5.

New strict tables: `sources`, `source_revisions`, `source_aliases`, `source_links`, `source_attachments`, `source_import_reports` and `source_import_records`. Source IDs are UUIDs, metadata is the validated supported CSL subset, `raw_import` preserves source input, and `unknown_fields` records omissions. A source may link to many document IDs. `source_attachments` has an attachment ID and an independent managed asset ID; an attachment can be removed from the active source without deleting the managed asset or immutable blob. `source_revisions` stores prior bibliographic snapshots; `source_aliases` resolves old/imported identifiers after explicit merge or link. Merged sources remain tombstoned with a replacement ID. Import reports and every original imported row, including skipped and invalid rows, are project-local and portable.

Every table is scoped by `project_id` and included in independent-copy rekeying. The portable graph validates exact app-owned schema, SQLite integrity and foreign keys, source record shapes, source aliases and links, and managed blob identity. Archive capture includes all managed assets, even removed attachments, so retained history and future restore do not lose bytes. Bibliography exports include only the declared CSL subset, while the `.collie` project archive retains sources, raw records, reports, attachment copies, notes and annotations independently.
