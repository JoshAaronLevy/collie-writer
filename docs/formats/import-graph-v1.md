## Authority and preservation

**Inspect selected files locally** first protects current settings, then submits one exact `prepare-graph` mutation through the retained Import owner and main's existing write/recovery guard. The worker reads only selected managed originals at their captured hashes. It never scans folders, resolves embedded `source_file` paths, opens URLs or interprets file content as commands. It neither calls ChatGPT nor creates accepted content. A fresh inspection is a deliberate new revision; an uncertain retry first looks up the exact operation receipt.

Schema 23 adds `import_graphs` (one immutable manifest per graph-bearing revision) and `import_graph_pages` (ordered immutable page descriptors backed by managed assets). The graph, revision, current selector, real project head and session receipt install together. Page blobs are staged and admitted before that SQL transaction. Graph artifacts use `application/vnd.collie.import-graph+json`. The manifest binds source revision, resulting revision, exact selected files/hashes, reader version, coverage/counts and the digest of ordered page descriptors. The old `intake-v1` artifact remains the frozen staging inventory; its zero analysis/acceptance counters and null downstream selectors do not represent the separate local graph.

Changing files, categories or instructions clears the current graph selector through a normal v1 preparation revision; prior graphs/originals remain retained. Discard also preserves history. No settings change, reopen, receipt lookup or copy reruns inspection or inference automatically. Schema 22 DDL/readers stay frozen under the retained-copy 22→23 migration. Save/Open, snapshot, archive/restore, independent-copy rekeying and retention consume the complete graph assets. Rekey only outer project ownership; batch/record/external IDs, evidence bytes and digests remain unchanged. Import-bearing working-copy removal stays refused under the earlier recovery rule.

Admission validates manifest/revision correspondence, immutable selection/settings, descriptor order and digest, asset ownership, byte hashes, record/page bounds, original-file locator membership, unique records/texts/fragments/relations, complete fragment coverage, membership/parent/reference/identity relationships and recomputed totals. Independent-copy and portable paths use the same semantic artifact reader. Exact text preview additionally resolves the original field/span and checks its text digest; no preview trusts a renderer-provided source path. No imported evidence grants execution authority.

## Bounded readers

- JSON: fatal UTF-8 decoding with a retained BOM flag; strict parser with duplicate-key rejection, finite numeric values, maximum depth 64, maximum decoded string 2,000,000 UTF-16 units and 1,000,000 members/values across selected inputs, including failed parse work. Original numeric timestamp lexemes are retained separately from optional normalized UTC. Missing zones/precision remain unknown.
- Recognized JSON shapes: raw chat envelopes and aggregate arrays, raw mapping nodes, bare message arrays, curated thread/message/source collections, CSL records/arrays, explicit `type: "note"` text/body objects, and arrays under conversations/chats/messages/notes envelopes. Unfamiliar structures receive a retained unclassified record and a clear local-reader limitation. Selection scope, not names/topics/directories/dates, determines which inputs are inspected.
- Text/Markdown: exact decoded text becomes a note candidate only when Notes is selected; otherwise it stays unclassified. Markdown is not executed/rendered as imported HTML and its unsupported future note structures are disclosed. Prose inside a chat is never guessed to be an authored note.
- CSL-JSON/BibTeX/RIS: existing bibliography parsing/normalization helpers, bounded to 2,000 explicit BibTeX/RIS entry starts per file and 300,000 units per entry. Original spans, unsupported fields and normalization losses remain inspectable. A preamble outside entries is reported. Bibliography parser/normalization errors stay with the affected record; this adapter does not promise support for arbitrary macros or ambiguous entry boundaries.

File admission stays at 100 files, 25 MiB each and 100 MiB retained originals per batch. Extracted text plus represented metadata is limited to 20,000,000 UTF-16 units; records to 50,000 and relationships to 100,000. Admission charges extracted units before adding fields. A file that exceeds reader bounds or has corrupt JSON is reported individually with no misleading partial extraction; its original remains protected and other inputs can still be inventoried. Unsupported structure differs from corrupt syntax and exhausted limits. If graph-wide consolidation/storage capacity cannot be admitted, the operation refuses and retains the existing selection for an explicit smaller inspection.

Descriptors have bounded metadata (32 facts, 4,000 units each and 16,000 combined; 128 short unknown-field names). Further metadata stays at the exact original locator with a notice. Every logical message/note over 1,000,000 total text units is ineligible for later acceptance; all admitted text still has contiguous fragments. Each text reference has at most 128 fragments of at most 16,000 units, exact UTF-16 offsets, an original field span and a content digest. Surrogate pairs are not split. Long plain-text files use contiguous parts; this never silently turns one oversized note into multiple accepted notes.

Pages contain at most 50 records or 50 relationships and 60,000 serialized UTF-16 units, within the existing 1 MiB artifact ceiling. A single record descriptor is capped at 48,000 units; the manifest at 40,000; graph pages at 4,000; retained derived artifacts remain within 256 MiB per batch. Storage admission also reserves project asset/space capacity. Preview responses are capped at 50 rows and 100,000 units, with indexed kind counts/record IDs and explicit continuation. Text reads return at most 8,000 units and a next offset. Limits never imply content was fully analyzed or accepted.

## Identity, order and occurrences

Each record has an opaque deterministic UUID derived from original file ID/hash, RFC 6901 pointer and record kind (bibliography entries additionally use exact spans). Text and fragment IDs derive from their exact source/ranges. External IDs are separate preserved strings. Graph ID is a new UUID for the inspection revision; record identities remain stable for unchanged selected originals.

Raw transcript ordering follows `current_node` backwards through parent links, then reverses that chain. Null structural nodes and alternate branches remain records; alternate branches are excluded from ordinary analysis. Every parent chain is checked for cycles/missing nodes/contradictory IDs, including alternate branches. Missing or contradictory conversation identity does not become a guessed chat. Raw mapping key, message ID, external conversation ID, role, historical times and branch membership remain separate fields.

Curated thread descriptors represent distinct chats; the aggregate root is retained collection metadata. Explicit message conversation IDs take precedence. Missing IDs can inherit the envelope only from an unambiguous single thread or a contiguous missing-ID prefix consistent with the declared root-thread count and later explicit memberships. Such membership is marked inferred until supporting selected raw identities establish it. Unknown membership stays unresolved. External raw and curated namespaces stay distinct until selected raw message evidence supports their common identity.

Cross-file matching uses message ID plus a unique raw conversation identity. Bare arrays additionally need matching role and exact text-part digests; curated messages can retain differing bodies as variants of a supported same-ID/same-role message. Contradictory explicit identities and ambiguous raw matches stay unresolved. Proven matching maps records to a shared conversation/message identity and raw path, without deleting any occurrence. `equivalent` means exact visible text and role, not equality of all metadata. Separate `same-identity` relationships preserve body/metadata variants. Equal literal source URLs generate only possible-match links, never source merges or global inclusion decisions.

Internal thought/reasoning/analysis and explicitly hidden message bodies have no graph text references or preview expansion. Originals still contain them, as disclosed during intake. Unknown/system/tool roles stay labeled and ineligible. Supported visible string parts are retained independently of unsupported multimodal parts.

Curated `sources.kept` and `sources.rejected` remain separate reference occurrences tied to the originating message and exact pointer; grades remain imported annotations. Raw supported webpage references, search-result groups and supporting websites retain distinct cited/search decisions. Images/widgets/unfamiliar reference types are retained as unsupported metadata, not promoted to cited sources. A title/URL/snippet/grade is not evidence of fetched, inspected or verified article text, nor an inspected excerpt. Rejected/search/alternate/internal material is ineligible under ordinary scope. Choosing Sources without Chats can still retain eligible references from supported message provenance.

## Presentation and stage boundary

The retained intake dialog exposes local inspection, a read-only inventory, per-file coverage, kind filtering, record/relationship pages and exact text slices. Deep details show original names, IDs, membership, source pointers, facts, exclusions and ambiguity. Relationship controls navigate to each endpoint without scanning/rendering an entire corpus. Read failures retain the selected batch; late replies cannot replace an unmounted preview. Dirty choices disable the saved inventory until protected and reinspected.

Logical conversation/message counts use identity groups; reference counts are occurrences. Neither equals file count or accepted-domain totals. The sample collection's expected 34 logical chats is a manual acceptance target, not a runtime constant. The user must inspect actual coverage and variants using the [IM04 guide](../manual-testing/import-IM04.md). IM05 onward owns external domain records, ChatGPT payloads, progress, review and explicit final commit.
