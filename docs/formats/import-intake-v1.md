## Native authority

`project-import.command` adds `pick-files` with exact project/workspace, batch ID and expected revision. Only the trusted top-frame owner can invoke it. Main checks the currently opened writable project, access state and captured frame/process identity before opening the native chooser and after its result. A main-owned intake scope prevents Save, project replacement and access changes while choosing/reading/staging. Close erects the existing barrier; work already dispatched settles, and unresolved intake pauses close.

The picker allows multiple individual files. Repeated Add files supports other folders; no folder enumeration, sibling reads, archive expansion, embedded path traversal or reference-app access exists. JSON/CSL-JSON, UTF-8 text, Markdown, BibTeX and RIS extensions are admitted; All files lets unsupported selections receive an explicit notice. Unsupported originals are not read/staged. Limits remain 100 retained files, 25 MiB per file and 100 MiB per batch. Zero-length, non-UTF-8, symbolic-link, non-regular, multiply linked or unsafe-named files are refused. JSON/bibliography syntax and message/source meaning are **not** inspected yet.

Main reads a supported selection through a bounded 64 KiB buffer, a fatal streaming UTF-8 decoder and SHA-256. It compares descriptor/path identities, size and modification/change times before/after; its descriptor freezes name, format-derived media type, IDs, byte count and hash. The existing worker copies and hashes the exact selected path again, comparing the frozen hash/bytes before committing its original, intake revision, selector, head and receipt. Source paths never enter renderer IPC, portable rows or artifacts. Copies cannot acquire native file or provider execution authority.

Exact duplicate bytes already retained in the same batch receive a notice and do not add another manifest or count. A removed duplicate stays removed until its retained checkbox is deliberately selected. Cross-batch deduplication and semantic conversation/source deduplication are outside IM03. Each successfully staged file gets its own real revision/receipt; a later failure never rolls back earlier successful files. Unsupported/unreadable files have named notices. A retained uncertain write stops the remaining files; they are reported as not staged and require explicit reselection after recovery. There is no automatic retry or later reading of unprocessed selected paths.

## Recovery and retained presentation

A `picked` acknowledgment contains bounded basename/size/status/file-ID/error-code notices, or a cancelled flag, never paths or file contents. Notices are session presentation; protected manifests/revisions are durable. A lost acknowledgment requires **Check saved outcome** against the main recovery owner and trusted worker reads. That action only reads: it never opens another picker, repeats a write or sends an AI request.

For a failed `stage-file`, a receipt lookup that proves absence **keeps** main's exact selected path/descriptor temporarily owned. `resolve-file` accepts only the same scope and complete captured add-file mutation, with explicit Retry or Abandon. Retry first checks the existing receipt and otherwise repeats only those same frozen bytes/IDs; a changed or missing original refuses it. Abandon first reconciles the receipt, clearing main authority only after receipt/absence is known. It cannot undo a completed file or delete an original. Generic local settings writes keep their exact portable retry intent in the renderer even when a proven absence clears main ownership. Pending-path authority is memory-only and disappears with the process; completed originals survive project reopen/Save/copy without the input files.

`ImportProvider` stays under the workspace/draft and shared connection owners, outside navigable presentation. Its registration retains composition, busy state, exact mutations, unresolved-picker state and dirty settings. Incomplete intake blocks unsafe replacement/access/close; dirty settings require Keep for later or explicit restoration before Save/navigation. It does not perform a new write during close's barrier. Native file reads and immediate file removal/reselection revisions are serialized; no stale reply can switch the destination. Head refresh reuses the existing metadata-only refresh and preserves manuscript/editor identity and dirty buffers.

The dialog displays destination title, contextual project/working-copy IDs, retained manifests and selected counts/sizes. Whole-original retention is disclosed **before Select files**: excluded/private records remain in originals and Save includes them. Each original is selectable without deleting its retained asset. Category checkboxes and optional bounded instructions are preparation hints only; an empty category list is allowed while preparing. Keep for later and ordinary dialog dismissal protect these choices; failed protection retains the exact intent and leaves the dialog open. Dismissal never analyzes or accepts content. Saved selections are read newest first in bounded pages; files use at most two pages with an exact revision reference. Discard creates the existing discarded revision and frees an active-session slot, preserving originals and history. New selection creates an independent batch.

Write, Research and Project actions share a named Import icon. Modal focus is trapped and returns to the surviving origin only after exit and scope/navigation/composition/visibility/new-focus guards. Manage ChatGPT first protects and dismisses intake, then opens the existing shared account/model dialog after exit; returning to Import retains its selection. No new provider status probe, model contract, account owner, credential path or dispatch is introduced.

Analyze with ChatGPT is explicitly unavailable. There is no progress simulation, fake proposal, final confirmation, accepted conversation/source/note, or import inference in IM03. Later stages own those controls and contracts. Native persistence, accessibility, focus and acceptance require the [manual guide](../manual-testing/import-IM03.md); code checks are separate evidence.
