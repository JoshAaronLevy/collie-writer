# Working project schema 6

Schema/minimum reader 6 extends [schema 5](working-project-v5.md). The archive container and editor AST versions stay at 1. Existing working copies migrate 5→6 through a retained same-volume backup and validated candidate; older copies follow their registered migration chain. A migration failure retains the original. Prior schema-2/3/4/5 archives remain declared reader inputs and migrate in the local workspace, never in place in the selected archive. New archives declare schema and minimum reader 6.

Four strict project-scoped tables are added: `source_versions`, `source_version_selections`, `source_pages`, and `source_excerpts`. A source version owns one retained attachment and a frozen attachment checksum, media type and canonical metadata snapshot. Its extractor identifier, status, title/author, page count and revision identify the inspected representation. The single active-version selection is separate and explicitly user-controlled. Saved page text has an index, optional PDF printed label, state, UTF-8 SHA-256 digest and optional extraction warning. Plain-text sources use index zero. Extracted excerpts retain an exact UTF-16 range and page-text hash; labeled transcriptions and corrections do not claim extracted-text provenance. A correction points to the earlier excerpt, preserving the original quote. PDF page image coordinates are not stored in schema 6.

All four tables participate in archive capture, restore and independent-copy project rekeying. Portable-graph validation checks source/attachment/asset ownership, representation hashes, ranges, page bounds, excerpt chains and active selection ownership. Stage 11 managed-asset retention includes prior versions' originals even after an attachment link is removed. Source merges transfer version ownership and preserve excerpt IDs. Versions and page data are project-local; no manuscript or source content is sent to the vendor.
