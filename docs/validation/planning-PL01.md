## Behavior and ownership

- **Write → Chapter material** replaces the separate Notes/Source companions. `ChapterMaterialPanel.tsx` uses a bounded worker projection of canonical notes, sources, excerpts and chats, with title search, type filters and 20-item pages. Direct material sorts before the nearest ancestor’s material; each original appears once. Labels identify inherited parents, inactive material and historical chat origin. Add/Remove acts on the selected outline item only; inherited links are removed by selecting their parent. Open original uses existing Research/inspector/conversation owners. Questions/claims and detailed source usage remain accessible in Research.
- `shared/chapter-material.ts`, `worker/projects/chapter-material.ts` and `material-links.ts` define exact scoped inputs/results and the association authority. Existing `note_links`/`source_links` remain canonical; chat/excerpt links are many-to-many identities. Content bodies, transcript turns, source versions and exact quotations are not copied into a second library. Only the visible page loads note/quotation previews. The panel preview is at most 400 characters; Open original reads the complete record.
- `projects.ts`, main/preload IPC, worker dispatch/repository and `domain/capabilities.ts` carry the new read/change commands through existing project/access boundaries. Mutation requires the expected project head and an active outline target; adding requires active material. Note/source revisions and their existing revision history advance when their links change, preventing stale Research forms from overwriting assignments. Chat revisions advance without rewriting historical origins or messages; immutable excerpt links use the project head.
- Link changes use exact operation IDs/digests and ordinary retained commit receipts. The retained panel flushes existing drafts before a change. An uncertain result stays with its exact project and operation; Check change, Save and navigation reconcile through a read-only status command. They never automatically repeat the mutation. Only a subsequent explicit Add/Remove starts another change after a confirmed absent receipt.
- `conversations.ts` groups current-section/current-chapter chats by explicit associations. Existing creation from active writing seeds a direct link. The association migration leaves historical `origin_document_id` intact, including when a link is later removed. Archived conversations remain readable through existing access. `conversationState.ts` has an explicit original-chat opener so an unrelated pending response cannot redirect this action. Linking material does not change AI context; PL04/PL06 own that work.
- `WritingSidePanel.tsx`, `WritingWorkspace.tsx`, `useWritingPreferences.ts` and the scoped panel stylesheet retain one writing/editor owner. Layout preferences migrate locally from v1 Notes/Source to v2 Chapter material, preserving pane widths, focus and AI/closed choices. Replaced `SectionSources` selection plumbing, unused ancestry helpers and companion styles were removed; Research usage/citation/evidence views stay available. The React skill review covered retained ownership, stale async reads, event guards, semantic CSS and keyboard controls; no browser/runtime review was performed.

## Schema, history and portability

SQL schema/minimum reader **39** adds `conversation_document_links`, `excerpt_document_links` and `chapter_material_history`. The 38→39 migration uses the existing retained-original/candidate workflow. It seeds valid chapter/text chat origins once, preserves old readers and does not modify existing material bodies. `manifest.ts` admits 39 alongside the historical version pairs; `schema.ts` keeps schema-38 DDL frozen. Portable graph admission validates link ownership, target identities, uniqueness and exact versioned history records. Independent copy remaps outer project IDs on all three tables; embedded histories contain stable material/document IDs, not project/workspace IDs. Save, Backup and Restore retain the whole database through their existing owners. Content-retention hashing already covers all admitted tables.

`manuscript.ts` stores `{version: 1, links: [{kind, id, documentId}]}` alongside each new checkpoint, preserving the frozen manuscript snapshot format. Link snapshots are capped at 200,000 associations and 32 MiB; over-limit operations fail without truncation. History size accounting and pruning include these rows. This is retained history, not another live association store.

| Operation                   | Association result                                                                                                                                                                                                    |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rename/reorder/reparent     | Stable direct links remain; inherited scope follows the current outline ancestry.                                                                                                                                     |
| Merge                       | Target receives the union without duplicate rows. The merged tombstone keeps its prior links for retained identity/history.                                                                                           |
| Split                       | Direct links stay on the original; the new sibling has no copied direct links. Both may inherit parent material.                                                                                                      |
| Archive/trash and restore   | Links stay attached; inactive outlines are readable and cannot be relinked until restored.                                                                                                                            |
| Restore a new checkpoint    | Restore links for the snapshot’s document identities; keep links on newer retained document tombstones. Preserve current writing/links in the pre-restore checkpoint. Research bodies and states are not rolled back. |
| Restore a pre-39 checkpoint | Preserve current links because no historical association snapshot exists. No links are guessed from chat origins again.                                                                                               |

`outline.ts` applies merge/history link changes in its existing structural transaction. `HistoryPanel.tsx` explains the restored scope. Individual Add/Remove can be reversed with the opposite action; they do not use whole-manuscript restoration as a per-link Undo workflow.
