## Implemented behavior and owners

- `ConversationPanel.tsx`, `conversationState.ts` and `PlanningChatControls.tsx` add Help me write starters and Preview for insertion using the existing retained conversation/composer. A new writing request defaults to the visible chapter, including canonical direct/inherited material through PL04's corpus (which uses PL01's chapter scope). Existing nonempty drafts are preserved in their chats. Scope names stay visible across navigation; only an explicit starter/scope change changes them. Custom prompts remain editable, and Send alone dispatches. New drafting starters leave web search off; explicit search still uses the existing route. Plan can return a writing chat to discussion without insertion.
- `shared/writing-assistance.ts` defines exact historical source points and writing context. `worker/projects/writing-assistance.ts` resolves those points against the protected active manuscript revision and current exclusions. Title, purpose, selected text and nearby writing are frozen with the explicit material scope. The worker checks these again before reviewed capture/append; changing writing or source eligibility during preparation refuses stale work. No hidden whole-manuscript context is added.
- Existing `planning-conversation.ts` owners retain additive analysis/planning v3 for question-mode writing requests. At most eight relevant original passages and 8,000 original-text units are supplied from the full eligible scoped inventory, alongside the existing coverage disclosure. Nearby text is bounded to 3,000 units before and after, using up to four adjacent text blocks on each side; selected prose is at most 8,000 units, and purpose at most 10,000. Existing context/output and corpus bounds still apply. Oversized requests retain the draft and explain narrowing/shortening. This is relevant selection, not whole-collection analysis.
- `main/ai/content-service.ts` appends frozen writing-format instructions consistently at request sizing, dispatch and reconciliation. Text/research templates, selected own-account connections, durable attempts/results and direct execution remain unchanged. No API key, proxy, paid fallback, provider migration or reactivated proofreading/authoring route is introduced.
- `WritingPreview.tsx` presents completed retained answers as editable plain text. No streaming/failed/partial response becomes an insertion action. Original conversation text stays unchanged. `useConversationDrafts.ts`, shared draft validators, main `ConversationDrafts` and `ConversationDraftRecovery.tsx` retain edited previews with the existing encrypted device-local owner and exact failed-write recovery. Twenty previews per chat, at most 128,000 units each, share the existing 500,000-unit aggregate and chat/scope limits; no old preview is evicted. Recovery shows each preview for manual copying, and individual edits can be explicitly discarded. Larger responses can be shortened locally to the 32,000-unit insertion bound.
- `useWritingAssistance.ts` holds only session-local targets keyed by project/workspace and producing attempt. `editor/writing-assistance.ts` reuses selection capture, the real editor, schema validation and history. The target includes exact editor identity, immutable document snapshot, protected chapter revision and bookmark. Cursor movement does not redirect it. Changed text/revision, another chapter, a replaced editor or read-only/transition/composition/mutation locks refuse insertion. Use current cursor or selection captures a new explicit target without contacting AI. No persisted record authorizes insertion after restart. The target map is bounded to 64 ephemeral entries; an unavailable target requires explicit selection, without losing output.
- Insert here / Replace selection constructs a plain text paragraph slice, assigns stable unique block IDs, validates the complete candidate document before dispatch and uses one isolated editor Undo group. Normal manuscript dirty/protection/Save owners receive the editor update; no worker body writer, separate editor or automatic selected-file Save is added. A successfully used target cannot silently insert twice; another insertion requires explicit retargeting. Undo keeps both the original answer and edited preview.

## Citation and structural boundaries

Generated Markdown, URLs, citation-looking strings and object-shaped text remain literal plain text. This stage does not mint citation nodes, bibliography entries or verification claims. Existing citation/footnote nodes outside the replacement retain their original project identities. A replacement containing citations, footnotes, images or other embedded objects is refused; users can narrow the selection and use the existing citation workflow. Cross-block replacement supports ordinary top-level paragraphs/headings; nested list/table replacements stay inside one text block to preserve their structure. These are deliberate product limits, not automatic lossy conversions.
