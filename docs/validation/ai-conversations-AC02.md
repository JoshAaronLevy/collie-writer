That local error is emitted only after the parser accepts `response.completed`, completed status and the output array, but extracts no non-whitespace text from that array. The old reader checked only the repeated terminal output and ignored already-received text for this decision. The exact terminal body was not logged; the evidence does not distinguish an empty array from otherwise accepted output with no answer text. `responseType: missing` refers only to the absent Content-Type header.

The correction retains this request's already-validated, bounded streamed text when the explicit completed event contains no answer characters. A terminal answer that is present must still match streamed text exactly, and whitespace-only output still fails. Completed status, supported output structure, null/absent error and incomplete details, nonempty final text and existing limits are required. EOF, `[DONE]`, individual text chunks, Stop, failed/incomplete events and interrupted connections cannot establish success. The [official streaming reference](https://developers.openai.com/api/reference/resources/responses/streaming-events) distinguishes text deltas from the response-completed event; the missing terminal text is evidence from this user report, not a claim that the reference guarantees its omission.
