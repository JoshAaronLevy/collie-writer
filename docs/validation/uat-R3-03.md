## Implementation and ownership

- `src/shared/chat-media.ts` defines exact bounded media request/result validators, formats and filename classification. `conversations.ts` includes these in the existing conversation command/worker/result admission. A request identifies the owned project/workspace, immutable message/revision and a media index; it never supplies a URL or filesystem path for main to fetch.
- `src/worker/projects/chat-media.ts` reads native canonical messages or exact accepted imported originals using `OriginalTranscriptText`, graph manifests and `readImportBlob`. CommonMark/GFM parsing produces image/direct-media references with canonical positions. Reference-style Markdown is resolved from its definitions. Read-time attachments use the accepted record's original JSON locator, not a search for similarly named objects. Internal imported records remain denied. Original hashes, selected graph files and immutable message revisions are checked through existing owners.
- Local bytes can be canonical base64 data URLs, explicit `image_url`/typed URL parts or `input_audio` base64 parts in a retained message's `content.parts`, or an exact unique filename selected alongside the export in the same accepted import graph. Encoded filenames are decoded once; directory paths, absolute paths, ambiguous duplicates, missing originals and provider-only pointers are refused. Non-text parts without usable bytes/URLs retain an unavailable label. This is not a general decoder for every provider attachment format or archive.
- `src/main/imports/selected-file.ts` now permits the listed binary media extensions alongside the existing text/JSON/bibliography inputs. Binary selection retains the same native picker, regular-file checks, size/hash evidence and original-blob staging; UTF-8 validation still applies to text inputs. `import-readers/graph.ts` records media as retained coverage with no extracted records, so media is not misclassified as corrupt UTF-8 or sent for structure discovery. Only explicit Import Accept creates chat content; displaying an existing message creates nothing. Binary media is not semantically interpreted; the existing optional-instructions admission can refuse a mixed selection it cannot fully interpret.
- `src/main/chat-media-fetch.ts` accepts only worker-resolved HTTPS references, port 443, no URL credentials, at most three redirects and a 20-second deadline including DNS waiting. Every hop resolves and checks all addresses, then pins the selected public address into the actual TLS request. Loopback, private, link-local, reserved/multicast and non-global/transition IPv6 ranges are excluded. Requests use Node HTTPS without an Electron/account session, cookies, authorization, referrer, message text or manuscript context. MIME and signature checks refuse HTML, SVG, playlists, hosted players and mismatched bytes. Per-item bytes are capped at 32 MiB; compressed HTTP bodies are refused.
- `SourceAssets` retains inspection grants separately from temporary media buffers. Opening the PDF/text inspector clears its previous inspection grant without revoking chat media. Media grants use opaque local URLs, support GET/HEAD and single byte ranges for native seeking, and enforce a three-load limit, 128 grants and 128 MiB of retained display buffers. There is no disk cache or automatic portable-project retention of remote downloads. Main intercepts worker media-source results and returns only the scoped asset URL to renderer. Renderer unmounts release grants; project changes, window closure, renderer loss/reload and unavailable storage revoke grants and abort downloads. A generation check prevents late reads from republishing old grants.
- `security.ts` permits images and media only through the existing `collie-source:` scheme, with streaming enabled in `index.ts`. Remote renderer networking, iframes, HTML execution and generic file access remain denied. Existing request allowlisting and external-link opening are reused. Implementation was informed by the official [Electron protocol documentation](https://www.electronjs.org/docs/latest/api/protocol) and [Node HTTPS request documentation](https://nodejs.org/api/https.html#httpsrequesturl-options-callback); native playback remains unverified.
- `ChatMedia.tsx`, `useChatMedia.ts`, `ChatMarkdown.tsx` and the existing message callers share one inline rendering path. Images load automatically; audio/video use native controls, metadata preload and no autoplay. Direct link labels stay clickable through the existing external opener; PDFs and hosted players remain ordinary links. The mounted timeline shares at most three read/download requests, cancels publication after scope/revision changes and releases late assets. Media context updates do not rerun the Markdown parser. Generated media/status labels confer no quote provenance. Native assistant media resolves after the completed message is retained; streaming text keeps the existing renderer. Scoped CSS contains images/players and provides loading/failure space.
- `ConversationPanel.tsx` extends its existing reading anchor with the visible text/media element inside a long message. Its existing resize observer handles media settling, preserves upward reading and continues latest-message following. No second navigation, draft, source, account, AI or persistence owner was introduced.

## Formats and compatibility

| Content        | Supported projection                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Images         | PNG, JPEG, GIF and WebP; Markdown images, direct image-file links and supported original parts                                                         |
| Audio          | MP3, WAV, Ogg audio, MP4 audio; WebM audio in explicitly typed original parts/data URLs                                                                |
| Video          | MP4, WebM and Ogg video; native controls, browser-supported codecs required                                                                            |
| Retained files | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.mp3`, `.wav`, `.oga`, `.m4a`, `.mp4`, `.webm`, `.ogv`; exact filename in the same selected accepted import |
| Ordinary links | PDFs, hosted players/webpages, unsupported file-link formats; no webpage scraping or embedded frames                                                   |

Up to 32 media references are projected per message; further references receive an unavailable notice. An import file remains limited to 25 MiB and a batch to 100 MiB by the existing intake contract. Public media fetches are limited to 32 MiB each. Unsupported codecs, incorrect server MIME, inaccessible/authenticated URLs, missing original bytes and size/capacity limits produce a short fallback; surrounding text and ordinary link labels remain. SVG, arbitrary local paths, nested export folders/ZIP attachment lookup and provider-authenticated asset recovery are unsupported. Remote-only media is temporary and requires a usable network on reopening; retained bytes work independently of their original disk location.

No persisted relationships or schema migration were added: SQL/minimum reader remains **38**. Binary originals use the already admitted generic managed-original format, existing import-file metadata and graph coverage. Message-to-media relationships are derived from immutable text/locators and selected original filenames. Existing manifest admission, retained copies, rekey, Save/Open, Backup/Restore and retention preserve the original bytes/identities without a new table or frozen-body rewrite. Their runtime portability remains pending user observation.

`mdast-util-from-markdown` 2.1.0 and `mdast-util-gfm` 3.1.0 are now explicit pinned production dependencies; `@types/mdast` 4.0.4 is an explicit development dependency. All were already locked and their verbatim licenses inventoried by R3-02; these declarations add no package versions or license files. Install commands used `--ignore-scripts --no-audit --no-fund`. Existing citeproc attribution and license originals remain.
