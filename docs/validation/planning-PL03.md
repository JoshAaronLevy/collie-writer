## Collection and owners

- `features/planning/PlanWorkspace.tsx` receives native file drops in the existing Import owner. The root captures file drops even over chapters, so a drop cannot become a chapter assignment. Internal card dragging retains its existing meaning. Plain paste outside editable fields and Paste as note route through existing Notes/Sources navigation intents. URLs use the existing safe-link check, prefill the source form and perform no page fetch. Prose creates an ordinary note; no manuscript insertion occurs. The paste form uses the existing retained Plan draft owner and restores its text if navigation is refused.
- `features/imports/useImportSelection.ts`, `ImportProvider.tsx` and `importContext.ts` reuse the retained selection, staging, recovery, explicit Submit and Accept flow. File-picking and drop intake share one selection function. Existing settings are protected before extending an unfinished selection; blocked work requires finishing/reconciling it and adding files again. After confirmed Accept, the existing result notice appears and visible Plan resets its pool filters/page to Unplaced. Import already commits with no chapter origin/link, and this stage adds none. Findings do not become library records before Accept.
- `shared/project-import.ts`, `preload/project-import.ts` and `main/imports/ipc.ts` add a narrow native-File drop bridge. Preload derives disk paths with Electron `webUtils.getPathForFile`; it exposes no path-returning API. Main validates the exact trusted-frame payload, scope, bounded absolute paths and current authorization, then calls the same `ImportService.pickFiles` staging authority as the native picker. Existing extension, byte/hash, symlink, duplicate, operation/recovery and batch limits remain. This follows the [official Electron preload guidance](https://www.electronjs.org/docs/latest/api/web-utils); native behavior awaits user testing.
- `app/navigation.ts`, `WorkspaceViews.tsx`, `NotesPanel.tsx` and `useSources.ts` carry one-time creation intents to the retained content editors. Already-consumed intents do not repeat on Back. URL source drafts remain editable/unverified and require the normal source save. `textNoteBody` creates ordinary editor paragraphs; it introduces no second content store/editor. `SourceInspector.tsx` adds Use excerpt. It opens the existing excerpt in Plan; the user chooses its destination with the existing assignment action.
- `shared/planning.ts` and `worker/projects/planning.ts` add an exact optional material target to the bounded read. Plan can select a specific excerpt/passage note even when its normal pool filters/page would hide it. This temporary focus does not rewrite saved pool filters; Show all material returns to them. Exact worker association validation still authorizes assignments. No citation, research decision or verification state is created by Use excerpt.

## Passage identity, authorship and recovery

`shared/note-passage.ts` defines a distinct version-1 origin: retained conversation/revision, imported/native segment, message/revision/sequence, UTF-16 start/end and exact canonical quote. Stored origins add the capture-time chat title, original role and native attempt identity. The 20,000-unit selection limit bounds each quote. Frozen whole-message imported AI-context references and recall limits are unchanged.

`chat-selection.ts` reuses Markdown source-offset mapping for exact selection, with the earlier Save reference API retaining its 2,000-unit contract. Generated badges/media confer no provenance; transformed tokens require complete unambiguous mappings and surrogate splits are refused. `ChatMessage.tsx`, native conversation/answer presentation and `ImportedMessageLinks.tsx` offer Keep passage for eligible selected text. Completed assistant text and visible imported messages keep their stored roles. Captured notes have `origin: chat-passage-v1`, so they are not labeled human-authored merely because the user kept them. Native/imported authorship is visible in Notes; chat text does not become verified source evidence.

`usePassageCapture.ts` is one retained write owner for all message bubbles. Keep passage is the disclosed save action, without a new review dialog. It submits `changeNote/capturePassage` with a stable operation/note ID and retains an uncertain request for explicit retry. Successful capture offers Open note/Open in Plan. Known validation/stale/not-found refusals release that refused intent and ask for a current selection. The existing draft registry protects unresolved writes across ordinary navigation and blocks close/project replacement until settled; it is not a new durable renderer journal. Reopening/Save/copy never dispatches AI or a new capture automatically.

`worker/projects/repository.ts`, `notes.ts` and `note-passages.ts` use the existing serialized project and note transaction owners. A recorded operation is reconciled before resolving text again; digest conflicts are refused. A new capture validates conversation/message revisions, ownership, sequence, visibility, boundaries and exact text before atomically creating the ordinary note, immutable origin, commit and ordinary receipt. Imported text is read through `OriginalTranscriptText` from hash-checked retained files, independently of the bounded AI recall window. Native assistant captures require a completed response. Normal note edits/revisions, labels, trash/archive and chapter links keep the immutable origin.

Notes exposes the unchanged quote separately from editable prose and Open original exchange. The conversation owner resolves the exact retained message, refuses changed native text/revisions and reveals its original exchange. The transcript presentation waits for required imported text slices, then positions the saved range in the correct message; generated/non-direct Markdown tokens use their mapped span. Existing Save reference, original readers, media and conversation drafts retain their owners.

## Migration and portability

SQL/minimum reader **41** adds only `note_passages`, keyed by project/note. It stores the versioned origin, not a second transcript, attachment store or import receipt. `chat-passage-v1` notes require that origin. Schema-40 DDL is frozen as `projectTablesV40`; retained-copy 40→41 migration adds an empty table after validating existing Plan metadata. Older note/portable readers do not query the new table before migration. PL01/PL02 history bodies and earlier imported context/result readers remain unchanged.

`storage/schema.ts`, `migrations.ts`, `manifest.ts`, `portable-db.ts`, `archive.ts`, `snapshot.ts`, `incoming.ts` and repository opening carry the new meaning through admission, Save, Backup/Restore and independent copies. Structural admission checks exact origin shape, ownership, note/conversation/message references, role, revisions and ranges. Imported quotes are resolved against managed originals during archive admission, active opening and snapshot capture; migration candidates validate their origins before publication. The original transcript reader keeps one decoded file/message cache per read rather than mounting transcripts on board cards. Independent copy remaps the new table’s outer project ID; embedded origins contain stable content identities without project/workspace authority. Existing retention hashing already includes all admitted tables. No original, note history or recovery data is removed as cache.

History restoration still restores structure/associations, not Research bodies. Passage origins remain with their notes across outline restore; no competing association history or passage-specific Undo framework is added.
