# RF07 — One straightforward export flow

October 11, 2026. **Implementation complete — awaiting user testing.** The complete refactor report and live export/native/worker/result callers were reviewed. This stage implements **S07**; RF08's citation-preview work remains separate. Earlier stage progression does not establish acceptance.

## Changes and source evidence

- The former DocxExportPanel is replaced by [ExportPanel](../../src/renderer/src/features/projects/ExportPanel.tsx). Options → **Export…** → result replaces the numbered options/review/results workflow. Default selection follows the full active outline; optional sections/custom order, page/title/properties and saved recipes remain deliberate tasks. The separate acknowledgment checkbox, captured-revision dashboard, explicit protection/preview steps and duplicate start functions/state/styles are removed.
- Export performs the existing draft protection and compiler preflight internally. Broken references/assets/content and compilation losses still block output. Incomplete source details alone show a bounded AppDialog with Cancel, Review sources or **Export with omissions…**, bound to the exact head/options. A changed capture cannot authorize a later export. Picker cancellation keeps options; unknown starts instruct destination inspection before retrying. No retry starts automatically.
- Ordinary `startCompilation` now carries the generation-bound single-DOCX replacement confirmation. All new jobs use one worker start/render path and one guarded publication writer. The old `startDocx` bridge/channel, worker command/repository method and duplicate DOCX start/render implementation are removed. Status/cancel and exact older report readers remain, including jobs without `files`; no historical report/manifest is rewritten to impersonate a new job.
- DOCX replacement retains previous bytes beside the output, rechecks the selected fingerprint, validates staged/published DOCX and output bytes, and reports the retained prior location. Rollback only restores an actually moved prior file into an absent destination using a no-overwrite link. A concurrent destination is preserved. Other formats and batch collisions keep their existing no-replacement behavior; completed files, candidates, sidecars, partial/uncertain outcomes and local reports remain retained. Cancellation does not interrupt publication.
- Results use readable states and per-file outcomes/losses, **Show file** and **Done**. Main resolves Show file only from the exact scoped retained job and completed format, never a renderer-supplied path/URL; it rechecks sender and file presence/safety. The existing session job/polling owner outlives navigation and project changes. Typed result links still focus the matching job; a scope-keyed panel keeps options/captures from crossing workspace copies. Older results remain reachable, and Done returns to Write without resending or deleting reports.
- Existing recipe persistence/revision checks and exact unknown-operation retries remain; free users can read/export every format and load existing recipes one format at a time, while recipe mutations and batches keep main's paid capability checks. Optional properties, citation assets/numbering, immutable compilation, PDF adapter and format-specific losses remain production-owned. Citation style/preview is unchanged pending RF08.
