# Stage 11 source and interchange decisions

The source library is local to each project. A canonical source has a stable UUID, a structured CSL subset, human verification flag, provenance, retained raw import, unknown-field names, revision history and a reversible state. A separate attachment identity points to a managed, immutable SHA-256 blob. One source can link to many sections; the same blob bytes can be represented by different attachment identities. Neither DOI nor URL entry opens a network resolver.

Supported canonical work types are `article-journal`, `book`, `chapter`, `report`, `thesis` and `webpage`. The deliberately shared bibliography field subset is title, creators (family/given or literal), issued year/month/day, container title, publisher, edition, volume, issue, pages, DOI, URL, ISBN and ISSN. DOI is lowercased with an optional `doi:` or doi.org prefix removed; HTTP(S) URLs are parsed and normalized without fetching; ISBN whitespace and dashes are removed. Unsupported work types and invalid required fields become per-record import errors. Canonical metadata is stored as a validated structured JSON object in `sources`; relationships, aliases, attachments and reports are separate SQLite tables. This keeps the source identity independent of a file or section identity.

Pinned local interchange packages are `@citation-js/core`, `@citation-js/plugin-bibtex` and `@citation-js/plugin-ris` 0.9.0. The three direct packages declare MIT and their licenses are bundled. Transitive date/name packages declare MIT; `moo` is BSD-3-Clause; `sync-fetch-undici` and `whatwg-mimetype` declare MIT. Their notices are in `resources/licenses/dependencies/`. Citation.js input is forced to local `@bibtex/text` or `@ris/file`; CSL JSON is parsed locally. The code imports no DOI, Wikidata or other resolver plugin. The core package contains an unused fetch dependency, so the supported path must never pass DOI or URL strings to automatic type detection. See the [Citation.js core API](https://citation.js.org/api/0.7/module-@citation-js_core.html), [BibTeX plugin](https://citation.js.org/api/0.7/module-@citation-js_plugin-bibtex.html) and [RIS plugin](https://citation.js.org/api/0.7/module-@citation-js_plugin-ris.html).

All three Citation.js packages stay external at the Electron worker boundary so plugin registration shares one core instance.

| ---------------------------------------------- | --------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------- |

| Container/publisher/edition/volume/issue/pages | CSL names                               | `journal`/`booktitle`, `publisher`, `edition`, `volume`, `number`, `pages` | `JO`/`JF`/`BT`, `PB`, `ET`, `VL`, `IS`, `SP`/`EP`   |

This table is the application's intended subset; dialect-specific behavior remains user acceptance work. BibTeX macros spanning separate entries are not expanded by the per-record preview splitter. RIS old/new variants supported by the pinned plugin are attempted, but arbitrary vendor tags are not canonicalized. Imports up to 8 MiB and 2,000 records receive a preview under a one-hour, project-scoped file grant. Each row has either normalized fields or an error, possible exact DOI/ISBN/URL/imported-ID matches and similar title/first-creator matches, and omitted field names. The preview does not mutate storage. A commit re-reads and hashes the selected file, requires one action for every row, and inserts all accepted rows plus the report in one transaction. Candidate matches default to Skip; Create separate, Merge into target and Link imported ID to target are explicit. Link does not replace target metadata; merge only fills target fields that are empty. Imported original records, including skipped/invalid rows, and unknown field names remain in project data. Export reports omit project-only provenance, verification, links, attachments, raw records and revision history, plus each unknown field. No universal bibliography round trip is asserted.

Merging existing project sources tombstones the losing source and retains its old UUID as an alias, reassigns its section links and attachment relations to the target in the same transaction, and keeps old revisions. Existing manuscript/history references can still resolve through that alias. Trashing a source does not remove citations or managed bytes. Physical blob deletion is not offered in this stage: source history, other attachment identities and backups may still refer to the same hash. File export uses a new filename only; no existing bibliography or attachment file is replaced.

Attachment picker permits PDF, PNG, JPEG and UTF-8 text. A selected file is checked for regular-file identity, type signature, size (up to 1 GiB for PDF/images and 8 MiB for text), available space and checksum while copying. The original stays outside the project and is never changed. The progress counter reports copied bytes. To reopen after restoring a project backup, use **Save copy** on the managed attachment and open the resulting local file. PDF inspection, text extraction and source-version reimport remain Stage 12.
