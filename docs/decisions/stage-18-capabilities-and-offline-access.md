# Stage 18 — Capabilities and offline access

October 1, 2026. Implementation complete — awaiting user testing. The approved capability matrix is unchanged. There is no trial, automatic conversion, advertising, watermark, account requirement for opening content, checkout, or AI eligibility code.

The main process classifies every project command before dispatch to the storage worker. Free mode permits editing one explicitly designated project; stored-project count is unrestricted. Opening, creating, duplicating or restoring a project does not silently designate it. Read/inspection/search, individual manuscript and bibliography exports, source attachment copies, saved recipe loading, Save/Backup and recovery remain available for all projects. Inspection extraction is allowed as a reading aid; manual excerpts and changing the active source version require editing rights. Creating/editing recipes and batches of two or more formats require paid access. Existing recipes can be used one format at a time in free mode. Paid subscription, grace and lifetime states have identical edition capabilities and no project-count ceiling.

Designation is local and scoped to both project and workspace IDs. The renderer first protects pending input; main rejects an unsettled designation change and binds the change to the settings revision. Ordinary content updates remain in the existing worker transactions. A separate sample-project slot is reserved in the device-local policy; Stage 19 owns creating/resetting the labeled product tutorial. Imported projects cannot declare themselves samples. No tutorial or testing-only UI is introduced here.

When paid editing ends for the active project, the main process retains a bounded buffer-drain permission for that previously authorized project. It accepts one frozen operation in each existing manuscript, section-metadata, note, annotation and source-draft slot, with identical operation/digest retries. It grants no new outline/import/recipe work or other project access. Already dispatched worker commands continue. The renderer freezes editing and offers protection plus acknowledgment; acknowledgment removes the drain permission. Failed protection keeps the buffer visible and the transition open. Selecting the *same transitioning project* for free editing is also permitted while its buffer is dirty: this preserves that editor's authority without a project switch and allows manual repair. Unsubmitted research decisions, questions/claims and transcriptions block switching/finishing until the user saves or clears them; the user can retain that project for free editing to do so. Reading/exporting committed work is never revoked by a grant.

Signed documents use the [grant and local-storage contract](../formats/access-v1.md). Node's established `crypto.verify` with Ed25519 verifies the signature; canonical serialization is the fixed flat ASCII/safe-integer subset of [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785). Ed25519 uses a null algorithm parameter in [Node's crypto API](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoverifyalgorithm-data-key-signature-callback). No new dependency or private key is added. The application keyring is deliberately empty: no actual issuer verification public key was supplied. Stage 20 must provision authentic issuer public keys, keep old verification keys during rotation, and provide a real issuance/restore route. No synthetic grants, keys, private-key tooling or paid-mode toggles are included. The production signed-document importer becomes available only when that trusted keyring is configured; the renderer never supplies key material or raw grants.

Verified lifetime access is edition-scoped without an app-version ceiling or expiry. Subscription access uses the signed paid-through date and signed grace date, with at most 14 days of grace. Grace means renewal is not locally confirmed, not refunded. Time never decreases within the running process and a highest-observed timestamp is checkpointed with the local grant cache. A rollback raises a visible warning and cannot extend subscription time beyond that high-water mark; essential access and free designation remain available. A device that stays offline cannot receive a refund, and local file/profile rollback or deletion cannot be prevented by an offline application alone. Reconciliation with authentic issuer state belongs to Stage 20. No claim of tamper-proof offline DRM is made.

Only authenticated issuer revisions replace a purchase record; an older revision or conflicting equal revision is rejected, including after a cached revocation. Unknown/network failure does not synthesize revocation. Invalid imports leave the prior cache intact. An unreadable cache is preserved and blocks cache replacement pending support/authoritative reconciliation; a separately readable free designation continues to work. An uncertain write of an authentic newer decision also makes paid access unavailable for that session, retaining buffers and files for recovery instead of continuing potentially superseded rights. Access storage is outside every project snapshot and outside local workspace reset. All native, replay, transition, clock, persistence and paid-state outcomes remain unverified. The [value-session guide](../research/stage-18-value-sessions.md) records the still-pending Stage 20 commercial gate.
