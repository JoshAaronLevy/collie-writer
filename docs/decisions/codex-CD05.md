## Main-owned availability and review identity

`codex-local-policy.ts` now derives conversation availability from session/catalog state, actual runtime account/workspace identity, pending protection, active work, journal capacity and the enforced execution policy. It explains Connect, Resume, refresh/select a model, pending account work, output protection, capacity and isolation separately. The availability union can describe a selected connection/model as available, but **the current `localExecutionReadiness()` always returns both real CD03 blockers**. No renderer, stored preference or configuration flag can change it. Proofreading remains unavailable pending CD06 and its prerequisites.

The same decision is consulted in main authorization alongside the existing project rights, close, versioned identity and session guards. An already reserved content intent is not mistaken for a competing command or its own running slot. Secure storage/runtime failures retain their own reasons. Main content work updates the shared connection snapshot; waiting for a local write or a response does not falsely sign the account out. The global status is advisory about the connection: project edit rights and exact operation authority are still checked at dispatch.

`AiStatus.reviewRevision` is an opaque, transient hash of main's existing conversation review stamp. It changes with account, catalog, model, route-generation and lifecycle invalidation, independently of status `sequence`. It carries no credential, profile, provider workspace or runtime handle and cannot authorize a send. Main/preload use the same exact response validator; available feature snapshots must match the active signed-in connection, selected model and execution state. No IPC command or portable field is added.

The renderer captures the connection/model/review revision before asynchronous review and compares it on completion and submission. A changed revision clears only unsubmitted review approval; the prompt, source and explicit history selection stay retained. A previously submitted uncertain request remains the original exact pending object. A stale or expired main review asks for a new review without losing the draft. Status reads alone do not invalidate a stable review or contact Codex.

## Conversation experience

The normal conversation panel reuses `AiModelSelection` and `AiConnectionsProvider`. It no longer owns an `AiModel[]` list, local model picker or `aiModels` lookup. Settings and the conversation panel show the same explicit catalog/selection. Connect opens the existing account settings; Resume, model actions, connection-state protection and status reads use the existing shared owner and focus rules. Funding copy describes accepted normal subscription/credit behavior. A listed model never implies account eligibility or completed isolation.

Send uses the main conversation capability plus editable/active project, local pending work, exact review and lifecycle conditions. Local review/save and offline history remain usable without an account. No-context and follow-up defaults are unchanged: no writing and no prior messages until explicitly selected. Selected messages retain transcript order, including selections across pages. Each future dispatched operation uses the existing fresh runtime thread; nothing silently imports account history.

Selected writing comes from the protected saved revision. Capture now also guards editor identity/destruction/composition and the active document after the flush. Review enforces prompt/context limits plus the exact existing v2 serialized frame and both frozen instruction strings: **16,000 / 64,000 / 80,000 UTF-16 units**, respectively. JSON escaping, source IDs, revisions, labels and selected history count. Oversized review refuses before storing dispatch approval and asks for less input; no trimming, batching or extra inference is introduced. Frozen v2 instructions, frame key order and digests are unchanged.

The composer retains explicit review, local Save, Send and Stop. A repeated click cannot replace the pending request or allocate another submitted attempt. Unknown acknowledgments retry the same exact request. Use prompt in a new request copies only the prompt; context/history and authorization must be selected/reviewed again. Local protection recovery never resends. Project-head refresh remains manuscript-preserving.

Stored user messages, actual assistant text, attempt outcomes and local saving remain separate. Local Save copy distinguishes the working project from its chosen `.collie` file. Refused sending does not promise a response. Model/auth/quota/unknown/storage explanations tell the user which explicit action can help, without switching models, accounts or providers. Protected snapshots, partial output, cancellation, local reconciliation, archive/read-only behavior and native transcript export continue through the existing CD04/I12 owners. No reasoning or tool events are added to the transcript.
