# Stage 19 — Onboarding, accessibility and privacy

October 1, 2026. Local implementation complete — awaiting user testing. Stage 19 uses the existing project, file, source, evidence, citation and export flows. It does not introduce a second content store or a service connection.

The tutorial is an ordinary article project created by a trusted main-process command. Its local project/workspace identity is recorded only in the separate access settings sample slot; a renderer or imported project cannot claim the sample allowance. A bundled fictional UTF-8 text source is copied into the sample as a managed original. Its short draft cites that fictional source. The guided actions ask the writer to extract an exact excerpt, form a question, link evidence, revise writing, Save and export. The sample is explicitly labeled fictional and is not represented as a real source. Creating a fresh sample rotates the sample slot to a new project and retains the previous project and any chosen file. The reset action requires a UI acknowledgment; it does not delete a workspace or touch a personal project's identity, destination or content. An interrupted sample setup can be resumed through the same trusted path, with existing edits preserved instead of overwritten.

Data Locations reuses Stage 7 recovery, retained versions and reviewed local reset. Show project file reads the selected-file destination already held by main for the matching active scope. Show local working folder uses the verified root. Neither command accepts an arbitrary renderer path. Save, Save As, Locate, Backup/Restore, recovery inspection and export remain their existing separate operations. Selected file, local recovery, customer cloud synchronization, display preferences and future service metadata are described separately in the UI.

Keyboard paths now include persistent section links, focusable section targets, reading order and non-drag outline controls. Search page changes focus the result summary. The note editor has a distinct screen-reader label. Interface zoom offers 100–200% in addition to native View controls. High contrast and reduced motion have explicit local preferences and respect operating-system preferences. Interactive controls have a minimum target height. Native dialog focus behavior, full editor selection restoration, 200% layouts and VoiceOver/NVDA announcements remain user-observed release gates, not certified outcomes.

The support preview is assembled in main from app/runtime version numbers, platform/architecture, storage state, process uptime and a bounded set of known `ProjectCode` values. It accepts no title, text, path, URL, content hash, exception message, arbitrary metadata or attachment. A user must request and copy the preview; there is no upload endpoint. Visual preferences are stored in the Chromium app profile only and carry no project data.

The packaged request policy remains deny-by-default for off-app network traffic. Crash reporter upload, content analytics, merchant calls and automatic updates are not initialized in this build. Stage 20/21 must document and user-review any new purchase/update endpoints and their non-content payloads. The current [privacy and file inventory](../privacy/stage-19-file-and-network-inventory.md) and [accessibility matrix](../accessibility/stage-19-matrix.md) record source-backed boundaries and pending user observations. No ad, affiliate, sponsored placement, promotional upsell slot, tracking SDK or advertising endpoint was added.
