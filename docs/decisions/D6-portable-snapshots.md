# D6 — Portable snapshots

September 29, 2026. **Implementation selected; format freeze, native acceptance and performance proof remain pending.** Stage 5 is an internal service checkpoint. Native Save/Open and cancellation controls belong to Stage 6; no temporary testing UI or command was added.

## Selected implementation

Use `yazl` **3.3.1** for streaming ZIP64 writing, `yauzl` **3.4.0** for lazy reading, and `saxes` **6.0.0** for bounded offline XML parsing. Types are pinned to `@types/yazl` **3.3.1** and `@types/yauzl` **3.4.0**. Retain the existing SQLite utility process and packaging pipeline. Exact package manifests, APIs and notices were inspected; no dependency audit or executable compatibility check was run.

[yazl](https://github.com/thejoshwolfe/yazl) supports lazy read streams and ZIP64. Stage 5's original writer stored every entry. The October 5 PS08 [writer policy and budget addendum](../formats/archive-compression-v1.md) supersedes that choice for newly created database and small manifest/pinned citation text entries with streamed deflate level 6. Managed blobs remain stored; fixed regular-file permissions and ZIP64 remain. New admission uses conservative worst-case deflate bounds plus full expanded validation, with compression/error stream ownership held through closure. Actual CPU/memory/time costs remain unmeasured. [yauzl](https://github.com/thejoshwolfe/yauzl) supports lazy enumeration and streamed declared-size enforcement; it does not check file CRCs, so the adapter checks CRC32 as well as SHA-256. Neither checksum authenticates a publisher.

The reader accepts only the exact manifest/database/hash-addressed blob/citation paths. It rejects directories, links, executable modes, encryption, comments, unsupported compression/extra fields, path aliases, duplicate entries and case collisions. Entry counts, actual streamed bytes, per-file sizes and total expansion are bounded. Extraction begins in a new private staging directory. Exact app-owned SQL, foreign keys, integrity, row contracts, document ownership, commit lineage and operation receipts are validated before promotion; imported triggers or migration SQL are never executed. User-authored text can naturally contain paths or private text; exclusion concerns device-local metadata and stores, not destructive filtering of manuscripts.

The [format contract](../formats/collie-v1.md) defines the current manifest and resource limits. Both pinned styles, en-US and their attribution notices travel as a fixed supported citation profile. Hashes must match the supported profile before bounded XML parsing; DOCTYPE, custom entities and processing instructions are refused. [saxes](https://github.com/lddubeau/saxes) has no external-entity fetch behavior. Arbitrary third-party styles are outside scope. Future changes must retain explicit supported profiles rather than silently adopting new installed assets.

## Capture and retention

The repository serializes mutations, opening and capture. A job persists provisional retention before backup. SQLite's online backup captures a coherent database; the actual head and complete registered asset set come from that copy. Exact leases are persisted before releasing the mutation/GC boundary. Later edits can commit while blob hashing, archive creation and archive inspection stream. The copied database is closed in DELETE journal mode and the archive has no WAL dependency. [SQLite backup](https://www.sqlite.org/backup.html) remains the coherent-copy mechanism; copying the live main DB file is prohibited.

Working schema 2 adds project-owned managed assets through a real 1→2 copy migration. Original schema-1 databases and verified pre-migration backups remain. The schema-2 validator retains every registered asset, including currently unused assets; no garbage collector or asset deletion was introduced. Stage 9 must keep assets referenced by retained history registered and extend validation when history records ship. No nonexistent history snapshot is claimed.

There is one active snapshot per workspace and up to eight pending lineage groups. Pending requests with the same parent snapshot coalesce; all requested minimum heads must be ancestors of the copied head. Reusing an operation ID with different input fails. The journal records queued/running/cancelling/cancelled/failed/interrupted/completed states, captured head, phase, byte progress, operation digests and leases. Progress counts work across phases, not a misleading overall percentage. Project switching is refused while a snapshot is active; writing in the same project remains available after capture. Stage 6 must present this constraint through its normal save UI.

Completed `candidate.collie` files remain until a trusted destination service explicitly reports verified replacement and durable acknowledgment. They are not “Saved” merely because they exist. Cancellation cleans only known disposable files belonging to that job; it preserves a complete candidate. Restart marks unfinished journals interrupted without replay and retains their leases/candidates. Corrupt journals conservatively pin all blobs and remain on disk while existing writing stays accessible. Cleanup of interrupted or ambiguous candidates needs Stage 7 recovery inspection; no automatic expiration is introduced.

## Pending budgets and limitations

Targets remain ≤15/60/120 seconds for 1/5/10 GiB and ≤256 MiB additional streaming-save memory on the plan's baseline machines. **No machine, sample, timing distribution, peak memory, disk amplification, cancellation responsiveness or failure result is recorded.** No archive or dataset was generated. The format cannot be considered performance-accepted until the user supplies evidence through the real Stage 6/8/11 paths.

Capture preflights two database copies plus 64 MiB margin. Archive creation preflights the archive and a full validation extraction, metadata and margin in addition to existing files. Earlier candidates, migration backups and chosen-destination staging consume additional space. Free-space estimates do not reserve storage; actual write failures still fail the job and preserve previous work. Expect extra sequential hashing/read/write passes; record costs before adjusting the strategy. Synchronous SQLite integrity/row validation is not immediately cancellable, and directory durability on Windows remains unproven. No measured disk multiplier or cloud-upload SLA is promised.

Current portable SQL supports the single Draft and asset inventory, not later source/history/multi-section schemas. Asset ingestion is a trusted streaming primitive; UI selection, media-specific parsing and registration commands belong to Stages 8/11/12. Native Save/Open grants, destination-generation checks, transfer/replacement, lineage mapping and conflict UI remain Stage 6. Its consumers may use this implementation checkpoint, but acceptance of large saves and cross-machine restoration must remain pending.
