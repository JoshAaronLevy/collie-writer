# D3 — Editor schema and shared compilation

September 29, 2026. **Implementation selected; fidelity and native acceptance await user testing.** No editor was launched or export generated by the assistant.

Use community `@tiptap/core` and `@tiptap/pm` **3.31.3**, with application-owned nodes and ProseMirror history/keymaps. Use `docx` **9.8.1** for native OOXML. Exact transitive versions are in `package-lock.json`. These packages' actual artifacts were read before adoption; their license notices ship in `resources/licenses/`. No paid extensions, cloud converter, React editor wrapper or second build pipeline is required. [Tiptap node API](https://tiptap.dev/docs/editor/extensions/custom-extensions/create-new/node), [docx native footnote API](https://docx.js.org/api/classes/index.FootnoteReferenceRun.html).

The canonical contract is `DocumentPayload = { schemaVersion: 1, ast, footnotesById }` in `src/domain/editor/schema.ts`. It uses plain application types compatible with ProseMirror JSON, not library types. Stage 8 now mounts the editor in the production writing screen with managed images, formatting controls, selection-aware copy and persistence; see the [Stage 8 decision](stage-08-editor-and-assets.md). Stage 15 supplies citation labels and footnote body editing. Do not add a demonstration screen, debug export button or hidden testing command to fill those gaps.

## Frozen schema v1 subset

| Canonical content | DOCX adapter | PDF adapter | Bounds / handling |
| --- | --- | --- | --- |
| Paragraph; heading levels 1–3 | Named paragraph styles / outline levels | `p`, `h1`–`h3` | Unique block ID; inline Unicode text |
| Bold, italic, underline, strike | Native run properties | Escaped semantic tags | Text marks only; no arbitrary CSS |
| HTTP(S) link | Native hyperlink | Escaped hyperlink | No credentials, active scheme or implicit navigation |
| Hard break | Run break | `br` | Plain-text paste preserves line breaks |
| Bullet / ordered list | Native numbering; independent start per list | `ul` / `ol start` | One level in v1; item owns one or more paragraphs. Unsupported nesting is rejected, never flattened silently |
| Block quotation | Indented named style | Indented paragraphs | Paragraph content only in v1 |
| Horizontal / page break | Border / native page break | `hr` / paged break | Separate addressable block |
| Managed PNG/JPEG image | Embedded inline drawing, alt text, caption | Data image, alt text, caption | Separate inline-flow figure block; no floating/text wrapping; proportional downscale within printable area |
| Rectangular table | Native rows/cells; repeating header row; rows may split | `table`, `thead`, `tbody` | Up to 20 columns / 10,000 rows; optional first header row; plain paragraphs/line breaks only; no spans, nested tables, notes or citations in cells |
| Citation cluster atom | Resolved formatted runs or Chicago native note | Same formatted runs or page note | UUID instance; ordered source IDs with per-item locator/label/prefix/suffix |
| Author footnote atom + owned body | Native footnote body / reference | Genuine page footnote | Paragraphs, basic marks, links and citations; no nested notes, tables or images |
| Section title and explicit boundary | Heading / page break | Heading / page break | Compile selection controls inclusion. Status/synopsis remain later document metadata, not manuscript text |
| Bibliography | Editable styled text | Escaped styled text | Derived from selected citation order, never canonical citation-manager fields |

Images are limited to 1–1600 logical pixels on each axis in editor JSON. Export proportionally fits the printable area; managed bytes are limited to 25 MiB each and 256 MiB total per compilation. The latter is a prototype memory budget, not a measured performance result. Source libraries may be much larger; only manuscript images are loaded here. Stage 16 must provide an actionable report for limits before writing destinations.

Validation rejects unknown fields/nodes/marks, bad IDs, duplicate identities, invalid links, missing or orphaned footnote bodies, malformed/nonrectangular tables and unsupported schema versions. Initial budgets are 200,000 AST nodes and 20 million text characters per document; rejection retains the original input. No coercion of unknown persisted content into a paragraph. Future migrations use Stage 4 copy-migration conventions; no persistent data is changed by Stage 3.

`copyDocument()` gives every block/citation/note instance a new identity and copies/remaps its note body, retaining source/asset identities. Moves retain IDs. ProseMirror transactions assign missing IDs and remap duplicate block IDs after a split; history includes those appended transactions. Serialization refuses an active IME composition. Native IME, undo and split anchor behavior remain unobserved. Stage 8 provides app-owned rich slice copy/paste with new block IDs, literal plain-text paste, and explicit refusal of external active HTML and copied external drops. Citation/footnote anchor copies remain refused until their managed UI exists. Native IME, undo and split-anchor behavior remain unobserved by the assistant.

## Compilation boundary

`compileManuscript()` consumes ordered validated section payloads plus an injected citation formatter. It rejects duplicate IDs across selected sections, preserves document/paragraph source IDs, and returns a recursively frozen, editor-independent model tagged with `capturedHead`. It does not claim to capture a database head: Stage 16 must atomically capture the real head and lease immutable blobs before calling it. DOCX and PDF consume this same model; neither writes a selected file or changes project-save status.

Author notes and automatic Chicago prose-citation notes share one sequential counter. Citations already inside an author note keep that note's CSL `noteIndex`; they never create nested notes. All citation updates are collected before final runs are resolved, so later disambiguation can change earlier occurrences. Both formats receive those final runs and the same bibliography.

`exportDocx()` creates native paragraphs, lists, tables, drawings, captions, page fields, author/citation footnotes and bibliography. Letter/A4 use one-inch margins and a 12-point manuscript body. Font files are embedded; the docx public font API embeds regular faces, so bold/italic use native formatting and may be synthesized or substituted by the reader. Actual Word/LibreOffice behavior, mixed-script shaping, reference integrity and page splits are pending, not guaranteed by these APIs.

See [D4](D4-citations-and-licenses.md), [D5](D5-local-pdf-pagination.md), the [license inventory](../licenses/stage-03.md) and [manual guide](../manual-testing/stage-03.md). Stage 8 must preserve this subset or record a coordinated version change; Stages 15–17 cannot treat this implementation decision as fidelity acceptance.

Stage 9 retains this AST unchanged. Between-top-level-block splits partition footnote bodies with their references; merges append whole blocks and preserve IDs. Current anchor projections, explicit repairs and materializable checkpoints are described in the [outline/history decision](stage-09-outline-and-history.md). Citation/footnote conservation remains unverified until the production Stage 15 workflow can be exercised by the user.
