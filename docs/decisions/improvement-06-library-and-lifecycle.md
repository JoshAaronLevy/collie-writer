# I06 — Returning projects and lifecycle surfaces

**October 3 correction:** [Explicit Save and local recovery](save-and-local-recovery.md) now owns Save/close semantics. A changed selected file can be replaced by explicit Save of local work with prior-file retention; normal close needs local protection, not a current selected file.

October 2, 2026. **Implementation complete — awaiting user testing.** This stage reorganizes access to existing local/project-file commands. It does not change their authority, persistence formats, retention, or release gates.

## Returning safely

The renderer stores only the last project, workspace and selected text-section UUIDs in `collie.last-project.v1` in the local app profile. The record has a bounded strict reader and conveys no filesystem path, grant, destination, credential, or portable project data. The first successful trusted project inventory resolves the hint. If setup is resumable, I05 setup wins. An empty healthy library opens project selection; unreadable local project entries or an initial inventory failure open the library with a recovery path. An archived last project opens the Archived library view instead of silently reopening. Missing or locked projects fall back to the library with a reason. An absent/inactive last section falls back to the worker's valid active text section; a failed section open falls back to the library. A valid project opens through normal trusted `openProject`/`openSection` and the existing persistent session `select` path. That path requests file status and triggers the existing selected-file check; no catalog path is accepted as proof of availability. The last-location hint is updated only for a real workspace selection, and a confirmed local reset clears it. If app-profile storage refuses the preference, manual Projects access still works.

Opening local work remains independent of the selected file. If a selected file is missing or changed, the project may still open from protected local storage while the file panel shows an actionable unavailable/conflict state. Reopening the currently selected project from Projects asks the existing status command to recheck its file even when its worker scope has not changed. File checks never overwrite either branch. There is no cloud upload acknowledgment or automatic Locate grant.

## Library and action ownership

The new library has Recent (up to eight currently active projects), All active, and Archived views, plus a local title/type filter. Each normal row shows title, nonfiction type, readable modified date, editable/read-only state, and concise local-versus-selected-file status. It contains no UUID, revision ID, or full path. Each row has a separate labeled Actions menu, outside its Open button. Opening a row uses I03's draft protection and trusted project open; Project actions opens the same identity into the existing details destination. Issues and retained recovery link to Data and recovery instead of disappearing from filtered views.

Project actions keeps the real I04 Project details editor, selected-file Save/Save As/Locate/Inspect, separate Backup and Duplicate, Move, Archive/Unarchive, Restore as a new project, and existing writing import. Current file jobs, file conflicts and interrupted states remain globally actionable; ordinary file controls now live in Project actions with a compact Save/status shortcut in the shell. The library calls attention to unreadable/interrupted entries and reset recovery; routine backups and previous copies remain under Data and recovery without generating a warning on every launch. File and lifecycle presentation use Mantine buttons and semantic component CSS Modules. Existing legacy `.projects` button rules now exclude app-authored Mantine buttons, leaving older native controls in place until their owning later stages.

The underlying contracts remain unchanged: Backup has its separate journal and never acknowledges the selected file; Move uses a fresh filename, switches mapping only after verification and retains the old file; Duplicate and Restore promote independent identities without a destination; Archive is reversible device-local organization. Data and recovery still exposes retained backup/previous/candidate/incoming archives, interrupted issues, reset recovery, exact inspected-copy restore, the local working folder, picker-history cleanup and the guarded reversible local reset. The reset review and native confirmation remain authoritative. Nothing is deleted, expired, moved automatically or treated as a disposable cache.

Working SQL/minimum reader **10**, editor AST **1**, archive container **1**, frozen compilation **3** and the I02 CSP strategy are unchanged. The existing narrow file-status IPC accepts an explicit recheck flag; it grants no path authority and adds no new worker operation. No assistant checks, builds, launches or browser activity occurred. [Manual observations](../manual-testing/improvement-I06.md) remain pending; I07 owns the next writing-workspace redesign.
