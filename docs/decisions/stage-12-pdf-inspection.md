# Stage 12 — local source inspection

September 30, 2026. Stage 12 uses pinned `pdfjs-dist@6.3.289` in the renderer. Its worker, character maps, standard fonts, ICC profiles and WASM resources are bundled locally; dependency and resource notices are retained in `resources/licenses/dependencies/`. The renderer requests only app-bundled assets and an opaque, expiring, single-blob `collie-source:` grant. Main checks owner, location, file identity, size and checksum before returning bytes. The reader paints pages to a canvas with annotations disabled. It exposes no PDF links, forms, launch actions or scripts, so there is no PDF click navigation to delegate to the shell. XFA and system-font fallback are disabled; external request/navigation policy remains denied by the app shell. [PDF.js document API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html) and [page API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html) describe the selected local loading, rendering and text-content calls.

Inspection accepts PDF or UTF-8 plain-text managed attachments. A PDF may be stored as a source attachment up to the Stage 11 limit, but the in-app reader accepts at most 32 MiB and 10,000 pages; at most the first 400 pages receive saved extraction. PDF parsing uses an explicit local web worker; worker startup must succeed rather than falling back to main-thread parsing. Per-page text is capped at 100,000 UTF-16 code units, with truncation recorded as partial coverage. Opening is bounded to 30 seconds; page retrieval and text extraction to 10 seconds each; page rendering to 15 seconds. Cancel stops after the current bounded page and keeps committed pages. A timeout, password request, unsupported document or parser failure updates inspection status without deleting the managed original. PDF.js text ordering and completeness are not guaranteed. Scanned pages commonly yield no selectable text; there is no OCR. Plain text has one unnumbered part, index zero. Large-library UI responsiveness and the PDF worker's native behavior remain user acceptance work.

The extractor identifiers are `pdfjs:6.3.289:text-v1` and `utf8:text-v1`. Page records store PDF page index, printed page label when PDF.js supplies one, state, saved text, text hash and any warning. An exact extracted excerpt must match a UTF-16 range of saved text and retains its page, hash, quote and surrounding context. A manual transcription is labeled separately from extraction; a correction is a new record pointing to its predecessor. There are no geometric page coordinates because the current extraction path does not calculate reliable glyph positions. Navigation opens the original version and page, while the saved text range and quote remain inspectable. Any excerpt on another version is marked stale relative to the active version; no automatic reanchoring or matching is attempted.

Reimport stages a new managed attachment and immutable source version. It does not replace the original, change the active version, rewrite prior excerpts, source IDs, section links or manuscript annotations. The user compares checksum, captured canonical metadata, PDF title/author and extraction coverage, then explicitly selects the active version. Stage 11's source merge moves version ownership along with attachments; old excerpts retain their version IDs. Project backup/restore and independent copies include all retained managed blobs and these version/page/excerpt records. Working schema 6 and archive minimum-reader 6 are described in [the format record](../formats/working-project-v6.md).

This is an implementation decision, not a native result. Offline rendering, safe handling of unusual PDFs, cancellation responsiveness, version navigation, reimport, migration and backup behavior await Josh's manual acceptance. No deliberately malicious PDF or parser fault tooling is part of the user guide.
