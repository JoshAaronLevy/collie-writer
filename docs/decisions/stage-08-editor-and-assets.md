# Stage 8 — editor, templates and managed images

September 30, 2026. Implementation selected; runtime and native acceptance await Josh's manual results.

The five templates use the existing working SQL schema 2 and AST schema 1. A template creates flat ordered `text` documents with independent document and revision IDs, blank manuscript bodies, and no destination. Book, article, research paper and report seed only section names; Blank seeds Draft. Section title, `draft`/`review`/`complete` status and synopsis are document metadata and make their own lineage commit. Nested outline transformations and history remain Stage 9. Citation/footnote editing remains Stage 15.

Only the selected section's payload is fetched for an editor read. Tiptap's community editor mounts that payload without flattening structured content. App-owned block IDs are assigned on insertion and remapped on rich internal copy; copied citation/footnote anchors are not duplicated before their managed UI exists. External active HTML is refused with a visible explanation; the native Edit menu and toolbar offer a literal text-only clipboard path. Plain-text paste keeps Unicode and line breaks. A session's undo stack is distinct from local commits and chosen-file saves. Find/replace is case-sensitive within the active section's text nodes; it does not search across marks or sections.

Editor changes schedule a local `document.commit` after 900 ms idle, with a five-second maximum attempt cadence while editing continues. Navigation, editor blur, Save, close and suspend flush the current section. The commit serializes only the selected section, never every document on a keystroke. The existing operation ID/revision retry protocol remains in force. Failed acknowledgments leave the editor visible and selectable; stale revision also exposes a separate read-only rendering of the stored section for copying. The selected file remains a separate 30-second save operation and its status never claims cloud upload.

Image import begins with a native picker and a window/frame/process/project-scoped token. The worker reads the selected regular file without following symlinks, bounds it to 25 MiB, checks PNG/JPEG signatures and declared dimensions (at most 12,000 per side and 40 megapixels), stages immutable hash-addressed bytes, then registers a managed asset and lineage commit. Manuscript JSON stores only the asset UUID, alt text, caption and bounded display dimensions. Reopening loads the app-owned blob through a named read command and `blob:` URL, with a 256 MiB active-section load ceiling that leaves further images as placeholders. A source file can move or disappear after import. The CSP permits `blob:` only for images. The original image path never becomes a manuscript dependency. Image decoding, malformed-pixel payloads, larger libraries and artifact round trips are unverified.

Electron's built-in local spellchecker is enabled, with suggestions through the native context menu. Its macOS engine uses OS spellcheck. Electron documents that Windows/Linux use local Hunspell checks but may download a dictionary from the Chromium CDN on first use; no typed text is sent to that service. Collie Writer's existing request filter denies non-app requests, so spellcheck on a Windows profile without a cached dictionary is not established and needs user observation. This does not weaken offline writing. [Electron spellchecker documentation](https://www.electronjs.org/docs/latest/tutorial/spellchecker/).

No SQL or AST version bump was needed. The portable validator now accepts these template IDs and ordered flat documents while still requiring the same exact schema, per-document AST validity, asset ownership and ID-only operation receipts. Future nested documents require a coordinated validator change and migration decision. User-observed IME, clipboard, file round trip, target-OS spellcheck and input-to-paint performance remain pending; no assistant validation was run.
