# CD08 shared durable AI handoff

October 3, 2026. **Implementation complete — awaiting user testing.** This request implements CD08 and its explicitly authorized shared C07 contract. No other C stage or CD09 is implemented. CD03/CD05/CD06 remain engineering partial; missing tool/content-log isolation still refuses live Send/Run. Release remains **NO-GO**.

The full Codex plan, the C07 contract, CD07 lifecycle owners and the actual conversation/proofreading settlement, binding, journal and copy consumers were reviewed. The existing main journal and each feature's worker binding collection had independent 64-entry limits. Freeing only the main map would leave the worker bottleneck. The design therefore transfers both through one trusted worker receipt, using the existing shared content coordinator and AI storage owner.

The [local format and consumer matrix](../formats/ai-handoff-v1.md) specifies commit ordering, receipt identity, original encrypted retention, local database migration, bounded cold reads and interruption behavior. Portable formats do not change. Exact local operations v1/v2/v3, including raw output and final-channel/schema identity, keep their original meanings.

Normally completed outcomes move out of active capacity only after the original feature has committed its actual result. Worker proof binds scope/purpose/attempt/operation/version, capture/input/result digests, terminal sequence and committed portable revision/head. Main validates that proof against its protected record; then it retains the original encrypted bytes and asks the worker to retire the matching active binding. Pending worker/main writes keep their exact retry and existing account/close/project guards. A failed handoff cannot turn into a new inference request.

Cancelled, failed and unknown outcomes stay reserved until explicit acknowledgment through the global AI work notice. The confirmation links to the saved request and explains retained text, honest outcome, local capacity and no resend. Main checks the protected outcome and committed portable result; the renderer cannot confer proof. Missing original records stay reserved, with an actionable recovery explanation. Completed but unfinished transfer uses **Finish local handoff**; storage failures use **Retry local output protection**. These are disk-only actions.

Shared capacity appears in both writing tools and connection Settings, including original-project links from the trusted local library. Selecting a project uses the existing session guards. Deferred background transfer waits for an idle storage queue and the worker-observed original scope; it cannot settle against whichever project is selected later. Closed originals retain their hot records until ordinary reopening/recovery. Independent copies contain readable portable history but cannot acknowledge original bindings. Cold replay still resolves the original record/receipt without dispatch.

The persistent global action owner retains the exact uncertain acknowledgment even if its work item disappears. Feature providers do not treat retained outcomes as live requests or trap idle drafts/close. Actual running/protection work keeps CD07 safeguards. Model/account/login/funding behavior, manuscript Apply/Ignore/undo/checkpoints and content/export formats are unchanged.

Repeated-request review, October 3: preserved the existing CD08 implementation and reread the full plan and shared C07 contract. An interrupted explicit acknowledgment could encounter its own saved worker failure and return busy instead of completing that write. Acknowledge and Protect now share an exact, scope-checked failed-write retry before advancing; a previously committed retirement still resolves as done. This changes local recovery only, with no new dispatch path or uncertainty-to-success conversion.

The same review moved the binding/receipt read limit into SQLite's selected text expression, before allocating the returned row in JavaScript. Oversize data still refuses through the exact parser. Receipt job rows also require their stored operation ID to match the binding. The existing per-feature row ceiling, frozen record versions and retained files remain unchanged.
