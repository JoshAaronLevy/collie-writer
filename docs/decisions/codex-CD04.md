## Full-plan review and scope

The complete Codex plan, shared route/storage/recovery contracts and prior CD01–CD03 records were reviewed before implementation. Its stage separation remains appropriate: CD04 owns execution identity and durable ordering; CD05/CD06 own working feature actions and native structured-output integration; CD07 owns the expanded lifecycle experience; CD08 owns bounded retention handoff; CD09 owns owner-observed acceptance. Three details needed explicit treatment. First, registered v1 journals cannot acquire local-route defaults without changing old identities. Second, emitting in-memory output after a failed encrypted write would let a feature settle output before its journal was protected. Third, the email label exposed by stable account/read cannot distinguish ChatGPT workspaces. The implementation addresses these in the existing owners and preserves the unresolved execution gate.

## Session boundary and account identity

`AiDispatchSession` is a main-only interface used by the same `AiService`. The registered implementation continues using its own token owner, runtime, consent, included-only and isolation refusals. The local implementation uses **the existing managed account child**, never an injected token, second login, copied global profile, alternate provider or separate feature network stack.

Pinned 0.160.0's published Rust protocol declares `account/read.workspaceRouting` as experimental, with `chatgptAccountId`, backend origin and routing override. The existing initialize call now advertises experimental protocol support specifically to consume the workspace ID from ordinary account/read responses. Collie does not use the returned origin/override as request configuration. No arbitrary experimental method or renderer capability is exposed. References: [account protocol](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/src/protocol/v2/account.rs), [account/workspace reader](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server/src/request_processors/account_processor/workspace_routing.rs), [turn effort contract](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript/v2/TurnStartParams.ts). These published files were read as local source; no protocol-generation or runtime command was run.

Account reads capture the workspace ID and a fingerprint of the authenticated label/workspace. A missing field permits honest account display but cannot authorize execution. A changed identity, or any post-authentication `account/updated` notification (which lacks a stable identity), conservatively retires that session generation and requires explicit recovery. An idle ChatGPT notification retains the child for an explicit Resume/account re-read, avoiding a repeated startup-routing-notification loop. Active execution or a change away from ChatGPT closes the child. The subsequent read must confirm the existing account/workspace; it cannot silently adopt a replacement. This can require Resume for a benign provider update. After CD03 is implemented, the dispatch owner additionally re-reads the account before any content and rechecks identity/generation/model/catalog at each authorization boundary. No provider subject ID is fabricated or token decoded by Collie.

Prepare binds route/policy/runtime, protected local profile/account/workspace, fresh session generation owned by the account child, catalog revision/model/default effort, action/template/output contract, exact capture and serialized framing. Main project edit rights and close gates are checked before prepare/start and inside execution. Subscription sign-in never changes Collie entitlements or free-project designation. Both feature capabilities now explain the actual isolation blocker rather than claiming their shared durable adapter is absent. Existing Send/Run eligibility remains unavailable; no developer bypass or ready state was added.

## Ordering and recovery

1. Main records an ephemeral review stamp around the real worker capture. Account/model/catalog/route/template changes invalidate unsent dispatch authority. Saving a request locally does not require secure AI storage and does not queue inference.
2. For a new sent request, main checks that review and the worker commits the exact portable intent/capture. An existing receipt returns before new eligibility checks and never sends again.
3. The shared service prepares an immutable v1 registered or v2 local grant. The worker protects the matching local binding **before** start. A failed/unknown append or binding cannot create a replacement operation.
4. Start protects the encrypted initial operation before dispatch. It rechecks capacity and identity; a failed initial write retains that same operation as unknown for disk-only repair and cannot open a turn.
5. Streaming snapshots are coalesced into encrypted writes. Only a successfully protected snapshot is emitted or returned for portable settlement. Failed writes retain the newest real output in memory, interrupt the active session and block normal close until local protection succeeds. They do not publish unprotected output as a settled result.
6. The two feature adapters share protected-record projection, original binding/scope correlation and sequence guards. Per-attempt worker protection is serialized; a newer snapshot cannot replace an exact failed write. Dropped notifications are repaired by reading the protected local record and original portable capture.
7. Protection retry repeats local storage only. On restart, interrupted journal states become unknown with actual retained text and their original version. No account refresh, thread resume, catalog lookup or inference is performed. Independent project copies retain history without execution authority.

The [operation format and consumer matrix](../formats/codex-operations-v2.md) specifies exact digests and compatibility. Old v1 inputs and digests are unchanged; registered credential v1 and account metadata v2 remain unchanged. The shared 64-operation ceiling is retained. New operation records have a bounded 4 MiB encrypted envelope; this is not a larger content allowance.
