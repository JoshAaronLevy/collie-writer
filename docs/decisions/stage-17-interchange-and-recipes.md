# Stage 17 — Offline compilation interchange and recipes

October 1, 2026. **Implementation complete — awaiting user testing.** D5 remains Paged.js 0.4.3 plus Electron `printToPDF`; the real-footnote clipping and font/layout gate remains open. No assistant-generated PDF or viewer evidence exists, and no PDF/UA claim is made.

The Stage 16 frozen compilation model is captured once through the repository boundary. Batch formats share its `capturedHead`, selected document order, formatted citations, note numbering, bibliography and verified image bytes. PDF uses only the app-owned HTML/CSS adapter in an isolated hidden print session with no preload, Node, downloads, external requests or navigation. The worker asks main to render that trusted document through a bounded private message exchange; renderer IPC never accepts print HTML or a file path. Output jobs are independent from project Save and retain per-format paths, bytes/pages where available, losses, status and local reports.

One format uses a native Save dialog; multiple formats use a chosen directory plus a user-entered base name. A collision is shown before work and is **skipped** even if the user continues the remaining batch; no existing output is replaced by this flow. Retry with the same name can produce only missing formats, leaving successful files untouched. Same-directory no-replace publication and digest reads guard each new file. Markdown images go in a unique adjacent asset folder and are referenced by encoded relative paths. A failed Markdown publication may leave that folder for inspection; it never changes the project or another output. Cancellation retains completed files and reports the remaining formats separately. The legacy Stage 16 DOCX replacement flow remains available with its retained previous-file sidecar.

Markdown output uses UTF-8 CommonMark-style headings, paragraphs, lists, quotes, rules, tables, HTTP links, visible formatted citations/bibliography and numbered `[^n]` footnote definitions. It reports layout changes, unsupported underlining/superscript semantics, and table-header substitution. Plain text uses UTF-8 paragraphs, heading cues, list markers, explicit `[note n]` references/bodies, visible citations/bibliography, link URLs, and image labels; its report states lost styling, page layout and image pixels. Neither format is a project backup. The importer accepts UTF-8 `.md`, `.markdown` and `.txt` up to 8 MiB. It maps headings 1–3, paragraphs, simple ordered/bullet lists, quotes, rules, basic bold/italic/HTTP links and single-use numbered footnote references. Rendered citations/bibliography remain visible text without source identity, and plain-text note markers do not become editable notes; the preview calls out these limits. It rejects raw HTML and unsafe file/network embedding. Tables/code fences and image links remain visible text with an explicit loss; it never fetches relative or remote resources. Exact original bytes can be retained by choice.

Working SQL/minimum reader move 8→9 through retained-copy migration. Recipe revisions are persistent project-local checkpoints; recipes store stable document IDs, not manuscript snapshots. Missing/inactive sections are flagged. Recipe edits and imports retain an operation ID across uncertain replies so a retry cannot repeat the mutation. Recipe create/edit and batch have no entitlement checks yet; Stage 18 applies the approved capability matrix, including continued export from an existing recipe after entitlement loss. Native package/print, long-note page boundaries, non-Latin shaping, 200,000-word timing, output collision/interruption, import fidelity and schema-9 archive round trips remain user-owned acceptance work.
