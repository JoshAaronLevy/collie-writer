# I09 — Export, saving, settings and the local writing journey

October 2, 2026. **Implementation complete — awaiting user testing.** I09 implements only the requested local UX stage. The full improvement plan and its I03/I04/I06–I08 ownership, format and recovery contracts were read alongside MVP Stage 16–19 decisions, export preparation/jobs, the trusted tutorial path, licensing, privacy/accessibility and the direct update/close handshake. No user acceptance was supplied; no assistant tests, checks, builds or launches occurred.

## Export and reference tools

The retained export owner now presents three views: Sections and options, Review and destination, and Export results. Initial selection contains active text sections; chapter/part choices toggle their text descendants. Selected order and saved recipes are disclosures, alongside document-property choices and format limits. Subsequent outline changes do not silently widen selection: missing/inactive IDs remain visible and must be removed or replaced. Free access exports one format at a time and can load existing recipes; authentic paid access owns recipe edits and batches. No substitute paid entitlement was introduced.

The renderer binds the displayed capture to the ordered section selection, paper, title-page/description choices, formats and output name, and to the current protected head. Changing options clears that capture and acknowledgment; changing the head makes it unusable and resets acknowledgment. Preview and both export paths protect drafts through the existing owner. The worker still re-prepares under its serial boundary and enforces the frozen head/digest, broken-reference blocking, metadata acknowledgment and conversion limits. I04 title/byline/description semantics remain unchanged. No output renderer or format was replaced.

The normal primary action opens a native file picker for one format or folder picker for a batch. Existing outputs remain kept by that flow. The separate DOCX replacement route remains disclosed, available only for a DOCX selection, and retains its existing confirmation and previous-output behavior. Cancelling the picker keeps the review. A later edit cannot alter an already captured job.

Results enumerate all session jobs for the current project, with every format's state, destination, errors, pages where reported, losses and retained report path. Partial/cancelled results explicitly keep completed files. The persistent session continues polling across navigation and project changes. Global result links reopen the matching project and focus the specific job; successful notices collapse into a completed-export disclosure, while active/error outcomes remain visible. This does not add a restart-persistent export-history index: existing worker reports/candidates remain retained, and release/native interruption evidence remains pending.

Citation style and bibliography preview live in a disclosure below Export. Citation/source correction links preserve the original typed navigation. Preview-only metadata acknowledgment still cannot approve an export. Style changes now register their pending exact operation with the session so scope replacement/close cannot drop an uncertain mutation; the disclosure opens for errors/retries. Citations, export, import and access controls use Mantine and scoped semantic styles. None of these owners is unmounted by ordinary destination navigation.

## Save, Settings and Help

The shared Save/Save options control appears in Write, other project destinations, and the app header when a project is retained in Projects, Settings or Help. It calls existing Save, Save As, separate Backup and Locate operations; File details opens Project actions. Existing detailed file states, conflicts, cancellation, native overwrite consent and retained-candidate handling remain globally actionable. Local protection, selected-file Save, export and cloud upload remain distinct. No destination is assigned by setup, and no cloud acknowledgment is invented.

Settings exposes Appearance & accessibility, AI connections, Collie access, Data & recovery, Updates and About/licenses/support. Appearance retains its startup-owned preferences and optional author. AI explicitly states unavailable with no login or inference action. Collie access retains its existing main-enforced free designation, signed access, purchase/restore availability and buffer-drain rules. No commercial prerequisites were configured.

About owns runtime details, privacy disclosure, the existing user-prepared content-free support preview, tutorial access and bundled notices/source. Initial citeproc attribution remains visible in the shell; moving support did not hide that required attribution.

A fixed `app.helpAction` IPC accepts only an exact request envelope and one string from `licenses | check-updates | install-update`. It verifies the trusted main frame and grants no renderer-supplied URL, path, feed or general restart authority. Preload accepts only a correlated boolean receipt. License UI shares the same native function as Help. Update controls invoke the existing `DirectUpdater`; no automatic check, new origin, credentials, publication or update policy was added. Installation still reaches the existing `prepareUpdateRestart`/close-and-flush handshake. Development/unconfigured builds explain that updates are unavailable in their native dialog. A completed action receipt does not mean an update was installed.

## Optional orientation and trusted sample

Write offers three short points: writing, research, and Save versus export. Dismissal writes the exact bounded device-local record `collie.orientation.v1 = {version:1,dismissed:true}`. Invalid/missing values show tips; a failed write offers a session-only hide with a truthful message. Setup is unaffected, and focus mode hides orientation. The same concepts remain available through the guide after dismissal; there is no per-project repeated onboarding prompt.

Fresh optional tutorials use **Sample: Evaluating a study**, an ordinary trusted sample article containing a synthetic before/after study, one retained plain-text original and a sample citation. Its source and draft explicitly disclose that the participants/data/findings are invented teaching material. They illustrate observation versus causal claim, limitations and research questions, without claiming actual research or adding a specialized Study critique engine. The resource is production help content, not a fixture or test harness.

The existing main-process sample slot remains authoritative. Reset creates a new sample identity, retains older samples/edits/files and rotates only the sample allowance. Renamed/provisioned older samples return unchanged. An interrupted older Lantern Library setup continues with its old source/text resource rather than being silently rewritten. The older resource remains bundled. Tutorial buttons now use guarded typed destinations instead of focusing hidden DOM targets. With personal work open, the guide states which project its actions apply to; opening the separate sample is explicit.
