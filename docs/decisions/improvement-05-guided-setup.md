## Flow and ownership

The first successful local-project inventory decides the opening destination: an empty installation stays on project selection; an installation with projects opens the library unless a saved setup record needs attention. I06 owns safe last-project reopening. The persistent I03 workspace session remains mounted behind a dedicated setup region, so unfinished editor and research owners are protected by their existing navigation/flush rules. Opening an existing project or the separate tutorial remains available from the first step.

`features/onboarding/OnboardingWizard.tsx` owns `type → details → creating → connection`; writing is the destination after completion. It uses Mantine `Radio.Card` and the authoritative I04 type labels/structure, with five primary cards and Research paper/Blank nonfiction under More starting points. Study critique describes a research-supported argument against a publication; PDF/link intake still uses general Sources later. Project title, author/byline and description reuse I04's field/error contract. Back before dispatch retains inputs. Back after a creation receipt shows the same project's saved summary and opens its real Project details editor for changes; it cannot create a second identity.

The app profile holds one bounded, versioned `collie.project-setup.v1` record. Before trusted IPC create, the renderer stores the exact `CreateInput`, including its operation UUID. `creating` freezes the payload. Retrying or reopening replays only that operation, which I04's worker reconciles through its durable intent/receipt. A confirmed result stores `{projectId, workspaceId, documentId}` and advances to the connection step. If saving the receipt fails, the frozen create request remains the recovery path; replaying it resolves to the same identity. Unreadable setup data is never silently reset: the screen offers another read or explicit discard without deleting any project. Before dispatch, Cancel clears only the setup record. After dispatch with an unknown outcome, leaving retains the exact request. After a confirmed commit, leaving retains the local project; continuing opens its first text section and clears setup. No destination is assigned in setup. The first project-file Save remains a native picker.

An optional `collie.project-author.v1` preference fills later new-project forms on this device. It is separate from portable project data and can be edited or cleared under Settings → Display and privacy. Its value is copied into a project only through an explicit create action. Description and setup fields never enter a provider request in this stage. The app profile can therefore contain project title/byline/description while setup is unfinished; Settings discloses this.

## Access and AI boundary

Creation does not require the new project to be editable. The connection step shows the current free editable choice, if any, and asks the writer to designate the new project explicitly when needed. The trusted existing access service owns that transition. The controller first protects pending work from the prior project; the access command also uses its established flush/transition contract. A failed or unfinished transition leaves the created project intact and read-only. An eligible paid project can continue without designation. Provider authentication cannot override Collie editing rights.

I10/I11 have no approved working provider route in this build. The connection step therefore says AI is unavailable and offers **Continue without AI** once editing rights are available. It renders no fake provider cards or sign-in success. The connection state is a replaceable boundary for I11, while this stage's local create and destination semantics remain stable.

Onboarding CSS lives in a semantic CSS Module beside the wizard. The setup region is outside the older `.projects` presentation scope; existing workspace styles stay with their current owner until I06–I09. The theme/CSP strategy from I02 is unchanged. Working SQL/minimum reader **10**, editor AST **1**, archive container **1**, and compilation **3** are unchanged. No tests/checks/builds/app launches were performed; [manual observations](../manual-testing/improvement-I05.md) are pending.
