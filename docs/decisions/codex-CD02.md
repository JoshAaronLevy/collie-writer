# CD02 — Managed browser login and connection ownership

October 2, 2026. **Implementation complete — awaiting user testing.** The entire [Codex plan](../../codex-implementation-plan.md), including CD03–CD09's separate execution, feature, lifecycle and capacity contracts, was reviewed before this work. CD02 implements account connection only. No assistant tests, checks, builds, app/runtime/browser launches, sign-ins or inference occurred.

## Decision and scope

Use the existing project-pinned Codex **0.160.0** app-server and its managed ChatGPT login. `AiService` owns one `LocalCodexSession`; its private `CodexAccountRuntime` supports only initialization, configuration inspection and named account methods. It exposes no generic RPC, thread, turn, model-list or execution method. The registered OAuth adapter, all null registrations, commercial funding/isolation refusals, packaged refusal and frozen operation v1 remain intact. No dependency or license change was needed.

Josh's normal subscription/account credit policy applies only to his unpackaged development identity. Credentials, browser authorization, refresh and revocation belong to Codex; Collie does not construct an OAuth client, intercept tokens, supply API keys, alter account billing or borrow any existing default Codex login. Commercial classification remains unresolved as recorded in [CD01](codex-CD01.md); this implementation does not grant provider approval or release permission.

## Profile and configuration ownership

Profiles live beneath the verified development working root, at `ai/runtime/local-codex/<profile UUID>/`. Each has separate `home`, `codex`, `work` and `tmp` directories. The active profile is stable through explicit resumes. A fresh login gets a new candidate namespace; a replacement cannot overwrite the old account while authorization is incomplete. Main checks containment and derives paths from UUIDs, never renderer paths. Codex's direct keyring namespace is `Codex Auth` / `cli|<16 hex characters from SHA-256 of canonical Codex home>`. Its [storage implementation](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/auth/storage.rs) supports strict keyring without auto/file fallback; [backend selection](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/config/auth_keyring.rs) uses `features.secret_auth_storage=false` for this direct backend.

The environment is an explicit allowlist, with isolated homes/temp roots and necessary Windows system paths only. No inherited PATH, proxy variables, credentials, provider overrides, default profile or test hooks. The resolver uses the exact installed platform package and contained binary, with no download/global launcher or self-update.

HOME and CLI flags do not override every [managed configuration layer](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/config/src/loader/README.md). On an explicit account action, a separate credential-free `configuration` profile first loads configuration through the real account transport. Main refuses nonempty active external layers before starting an existing credential namespace; that process is closed before the account process starts. The actual account process repeats the effective-config check. Required values include strict keyring, direct backend and ChatGPT-only login. Unexpected `auth.json`, user config or working-directory `.codex` is refused without reading credential contents or deleting files. This is production connection input validation, not a diagnostic/test interface.

This prevents knowingly loading an incompatible store. It is not an OS sandbox or a guarantee against an administrator changing policy between the configuration read and process startup. Managed cloud configuration can also arrive after login; incompatible configuration is refused by later checks. CD03 still owns complete tool/config/content-log isolation before any manuscript is dispatched. No thread is created in CD02.

## Login, state and recovery

The global **Connect Codex** entry opens the existing guarded Settings → AI connections. The existing setup and writing companion share the same persistent provider. **Continue with ChatGPT** invokes main; main protects the attempt/candidate record before launching Codex, initializes the transport, requests `account/login/start` with only `type: chatgpt`, and opens the returned URL through Electron's system browser. The initial URL must be the pinned HTTPS OpenAI authorize endpoint with a single PKCE/state/client/response/loopback redirect set. URLs and runtime login IDs never enter renderer state.

The [pinned login server](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/server.rs) uses port 1455 and may send `/cancel` to an occupying service before falling back to 1457. Collie first attempts an exclusive local bind and refuses an occupied port without contacting that service; only a port-1455 authorization response is accepted. The reservation must be released for the runtime to bind, so an external process racing that handover remains a platform limitation. Do not claim that the port can be reserved atomically across these separate processes.

An app attempt is correlated to the returned runtime login ID. Early completion events are bounded and retained until their response arrives. Only a matching successful completion followed by authoritative ChatGPT `account/read`, a nonempty sanitized account email and a protected active-pointer write publishes connected. Email is display metadata, not a provider subject/workspace identity or execution grant. Stable published `account/read` lacks those execution identities; CD04 must establish its own required binding instead of treating this label as one.

Cancel tombstones the app attempt immediately, sends the exact runtime cancellation if known, and closes the child/callback listener. Cancellation accepted before matching completion/account reconciliation prevents adoption. Once that reconciliation wins, main disables Cancel before the durable adoption write begins; a delayed Cancel waits for its actual outcome and explains if sign-in already completed. It never reports false cancellation after committing an account. A failed adoption write restores the old pointer, with an uncertain restoration held for disk-only protection. The last attempt receipt survives restart; current-process duplicate attempts use the existing bounded 64-entry convention. Cancelled/failed/interrupted candidate namespaces cannot be resumed. They remain visible as **Clean up inactive sessions**; cleanup performs only logout on those namespaces, sequentially. It pauses any active child, whose saved connection then needs explicit resume. Up to eight retired namespaces are retained; new logins stop before exhausting the space needed for disconnect. Explicit cleanup frees their metadata slots; profile directories and interrupted encrypted candidates are retained without automatic expiry.

Metadata uncertainty keeps the exact desired envelope in main and blocks further account mutations and normal close. **Retry saving connection state** repeats only that encrypted disk write, without login, refresh, cleanup or inference. Startup reads the last complete encrypted envelope and never adopts a retired candidate or resumes network work. See [local v2 compatibility](../formats/codex-local-v2.md).

Ordinary status/focus polling uses only Collie's local snapshot. A returning account says **Resume Codex connection** until an explicit resume starts the runtime and reads its actual account. Missing/non-ChatGPT credentials require reconnect; a changed email requires new browser authorization. Codex owns automatic renewal while its explicitly started child is active. Runtime loss or an account-authentication loss invalidates the connection. Idle children are closed through the existing main close/update owner and suspend path; they do not count as unfinished inference.

Disconnect protects removal of the active pointer before stopping its child and logging out retired profiles. Failure leaves actionable cleanup rather than usable credentials. [Pinned logout](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/auth/manager.rs) attempts remote revocation but swallows its failure before local deletion. A successful reply therefore acknowledges local credential removal only; Collie always reports remote revocation unconfirmed for this route. Logout can affect the corresponding remote authorization, but Collie neither targets nor deletes the user's default local Codex store.

## Network, presentation and remaining work

Explicit Connect, Resume, Disconnect or cleanup starts account services. App-server startup/background model metadata and `account/read` workspace routing may network even without an explicit model RPC. The existing [pinned map](../ai/codex-local-contracts.md) documents this. There is no inference probe or manuscript/context submission. Runtime metadata/cache/SQLite diagnostics stay within its isolated root and are not collected in Collie support output; do not promise the runtime creates no files or logs. Complete content-log isolation is still CD03 work.

The bounded UTF-8 JSON transport rejects unsupported server requests, ignores unrelated notifications, limits line buffering to 4 MiB and uses 20-second RPC deadlines. The OS browser-launch acknowledgment also has a 20-second deadline and settles on cancellation or runtime exit. The OS may still open a late window; its acknowledgment cannot restart or adopt the retired attempt. Browser sign-in completion then has a three-minute deadline. Browser closure cannot be detected directly; the user can Cancel or wait for that deadline. Cancellation waits on the work/controller captured for that exact attempt, never a newer action; a delayed completion notice also checks the latest protected attempt. Account denial, callback conflict, browser-open failure, secure-store failure, offline errors, timeout, process loss and metadata protection have sanitized user-facing recovery messages. Provider error text, tokens and authorization URLs are never forwarded.

Existing Mantine controls/dialogs, scoped semantic CSS, retained drafts and IME/navigation-aware focus return are reused. Global progress remains visible away from the originating panel. No renderer CSP relaxation or preference is added. Local-development and account spending labels remain distinct from commercial approval. Both feature capabilities remain unavailable; local request/history handling and manuscript access rules are preserved. SQL/minimum reader **12**, AST/archive **1**, compilation **3**, operation capacity and release **NO-GO** are unchanged.

The review confirms CD03 must settle true execution isolation/readiness; CD04 must add route/session/output-bound durable dispatch; CD05/CD06 own actual feature results; CD07–CD09 own the remaining integrated lifecycle, shared C07 capacity and final owner runbook. No later stage is implemented here. Native credential behavior, provider access, UI/focus/IME and recovery all await the [manual handoff](../manual-testing/codex-CD02.md).
