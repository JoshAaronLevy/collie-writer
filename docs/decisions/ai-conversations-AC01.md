# AC01 provider and extension contract

October 8, 2026. Source/documentation decision for [AC01](../../ai-conversations-implementation-plan.md). Runtime access and commercial approval are not established by this record.

## Active development path

Keep the main-owned direct ChatGPT-plan session for the exact unpackaged development identity. It uses the user's own OAuth grant, protected local credentials and the existing conversation capture/operation/handoff owners. No API key, proxy, automatic inference retry, model substitution, Codex runtime or additional provider is introduced.

The existing dynamic registration, stable host/client association, validated identity and separate plan-use scope agree with the [official sign-in contract](https://developers.openai.com/siwc/token-sharing-open-source/sign-in). Account registrations remain separate, renewal remains serialized with replacement credentials protected before reuse, and sign-out retains the registration while revoking/clearing credentials. [Official account/session contract](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).

`direct-http.ts` already sends OAuth-authenticated `POST /v1/responses` with array input, instructions, `store:false` and `stream:true`; model choices come from the selected account's catalog. The bounded SSE reader requires a completed provider response and matching final text; EOF alone is unknown, and partial/incomplete output retains its actual outcome. No transport rewrite is needed for AC01. [Official models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

AC01 corrects the early-renewal refusal: a valid access token remains usable when it cannot yet be refreshed or has no refresh token. Expiry is still checked before dispatch; unknown rotation outcomes still cannot replay a possibly consumed refresh token. This follows the existing expiry/earliest-refresh fields rather than adding a timer or probe. [Official token fields](https://developers.openai.com/siwc/token-sharing-open-source/token-reference).

AC01 preserves specific catalog failure reasons, distinguishes confirmed unusable credentials from an otherwise unvalidated subscriber context, and recognizes a model-specific capability refusal. Indexed error fields remain bounded machine identifiers. A route/fixed-capability refusal pauses that registration's sends in main for this app session, retaining its safe diagnostic even after model refresh or reauthorization. Correct the integration before a later app session; restarting is not itself a remedy. Other account registrations remain independent. Temporary failures retain credentials, and no refusal automatically retries inference. [Official recovery guidance](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).

## Main-owned capabilities

`AiStatus.capabilities` is transient version 1, produced by `src/main/ai/capabilities.ts` and strictly checked at the shared status boundary. Its binding contains the route kind, local account registration ID, selected model, catalog revision and existing conversation review revision. The review revision carries session/policy invalidation. The envelope must match the surrounding status; it cannot confer dispatch authority. It contains no provider subject, client ID, token, account fingerprint, conversation content or portable state.

| Fact                             | AC01 representation                                                                                       | Meaning                                                                                                   |
| -------------------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Text readiness                   | Exact copy of main's conversation availability, including its unavailable reason                          | Eligible to review/attempt a request under existing guards; not proof of provider admission or completion |
| Web implementation               | `unavailable / research-adapter-not-ready` on the direct route                                            | AC06 has not implemented the tool-enabled request/result adapter                                          |
| Direct web contract              | `documented`                                                                                              | The route documents conditional web search; this is not account authorization                             |
| Direct account/model eligibility | `unknown / account-model-unverified`                                                                      | Neither model listing nor successful text inference establishes tool eligibility                          |
| Other build/route                | `unavailable / route-not-established`, contract `unestablished`, eligibility `unknown / route-unverified` | No usable research route has been established for that build                                              |

The shared Manage ChatGPT dialog's Connection details shows Conversations and Web research separately. Capability calculation performs no network or credential reads; quiet startup and the existing preparation owner remain. Ordinary saved transcript reads do not require a connection.

Unknown does **not** mean provider-unsupported. The current route documents conditional web search, whereas hosted file search, Code Interpreter and other listed hosted tools are explicitly unsupported. AC01 adds none of them. [Official route limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

AC06 must introduce a new capability revision when its adapter becomes usable: distinguish available-to-attempt, explicit unsupported/refused evidence, and still-unknown eligibility. Without an authoritative capability field, permit the user's explicit, reviewed research request as the first real attempt. Never require a hidden probe. Bind observed evidence to route/account/model and the effective policy/session generation; do not carry it across a changed binding or treat one success as perpetual permission. A tool refusal affects research without falsely revoking ordinary text capability. The current v4 text request cannot produce tool-eligibility evidence.

## Frozen extension strategy

No persisted format changes in AC01. SQL/minimum reader 16, conversation 2, capture/message 1, archive/editor 1 and direct operation/binding 4 remain. Preserve `DIRECT_INSTRUCTIONS`, `directFrame`, `operationDigestV4`, `isDirectExecution` and all historical readers exactly.

1. **AC02 context:** introduce a new explicitly discriminated capture/template and direct execution version for automatic history. Retain historical readers/digests; do not reconstruct a pending old request with new history. Hash the exact ordered messages, roles, revisions, attachment selections, coverage and instructions that the user authorizes. The worker assembles bounded context independently of display pagination. Use client-supplied HTTP input, not provider conversation IDs or HTTP continuation IDs.
2. **AC04/AC05 extensions:** version memory coverage and source/excerpt references under that context contract. Older inputs retain their original interpretation. Reviewed summaries do not replace transcript originals; research evidence remains separately identified and untrusted as instructions. Exclude device credential/binding identity from portable context.
3. **AC06 request/results:** introduce a distinct tool-enabled execution/template and structured result contract. Never add tools to `responses-text-v1` or weaken its frozen no-tools instructions. A request digest must bind exact tool configuration, model/account/session, ordered context and output contract. The result envelope separates assistant text/outcome, cited references, other retrieved references and warnings; it never marks a source verified or saved merely because a provider returned it. Preserve useful answer text when ancillary reference metadata is malformed. Unknown tool types cannot become executable local actions.
4. **Persistence in the owning stage:** choose the next unused versions from the actual checkout when implementing them. Update strict validators, IPC, worker writes/reads, budgets, migration, archive/copy/rekey, exports and full-data retention comparisons together. Migration must retain originals and never redispatch an old attempt. New versions use the existing protection/handoff service; no second queue or remote conversation store.

These are fixed design boundaries, not implemented AC02–AC07 behavior. The reviewed-context and response schemas will be concrete in their owning stages.
