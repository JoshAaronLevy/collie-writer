# D5 — Offline PDF pagination

September 29, 2026. **Select Paged.js 0.4.3 + Electron printToPDF. Adapter implementation complete; PDF fidelity gate pending user evidence.** No PDF was generated, opened or visually inspected by the assistant.

`exportPrintDocument()` translates the immutable compilation into escaped local HTML and fixed app CSS. Manuscript images become bounded PNG/JPEG data URLs. Bibliography/citation markup is rebuilt from safe formatted runs. Paged.js uses real CSS page footnotes; author notes and Chicago citation notes follow compilation order, with no endnote fallback. The full unmodified `dist/paged.js` artifact is pinned and bundled as `resources/vendor/paged.js`; the automatically running polyfill/legacy build is not used.

`src/main/printing/pdf.ts` is an internal main-process adapter, not a renderer capability or a production export screen. Each invocation owns a fresh nonpersistent Electron session and hidden sandboxed window, with context isolation, no preload/Node/webview, denied permissions/popups/navigation/downloads, and an exact in-memory URL allowlist. The `collie-print` scheme is registered before app readiness; only the job's private session installs its handler. File paths and browser URLs are not accepted from the renderer. Stage 17 must connect it only to validated worker compilation results and trusted export grants.

The print CSP permits only its own app script, fonts and stylesheet plus generated data images. Paged.js needs dynamically inserted inline styles; that exception is confined to the print session. The main application CSP stays unchanged. No imported HTML/CSS or remote content is a valid adapter input.

Before pagination, the service explicitly loads every selected font face, waits for `document.fonts.ready`, and decodes images. It awaits `Previewer.preview()`, removes the unpaginated source, then waits again for fonts/images before `printToPDF({ preferCSSPageSize: true })`. A bounded 120-second job lifetime and 2,000-page limit reject stalled/oversized jobs. Abort/failure destroys the owned window, unregisters its protocol and discards in-memory content; only PDF bytes, page count and captured head return to the future job owner. No temporary manuscript file or destination overwrite occurs here. [Paged.js Previewer](https://pagedjs.org/devdocs/Previewer.html), [Electron PDF API](https://www.electronjs.org/docs/latest/api/web-contents#contentsprinttopdfoptions).

## Fidelity and fallback ownership

[Paged.js issue 320](https://github.com/pagedjs/pagedjs/issues/320) documents a real footnote-clipping risk; installing the package, awaiting pagination or inspecting source does not resolve it. Long/multiple/boundary notes, continued notes, long tables, image/caption layout and reader output remain acceptance gates. The adapter does not claim automatic detection of every clipped line. Keep release acceptance blocked until the user supplies those observations through a real export workflow.

If user evidence exposes a pagination failure, the owning implementation stage first gets a bounded two-day targeted correction window. If the selected engine cannot preserve complete genuine page notes, change D5 to the planned **bundled Apache-2.0 Typst compiler** before accepting PDF export. That change must include app-generated safe source, restricted file access, per-target packaged binaries/notices, the same immutable compilation input and new user-owned fidelity results. Do not silently replace footnotes with endnotes, send content to a hosted renderer, accept clipped output or leave Stage 17 to choose an engine from scratch. Typst is a documented fallback, not an installed or proven second engine. [Typst footnotes](https://typst.app/docs/reference/model/footnote/).

## Fonts and layout

Bundle unmodified Source Serif 4 regular/bold/italic/bold-italic; Noto Sans CJK SC regular; Noto Naskh Arabic regular; Noto Sans Hebrew regular, all with their OFL notices and exact asset hashes. CSS uses explicit local faces; DOCX embeds the regular families and sets native run formatting. Source Serif covers the principal Latin/Greek/Cyrillic body role, with Noto families intended for CJK and mixed-direction quotations. CJK uses a Simplified Chinese regional font; language-specific Han glyph preferences and synthesized emphasis require user review. Font presence is not proof of glyph coverage or correct shaping. Emoji, every Unicode script, full RTL manuscript layout, identical Word/PDF pagination and PDF/UA compliance are not claimed.

Letter and A4, single column, one-inch margins, page numbers, constrained images, plain rectangular tables and native page notes are the selected subset. The [pending manual scenarios](../manual-testing/stage-03-pending-fidelity.md) define user evidence needed before D5 acceptance. No fix to upstream clipping is claimed without that evidence.
