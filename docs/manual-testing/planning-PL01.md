# PL01 — Chapter material walkthrough

Implementation is complete; runtime acceptance is pending. Use disposable projects/files for structural, history and recovery actions. Keep the original `.collie` file untouched. The assistant has not launched the app or run these steps.

1. **Open existing work.** Launch with `npm run dev` and open a disposable copy of an existing project. Expect the same writing, outline, notes, sources and conversations. Choose **Chapter material** in Write. Existing note/source links and chats with valid historical chapter/section origins should appear. A previously remembered Notes/Source companion should open Chapter material with its prior pane sizing.
2. **Reuse originals.** Select a chapter, choose **Add material**, filter/search by title, and add an existing note, source, saved source excerpt and chat. Select another chapter and add those same items. Each chapter should show one entry for each original. If needed, create the sample note/source/chat through their existing surfaces; save an excerpt through Research’s original reader. Adding a link should not change manuscript prose or send an AI request.
3. **Open and edit.** Choose Open original on each material type. Expect the correct retained note, source, exact excerpt/version or chat to open. Edit/save the note through Research, then return to both chapters: both should show its updated original. In the AI conversation list, the linked chat should appear under the selected chapter/section; its historical starting chapter remains unchanged.
4. **Remove one use.** Remove an item from one chapter. Expect it to remain in the other chapter and in the project library. Add it back and expect one entry. Remove a migrated chat’s original chapter link, then reopen the project later: it should not be silently seeded again.
5. **Check nesting.** Select a child section beneath a linked chapter. Expect parent material labeled Inherited from the chapter, after direct section material. Add the same item directly to the child: expect one entry showing both direct/inherited use. Remove its child link: expect it to remain inherited. Select the parent to remove that parent link. Part links, where available, follow the same rule.
6. **Preserve drafts and inactive material.** Make an ordinary note/manuscript edit, then add material through Write. Expect the existing draft-protection flow to retain/save eligible edits or identify an explicit draft that needs attention. Archive a linked chat or note and inspect its chapter: expect its retained entry/state and original access. Archive/restore a chapter through the outline’s existing controls: links should remain, with mutation unavailable while inactive. In a project with read-only access, reading/opening originals should remain available and link changes should be disabled. If Check change appears after a genuine interruption, use it to resolve the saved outcome; Save/reopen must not send AI or silently repeat the change.
7. **Check structural changes on the disposable copy.** Give two merge-compatible sections distinct and shared links, then merge through the outline. Expect the surviving section’s material to be their union, with shared items once. Split a section using the existing split action. Its direct links should stay with the original, while the new sibling may still inherit parent links. Rename or move an item: direct links should follow its identity and inherited labels should follow its new parents.
8. **Check history on the disposable copy.** Keep a named version with known links. Change links and writing, then restore that version. Expect its writing/outline and saved links to return; current work should be retained in the pre-restore version. Restoring that pre-restore version should recover the later state. If an older pre-PL01 version exists, restoring it should leave current associations intact. Original research bodies must not be rewritten by manuscript history restoration.
9. **Save and transfer.** Save the disposable `.collie`, close/reopen, then create an independent copy and use Backup/Restore with disposable destinations. Expect direct/inherited links, chat origins, excerpt originals and saved link history to survive. Change a link in the independent copy and reopen the original: its links should be unchanged. Repeat reading/linking with ChatGPT disconnected; these are local actions.
10. **Check reading and keyboard use.** Use a collection with more than 20 items to exercise title search, type filters and Previous/Next. Navigate between chapters and Research while reads load; expect only the selected project/chapter’s results. Repeat basic panel actions using the keyboard, a narrow window and 200% zoom. Expect named controls, visible focus and contained content; closing the companion or entering focus mode must preserve manuscript/chat drafts.

Report observed results separately from the passed format/lint/typecheck commands. No automated test suite is part of this walkthrough. The Plan board and AI organization are later stages.
