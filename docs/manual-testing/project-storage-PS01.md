# PS01 manual guide — Storage locations and project identity

October 5, 2026. **Implementation complete — awaiting user testing.** Format, lint and node/web typecheck passed without warnings/errors; see the [implementation record](../validation/project-storage-PS01.md). The following walkthrough is for the user; no runtime acceptance has been recorded.

Use disposable projects and files, with no important unsaved forms or active AI requests. Do not delete app data, alter journals, fill disks or reset your real library. Saved research/conversations can be checked with an existing disposable project; no new AI request is needed for this stage.

Stage PS01 complete. As a user:

1. When I run `npm run dev` from the repository myself and create/open a disposable project, the usual creation and writing journey still works. The assistant has not launched the app. If no project is open, Settings → Data and recovery tells me to open one to see its selected file and Save status.
2. When I open Settings → Data and recovery and expand **Working-data location**, I see the shared local folder and its explanation. **Show local working folder** opens that folder in Finder/Explorer. The separate **Selected project file** section identifies my project. A never-saved project says no project file is selected and offers Project file actions, without a Show project file button.
3. When I open **Project file actions**, choose the first **Save…**, and cancel the native picker, the project remains local with no selected file. When I Save again to a new disposable `.collie` outside the working folder, Data and recovery shows that exact selected path and a saved status after the operation finishes. **Show project file** reveals it in Finder/Explorer; it does not reveal the working root. The explanation says the file opens the whole saved project, including research, citations, managed originals and saved conversations.
4. When I return to Write and edit without Save, local protection still runs automatically. Typing can briefly need protection; after protection settles, the selected file remains older and the UI asks me to Save. Data and recovery and Project file actions agree. When I explicitly Save and let it finish without further typing, they show saved status. If I type during Save, newer work must not be described as included in that captured file.
5. When I make another edit, let local protection finish, then close normally without Save and relaunch myself, my local writing returns and remains unsaved relative to the selected file. Close should not initiate a file Save or picker. When I explicitly Save afterward, the selected file is updated. Repeat with a never-saved disposable project if useful; it should reopen locally with no assigned file.
6. When I inspect **Recovery, backups and retained versions → Picker history and recovery limits**, search indexes are described as rebuildable and cache clearing as unavailable. When I choose **Clear picker history**, the notice reports that work and recovery were kept. My saved writing/research/conversations remain accessible. In Project actions/Projects, Archive and the Archived view explain that hiding a project frees no space; unarchiving restores visibility. Reviewing the Reset disclosure explains retained recovery and no space reclamation; executing Reset is not needed for PS01.
7. When I read the tutorial and About → Where your data lives, their storage, Save/close and cache explanations agree with Data and recovery. When I switch to a second disposable project, the selected title/path/status follows that project, without briefly presenting another project's file as its own. Keyboard navigation can reach the disclosures and actions, and long paths remain readable in a narrow window.
8. **Only if an appropriate installed production artifact containing PS01 is already available:** when I inspect a disposable `.collie` in Finder/Explorer, it uses the approved collie-and-pencil artwork. When I double-click it with Collie closed and then with Collie already open, the existing guarded inspection/opening journey handles it, including the local-versus-independent-copy choice when applicable.
