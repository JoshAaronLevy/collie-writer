# IM06 — user manual guide

**Implementation complete — awaiting user testing.** This guide covers local source/note destination previews. ChatGPT analysis, final proposal editing/confirmation and accepted content creation remain later stages. Earlier stage acceptance is not inferred.

Use a disposable Collie project/copy. Save any work and quit the previous app process normally, then launch the updated development app using your usual `npm run dev` workflow from the repository. The assistant has not built or launched it. Schema 25 migration uses a retained copy; keep an untouched saved project when exploring older-file migration.

1. **Open a project → Import → select existing files → select Sources & research (and AI chats if desired) → Inspect selected files locally.** Expect protected intake and a local inventory, with no ChatGPT send and no accepted Research rows. In **Sources and notes**, choose **Preview sources and notes**; expect candidate chat counts, source destination groups, usable notes, reference occurrences and retained/unresolved counts. Counts describe proposals, not a promise of new rows.
2. **Expand a source row.** Expect original decision and grade (when supplied), proposed canonical metadata, missing-author/date notices, existing match suggestions and filename/input pointer. Expect grades/snippets to remain unverified. **Open original record** shows the local graph facts and **Open originating message** resolves that specific message when one exists.
3. **Inspect a repeated reference and a rejected reference in existing exports.** Expect a repeated eligible identifier to share a destination group. Different metadata in that group should warn that explicit review is needed. Rejected/search occurrences must stay retained without a destination, even when another message keeps/cites the same source. Page using **Next page**; **First page** returns to the beginning. The detailed graph Relationships view remains available for browsing original decisions.
4. **If the disposable project already contains a matching Research source, inspect that occurrence.** Expect an existing-source suggestion. An ordinary merged source should resolve to its current canonical identity; a removed match should be labeled removed and remain removed. No existing metadata, verification state or source state should change. Do not edit stored databases to construct this scenario.
5. **Change category checkboxes and inspect again.** Expect the old destination preview to be unavailable while choices are unsaved. Chats-only gives zero source/note destinations. Sources-only gives zero visible chat candidates but keeps source origins pointing into retained input messages. Notes-only must not invent Research sources. Each new inspection reflects the protected choices; none accepts content.
6. **Select an existing personal `.txt`, `.md`, or supported JSON note file, enable Notes and inspect.** Expect original wording in the preview, honest imported/unspecified authorship, declared labels if present and explicit format-loss notices. Markdown/HTML remains literal text, images do not load, and foreign links do not attach the note to arbitrary manuscript items. For long text, **Open original record → Read text part → Next text slice** retains the rest. An unsupported body stays retained without a usable-note destination. No assistant-generated sample/fixture is needed.
7. **Dismiss using Keep for later; resume; Save; close normally and reopen the project.** Expect the batch and originals to remain available and the preview to be recomputable. Research, accepted chats, notes and manuscript should contain no additions caused by the preview. Repeat with an ordinary independent project copy if desired; expect origins to stay within the copy's project.
8. **Use keyboard navigation and a narrower window.** Expect named buttons, expandable details, bounded text areas, readable errors/status, and no result from a dismissed/changed preview replacing the current view. Confirm ordinary note creation/editing and manuscript draft/Save behavior remain usable.

Report the action, visible result and any error text. No automated suite, fault injection, database edits, network probe or benchmark is needed. Accepted imported-note editing, imported-source provenance readback/export and atomic writes cannot yet be exercised through the UI; those manual gates remain IM10/IM11. Provider, installed/commercial and broader release gates remain unresolved.
