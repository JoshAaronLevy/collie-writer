# R3-02 — User-owned manual guide

Implementation and required code checks are complete; **awaiting user testing**. No runtime outcomes have been observed by the assistant. Use disposable project copies for source saves, merges/removals, citation changes and AI requests. R3-01 acceptance remains pending; R3-03 images/media are not implemented.

1. **Launch and open chats.** Start your usual development app (`npm run dev`) with the repository's pinned Node, then open imported-only, native-only and mixed chats. Expect complete text in one timeline, user bubbles on the right, assistant bubbles on the left, distinct restrained backgrounds and small readable timestamps. No numbered/imported headings, original-text gates, source lists or Copy/options rows should appear routinely. Date-only records show a date; unknown-zone times retain their original wall time; missing dates have no invented label. Recent labels update while the pane is visible. Selecting a chat afresh still opens its latest content.
2. **Read formatted and long content.** Use existing messages containing headings, nested emphasis/lists, blockquotes, links, inline/fenced code, tables, task lists and footnotes, including content longer than an old excerpt. Expect readable formatting and complete text, with wide tables/code scrolling inside the bubble. Footnotes stay in their own message; ordinary links use the existing external opener. Raw HTML does not execute. Images remain unavailable placeholders for this stage.
3. **Open message options by pointer and keyboard.** Right-click a message, then focus a bubble and press Shift+F10 or the context-menu key. Expect Copy message and, on native turns, View sent context and Copy prompt to composer; reuse is disabled when existing draft/work/state guards require it. Copy should preserve original Markdown. Dismiss the menu with Escape and expect focus on the bubble. Reusing a prompt fills the existing composer without sending it. Source options open their disclosure with focus there; Close sources returns focus to the bubble.
4. **Compare actual Research relationships.** In disposable copies, compare an unlinked imported message, an accepted source link, a merged link and a removed-only link. Expect an icon only for an active linked source, the merged link to reach its canonical destination, and no icon for unknown/removed-only relationships. Open an icon and use Open source or Cite; if more sources are available, More sources/First sources page them. On a native reply with unsaved web references or only possible matches, expect Sources in its context menu without a linked-Research icon. Sources should label unsaved references versus project matches and offer Add to Research. After an explicit save, expect the active link to appear without reopening the project.
5. **Save exact selections and resume review.** In a completed native reply, select a phrase across formatting, a link label, escaped punctuation, an entity, Unicode and multiline code. Expect Save reference for selections whose canonical mapping is known. Inspect the saved quote: it must correspond to the exact original answer slice, including any original Markdown inside the selected range, and exclude generated citation/footnote labels. Ambiguous partial decoded-token selections should offer no Save reference. Cancel reference review and reopen it; expect the retained draft. Use Cite and the existing explicit Apply flow; a cancelled/stale citation target must not alter writing.
6. **Continue a native chat deliberately.** With your own connected account/model, send a message when you intend to use AI. Expect Markdown to update as text arrives and Stop to remain available. Scroll upward while it streams; expect your reading position to stay put. Return to latest and expect following to resume. Inspect an existing failed/interrupted request, if available: its genuine status and recovery actions remain visible. Reading, copying, navigating or opening Sources alone should not start AI.
7. **Check constrained and accessible presentation.** Repeat ordinary reading, table/code navigation and menus with the keyboard, a narrow window, 200% interface zoom, dark/high-contrast modes and reduced motion. Expect accessible authorship and exact-time descriptions, visible focus, contained horizontal overflow and usable source/menu controls. Save and reopen your disposable project; retained messages and Research relationships should remain available.

Report observed results or defects separately from code-check success. Do not run automated suites for this guide.
