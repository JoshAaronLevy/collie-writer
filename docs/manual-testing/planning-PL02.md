# PL02 — Manual Plan walkthrough

Implementation is complete; runtime acceptance is pending. Use disposable project/file copies for structural, history and transfer actions. Preserve the original `.collie`. The assistant has not launched the app or performed these steps.

1. **Keep writing intact.** Launch with `npm run dev`, open a disposable existing project, type a paragraph and leave the cursor within it. Enter **Plan**, then return to **Write**. Expect the same writing and selection; ordinary Undo should still undo the paragraph. Navigation protects local drafts without silently saving the selected `.collie` file. Opening the project should still start in Write.
2. **Find existing material.** Enter Plan and inspect Unplaced, All, type, title and Needs development filters. Expect existing notes, sources, excerpts and chats without reimport. Unplaced means no active chapter/section assignment; topic membership alone does not remove it from Unplaced. Open card details and Open original. Expect the correct Research record, exact excerpt/version or retained chat; Back should return to the retained board. No full source/transcript should be embedded in the grid.
3. **Use the empty path.** In a disposable new project, enter Plan. Expect a short empty message with **Import material** and **Add note**. Add note should open the existing Notes editor with one new ordinary note; save it and return to Plan. Returning to that Notes destination through Back should not create another note. Import material should open the established Submit/summary/Accept flow; only explicitly accepted findings should appear, with no automatic chapter assignment.
4. **Collect a topic.** Add a topic, select several material cards and choose that topic under Destination → Add to. Repeat by dragging a card from the Material rail to the topic. Expect one reference per original, with no copied bodies. Add the same item to another topic and chapter; other uses should remain. Rename/reorder topics using their actions and earlier/later controls.
5. **Make a real chapter.** On the topic, choose **Make chapter** (or Make section for an article/report). Expect an empty actual outline item with the topic’s name and references; the superseded topic should disappear. Other topics/material should remain. Edit the new item’s title/purpose and reorder it through arrow controls or sibling-card dragging. Write should show the same name/order. Existing prose should remain intact, and returning to Plan should keep its board selection.
6. **Share and move deliberately.** Link one item to two chapters. Open the first chapter’s contents, select the item and Add to another destination; expect another reference. Use Move to or drag its direct assignment onto another chapter; expect only the first chapter’s link to be removed. Remove from chapter should preserve other chapter/topic links and the original. Dragging a card from the Material rail should always add a reference, even when that card is already used elsewhere. Expect a destination-specific status announcement and useful focus after each action.
7. **Check nested scope.** Open an existing part/chapter’s sections through Show sections and breadcrumbs. Select a nested section. Expect its direct material first, followed by labeled inherited parent material without duplicate cards. An inherited entry should not offer to move/remove a direct child assignment until it has one. Changing an item in Write’s outline should appear in Plan through the same document identity.
8. **Develop and set aside.** Mark an item Needs development with an optional reason, then assign it to a chapter. Expect it to remain usable and labeled. Set it aside: expect it to leave the ordinary pool while its original and assignments remain. Find it under Set aside, or Show set-aside material in the selected group; Write → Chapter material should retain it in its expandable set-aside group. Restore to Keep: expect ordinary planning availability. Citation text, source verification and question/evidence decisions should not change.
9. **Check drafts and access.** Edit a topic/title/purpose/reason dialog and try to leave or Save the project before finishing it. Expect Save/Cancel protection for the unfinished form. If a genuine storage/acknowledgment issue produces Check change, use it to resolve the recorded outcome before retrying; it should not dispatch AI or silently apply another mutation. In a read-only project, expect saved topics/material/original access, with organization controls disabled.
10. **Check saved history on a disposable copy.** Keep a named version with a topic and development/set-aside status. Convert the topic and change metadata, then restore the named version. Expect its writing/outline, references, topics and editorial status to return; the newer state should be retained as the pre-restore version. If a PL01-only version is available, restoring it should leave current topics/dispositions intact. An older pre-39 version should retain current links as well. Research bodies/originals must not be replaced by manuscript history.
11. **Save and transfer.** Save the disposable `.collie`, close/reopen, then use an independent copy and Backup/Restore with disposable destinations. Expect topics, order, dispositions, references and saved planning history to survive. Change a topic/link in the independent copy: the original should stay independent. Repeat local planning with ChatGPT disconnected; opening Plan or moving cards should not send a request.
12. **Use keyboard and narrow layouts.** Repeat selection, Add/Move/Remove, topic conversion and chapter ordering using keyboard controls. Use a collection with more than 20 entries to exercise material, group contents and structure pages. Resize narrowly and use 200% zoom: Material, Structure and Details should be reachable one at a time, with contained content, visible focus and readable controls. Change filters/chapters while reads finish; expect no old-project results. Return from originals and reopen Plan: local pane/filter/page/scroll hints should remain useful. Existing manuscript and unsent chat drafts should remain retained.

Report observed results separately from the passed format/lint/typecheck commands. Planning AI, actionable outline proposals, passage capture and prose insertion remain later stages; this guide does not ask you to run an automated suite.
