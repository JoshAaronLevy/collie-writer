Save and local recovery correction complete. As a user:

Use disposable projects and a disposable folder for the file replacement steps. Follow the pinned Node/npm setup in README and launch the updated development app yourself with `npm run dev`. Preserve any important writing in your currently running older app before restarting it.

1. When I create a disposable project, type a sentence in a chapter and click **Save**, the native Save dialog opens. Cancelling leaves the writing visible and no destination selected. Clicking Save again and choosing a new `.collie` filename saves to that location.
2. When I edit the chapter and click **Save** again (or press **Command+S** on macOS), the same file updates without requiring a different filename. **Inspect saved file → Open independent copy** shows the text captured by that Save. Return to the original from Projects afterward.
3. When I make another edit and leave it idle for more than 30 seconds, the app reports local protection and **Unsaved changes**. The selected file does not update. Inspecting an independent copy of that file still shows the last manually saved text; return to the original to see the newer local text.
4. When I type another sentence and quit normally without Save, the app protects local writing and closes without asking to save the selected file. Relaunching restores the local chapter and sentence, still marked unsaved. Clicking Save then updates the same selected file.
5. When I create another disposable project, type without ever choosing a file and quit normally, reopening restores the project and writing without a destination. Its first Save still opens the native picker.
6. When I duplicate the disposable saved file in Finder, then replace the assigned file with that identical copy under its original name, returning to Collie does not label identical contents as a conflict. Editing and Save still work at that path. Perform this replacement only while no file operation is running.
7. When I keep a Finder copy of an older disposable saved version, save a newer version, and then replace the assigned file with that older copy, Collie keeps the newer local writing. Its file notice explains that Save writes local work. Clicking Save succeeds at the same path; inspecting an independent copy shows the newer local writing. In **Settings → Data and recovery**, refreshing and inspecting the corresponding retained previous version opens the older writing as a separate project.
8. When I remove only the disposable selected file in Finder while leaving its folder available, Save recreates it with the local writing. If instead I make the folder unavailable, Save reports the unavailable destination; normal quit and reopen still preserve locally protected writing, and Save As can select an available folder.
9. When an explicit form draft or unfinished operation blocks closing, the existing notice keeps the app open and offers a path back to that draft. Resolving it and quitting closes without forcing a project-file Save. Do not use force quit to exercise this step.
