# AC01 user walkthrough

Use an editable disposable project and synthetic writing. These are user-owned observations; no assistant runtime acceptance is recorded. AC01 still uses the existing explicit review and manual history-selection flow. Automatic history, single Send, restart draft recovery and source saving belong to later stages.

1. In the repository, use the pinned Node 24.21.0/npm 11.19.0 toolchain and launch `npm run dev` yourself. On this Mac, the pinned binaries are under `.tools/node-v24.21.0-darwin-arm64/bin`; put that directory first on your terminal's PATH. **Expected:** ordinary startup stays quiet, with no forced sign-in dialog or submitted conversation request.
2. Open **Manage ChatGPT** from the ChatGPT control or Settings. Connect/reconnect your own saved account when needed and finish the browser consent flow. **Expected:** the selected account is shown and its model setup finishes or reports an actionable problem. Sign-in alone is not an accepted AI-response result.
3. Expand **Connection details**. **Expected:** Conversations has its own availability. Web research says it is not enabled in Collie and that account/model browsing support has not been confirmed. Loading models or receiving a text answer must not turn that into confirmed web access.
4. Open the disposable project's **Write → AI → New chat**. Type “Suggest three chapter titles for a short nonfiction book about urban gardens.” Choose **Review request**, inspect the exact prompt/context/account/model, then **Send reviewed request** once. **Expected:** actual text arrives, the request reaches a genuine completed outcome, and its local saving/protection status settles. An unavailable button, a failed/incomplete outcome or partial text does not pass this step. If denied, retain the safe stage/status/code/request reference from Connection details and report it; do not share credentials.
5. Return to the conversation list, reopen that chat and inspect the saved answer. For a follow-up, select the relevant previous messages using the existing checkboxes, then review/send “Which title best suits a beginner audience?” **Expected:** review shows only selected history and the new answer remains in that same chat. This exercises existing continuation; automatic context is not yet implemented.
6. After all AI work and local protection have settled, use **Manage ChatGPT → Manage account → Disconnect**, confirming the selected account. Reopen the chat, then close/reopen the project normally. **Expected:** its saved messages remain readable, new provider sending requires a connection, and no saved request resends. If remote revocation is unconfirmed, the dialog says so.
7. If you have another permitted account/model, select it explicitly and reopen Connection details before a new review. **Expected:** the displayed text availability belongs to the new selection; web eligibility remains unconfirmed. Keyboard focus and dialog dismissal should remain usable at your normal and narrow window sizes.

Report naturally encountered catalog, expiry, interruption or provider-refusal cases; do not manufacture them by editing credentials or injecting failures. A model refusal requires an explicit replacement choice. A route/fixed-capability refusal pauses new requests for that account in this app session and keeps the safe diagnostic after model refresh. Such a refusal needs an integration correction, not repeated sign-in or a restart workaround. Still-valid access must not require reauthorization merely because renewal is too early. Native rotation timing remains unobserved until encountered.

Report which steps succeeded, the selected model, whether a real response completed and remained saved, and any safe diagnostic reference. Installed commercial use and web research remain separate blocked milestones; this guide does not accept them.
