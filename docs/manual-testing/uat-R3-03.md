# R3-03 — User-owned manual guide

Implementation and required format/lint/typecheck work are complete; **awaiting user testing**. The assistant has not launched or exercised the app. Use disposable project copies and your own existing media/export files. Earlier R3 acceptance remains pending.

1. **Launch and read public images.** Run your usual development launch (`npm run dev`) with the pinned Node, open a copied project and select a chat containing public HTTPS Markdown images or direct image-file links. Expect images to appear automatically, with no Read/Load or consent step. Several images should coexist; useful alt/unavailable text should remain if one fails. Surrounding Markdown and link labels stay readable. Reading the chat must not send AI or add Research.
2. **Play direct media and compare links.** Open existing direct MP3/WAV/Ogg/MP4/WebM references, and use Play, Pause, seeking, volume and available native controls. Expect contained inline players, no autoplay, and playback only after you choose it. Browser codec support still applies. PDFs and hosted players such as YouTube should remain ordinary links using the existing external-opening flow.
3. **Retain local media deliberately.** In a disposable project, import a supported chat export whose message Markdown references exact filenames, selecting the corresponding supported image/audio/video files in that same import. Keep optional instructions empty for this binary-media case; select Chats, Submit and explicitly Accept through the existing flow. Expect referenced bytes to render without a disk-path grant. Unreferenced selected media remains an original, not a new source/note. Missing filenames, duplicate ambiguous filenames and provider-only attachment pointers should show unavailable media, not unrelated content. Canonical base64 data URLs and supported retained `content.parts` can also supply local bytes; a text-only export cannot recreate missing attachments.
4. **Read upward during loading.** In a long chat/message, scroll above the latest content while images or player metadata settle, including text below an image in the same message. Expect your visible reading position to remain stable. Return to latest and expect bottom following to resume. A native assistant's media should appear once its completed reply is retained; Stop and streaming text remain available while it runs.
5. **Check offline and portability.** Save your disposable `.collie` project, close/reopen it offline and read retained media. Expect local images and compatible players to remain available, while remote-only content may show unavailable. Reconnect and reopen the chat to reload public media. Create an independent copy and perform Backup/Restore using disposable destinations; retained message/media relationships should survive without the original source-file location or another project's grants. Remote viewing alone must not retain downloaded media in the portable project.
6. **Check fallback and scope changes.** Read existing messages with missing, unsupported, oversized or inaccessible media; expect a short fallback and readable text. If your own sample contains local/private-network URLs or HTML masquerading as an image, expect refusal. Switch projects or close/reopen the window while a slow asset is loading; expect no old-project media to appear in the new view. No failure-injection tooling is needed.
7. **Check Research and accessibility.** Open Research's existing PDF/text inspector while chat media is available; expect both to remain usable without revoking each other's reading grants. Repeat keyboard navigation and playback controls at narrow width, 200% zoom, dark/high-contrast modes and reduced motion. Expect contained sizing, useful labels and visible focus. Select text around an inline media item and save a reference: media/loading/citation labels must not become quote text.

Supported formats, byte/reference limits, filename rules and pending runtime gates are documented in the [implementation record](../validation/uat-R3-03.md). Report observed results or defects separately from code-check success; no automated suite is part of this guide.
