# PL04 — User walkthrough

Implementation and code checks are complete; runtime acceptance is pending. Perform these actions yourself. Use disposable projects/copies, especially for migration and recovery.

1. Launch with your usual `npm run dev` setup and open a disposable project containing notes, research and native/imported chats. Switch to Plan, open ChatGPT and create a chat. Expect one composer, **Using: Project material**, and Search the web off. Opening Plan should send nothing.
2. Select a few cards and choose Discuss; repeat with a topic and a chapter. Expect the visible scope to change. Use Change before sending an ordinary question. With an eligible own-account connection/model selected, expect a saved answer labeled as a passage selection, with inspectable originals. Hidden editor text should not appear in View sent context.
3. Type an unsent message, open a material detail, return to Chat, and switch Write/Plan. Expect the selected chat and unsent text to remain. Repeat at a narrow width/200% zoom and using the keyboard; Material, Structure, Details and Chat should be reachable without simultaneous columns.
4. Use a disposable collection with several long chats/notes, including older material, and choose Find themes or Suggest an outline. Expect the multi-request notice before Send, sequential progress, Stop and explicit coverage. Inspect original range links, including a later passage in a long chat. An outline response should remain discussion; chapters and prose should not change.
5. Stop while preparation is running, wait for its retained outcome, Save and close normally. Reopen and inspect progress. Expect no automatic requests. Choose Continue explicitly: completed matching batches should be reused, and unfinished work should advance or show the actual blocker. More than ten unfinished batches should require another explicit Continue after the bounded response.
6. Change a previously analyzed note, set an item aside, or change a scope assignment. Expect the old response to remain readable and its analysis to be marked changed. A fresh Send should use current inputs; changed prefixes must not be presented as current. Unreadable, incomplete or hard-limit omissions should stay disclosed. Restore a set-aside item to make it available again.
7. From a chapter/topic discussion, explicitly enable Search the web and request evidence. Choose Add to Research for a candidate. Expect ordinary metadata/duplicate review and a visible Add to chapter/topic choice. Save with that choice selected: expect one Research source and its group association, with verification remaining unchecked unless you explicitly checked it. Open its original response provenance and its Plan card.
8. On a completed answer of at most 20,000 characters, choose Save as note. Expect an editable note with its unchanged assistant quotation and Open original exchange. For longer answers, select a passage and Keep passage. Select a short unresolved question in an answer and choose Save as question; expect an editable Research question draft that is committed only by Save.
9. Save, then open an independent disposable copy. Expect the board, conversations, analysis progress, originals, notes and source associations to remain available. No copied request should dispatch itself. Disconnect AI and confirm that local organization, original reading and writing remain usable; sending should show the actual connection/capability remedy.

Report the step, observed behavior and any visible error. Do not treat an AI summary as a verified source, or successful code checks as runtime acceptance. PL05 outline application and PL06 writing insertion are not implemented here.
