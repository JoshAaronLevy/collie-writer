# R3-01 — Direct conversation reading

October 12, 2026. Implementation complete — awaiting user testing. These steps are for Josh; no assistant runtime checks have been performed.

Use disposable copies of projects containing accepted imported history, native replies, and imported Research links. Include a chat with more than 20 imported messages, a mixed chat with several pages of native replies, and an imported message longer than 8,000 characters where available. Keep originals separate. Run `npm run dev` yourself from the repository and open the disposable project.

1. Select an imported conversation title. Its latest messages appear directly, followed by any automatically loaded remaining text. The view settles at the newest message; there is no Read/Find screen, original-text button, or origin/variant panel. Repeat with a native-only chat and with the same title after returning to the list: each fresh selection starts at the latest message.
2. Read a long imported message through its ending. Text beyond the old excerpt and slice limits arrives automatically in the same message. Scroll upward while text is loading: your visible message and position stay put. A genuine read failure shows a short explanation and Retry; it does not claim the excerpt is complete. Switching chats during a read must not bring the old chat's text into the new one.
3. In the long imported chat, use Load earlier messages several times, then Load later messages or Jump to latest. The window stays readable, preserves the current reading position when loading adjacent messages, and shows each message once in stored order. Jump to latest reloads the tail. In the mixed chat, page upward through native replies to the imported prefix: the transition has no duplicate native replies or missing displayed interval.
4. In Research or Notes, expand an item's Imported origins, read its origins, and choose Open original message. The ordinary chat pane opens that exact imported message, including its full text. Use a saved native response/recovery link as well: it opens the requested response. Return to writing and confirm an unsent writing/chat draft is retained. If a message has Linked Research, use it to open its existing source.
5. Open an active chat. Search the web starts checked. Uncheck it, open another chat, and return: the first chat stays unchecked during this project session. A previously untouched chat starts checked. Toggling alone never sends a request. With search unavailable, the adjacent explanation identifies the connection/route blocker; unchecking allows text-only Send when ordinary chat is otherwise available. An existing failed research request's Try without web search still copies an unchecked draft without sending it.
6. Use Chat options → Archived conversations, open an archived chat, and read/export it. Restore a disposable archived chat where editing is allowed, then return to Chat options → Active conversations to find it. Search and history and Find are absent; archive/restore/export remain accessible by keyboard.
7. If you choose to send a message using your own connected account, read the incoming reply at the bottom, scroll upward, then choose Jump to latest. Text growth follows only while you are at the latest position; reading upward stays anchored. Stop and any genuine failure/recovery actions remain available. Sending from an older imported window returns to the new native reply.

The current body uses the existing basic Markdown renderer. Bubble styling, friendly timestamps, conditional Research icons and contextual message actions belong to R3-02. Images and audio/video belong to R3-03. Neither later stage is implemented here. Reading/opening does not run AI, reimport content, or Accept anything.

Record observed results and any failing step before proceeding to R3-02.
