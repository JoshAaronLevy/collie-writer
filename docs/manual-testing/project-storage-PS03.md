# PS03 manual guide — Storage notices and space explanations

**Implementation complete — awaiting user testing.** Format, lint and node/web typecheck passed without warnings/errors; runtime acceptance is pending. The user owns the actions below. Use genuine disposable project copies for Save/Backup observations. Do not fill a disk, generate large data, change thresholds or manufacture failures to produce a notice. Leave naturally unavailable cases pending.

Stage PS03 complete. As a user:

1. When I start development with `npm run dev`, open an ordinary disposable project and go to **Settings → Data and recovery → Measure storage**, the inventory still shows distinct working/application/external file lengths, and **Available volume space** shows timestamped available/total capacity or explicit unknowns. Each volume's location and category labels make the working and destination volumes distinguishable. Reporting does not open a Save picker or run AI.
2. When I read **Storage notices**, the defaults are explained separately from operation checks. An ordinary project below size thresholds produces no size notice; a genuinely low-space volume can have a notice even for a small project. Returning to Write preserves my editor and input, without repeated scans, dialogs or focus changes while typing. Any active notices have a passive workspace link back to Data and recovery.
3. If naturally accumulated data crosses a threshold, when I choose **Review breakdown** or **Review volume**, it opens the appropriate project page/disclosure/search row or volume reading, with locations and measured sizes. A project on another inventory page still has advice based on the whole scan. No erase/clear-cache button appears, and recorded backups/unclassified content retain their separate meanings.
4. If a real notice exists, when I **Snooze for 24 hours** or **Dismiss notice**, that condition disappears from active presentation and the hidden-condition count changes. **Show dismissed and snoozed notices** restores it. Refreshing above the threshold does not undo an unexpired choice. After reopening and measuring again, valid saved choices remain effective; a failed preference write is visibly reported and preserves the session choice. Snooze expiry and 30-day idle expiry may be left pending until naturally observable.
5. If measured storage naturally recovers, when I refresh, size advice clears only below 80% with a complete known reading, and low-volume advice clears at 125%. Small fluctuations, partial results and unknown capacity do not declare the condition resolved or imply enough space. Do not delete project content or recovery material to produce this observation.
6. When I refresh/cancel an inventory or leave Data and recovery while it runs, partial results remain honest, the retained editor remains usable, and notices still refer to the last available ended/partial measurement. No background scan starts while I type. Keyboard review focus stays within the visible Data region and does not jump behind an open dialog or during composition; narrow-window tables and long locations remain readable.
7. When I use the existing **Project file actions → Save As** or **Backup** on a disposable project with ordinary available space, its native picker, progress and retained-copy behavior remain available. Reopening retains locally protected work and its actual unsaved status; ordinary close does not perform selected-file Save. Moving the destination to another volume still requires local working-folder space.
8. Only if a real space/capacity/write failure naturally occurs, when I read the file/operation/export error, it identifies the operation and location to review, shows the additional estimate including margin and available/reserved bytes when known, and says unknown when not known. Preflight failure identifies the checked folder; a later write with no supplied path does not claim a confirmed failing volume. Existing exact retries, reports, candidates and live input remain available, with storage/recovery links. Keep the window open if input still needs protection. Restoring space does not automatically retry or override close guards. Leave concurrent-job rejection and failure/unknown-capacity observations unverified if they do not occur.

Report the notice kind, scan state, displayed location, navigation/focus outcome and any unexpected Save/recovery behavior. Never send credentials or project contents merely to report a storage notice. No runtime, native, capacity/concurrency, accessibility or performance acceptance has been recorded. Release remains **NO-GO**. Stop at PS03; PS04 and later storage/import work require a new request.
