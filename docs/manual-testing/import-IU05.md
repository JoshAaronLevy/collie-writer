1. Relaunch the updated app normally and let the background connection setup finish. With your saved healthy account/model, expect a connected indicator and no connection warning. If a real connection or saved-account issue is reported, expect a visible global notice with the reason and next action before opening Import.
2. Open Import in a disposable writable project, choose the same supported file and categories, and confirm the model. When no other AI work/recovery is pending, expect Submit to be enabled without reconnecting. Submit once; expect preparation/analysis to begin. Live completion/extraction remain to be observed.
3. If a blocker naturally appears, expect a specific explanation: Check status for an unconfirmed status, model guidance beside the selector, Manage ChatGPT for account setup, or directions to AI work for pending responses/local recovery. After the indicated condition clears, expect availability to update without losing the form. Do not disconnect an account or manufacture an error to exercise this step.

## Complete revised flow

1. **Launch and open Import.** Launch the updated app through your normal local workflow (`npm run dev` for the development checkout) and open a disposable writable project. Click Import. Expect a compact modal with selected files, AI conversations/Sources/Notes, optional instructions, the connected account's model dropdown and Cancel/Submit. A fresh form has no categories checked. If disconnected, Connect ChatGPT should transfer to the existing account dialog; reopen Import afterward and expect preserved choices.
2. **Choose files and Submit.** Add one small supported conversation file or file set, select AI conversations and Sources, optionally add instructions, and choose an available model. Adding more files should accumulate them; removing a file should remove only its selected row. Canceling the native picker should leave the existing form intact. With files and a category selected and ChatGPT ready, Submit should begin in-place preparation/analysis without another consent, preview, budget or individual-item screen. No accepted project content should appear yet.
3. **Read the summary, then Cancel.** Expect Ready to import, actual conversation totals/titles/message counts and source totals, with only a short relevant omission notice. Re-Analyze should show Coming later and do nothing. Cancel, the close icon or Escape should return to the populated setup. After a healthy full result, expect no routine recovery button row; unchanged Submit should show the same findings without another ChatGPT analysis. Account/model preference changes preserve saved findings and do not trigger analysis themselves.
4. **Accept and inspect ordinary content.** Accept the usable summary once. Expect Importing, then dialog closure and a brief dismissible success notice, with no extra report or forced navigation. Open ordinary Chats: use Read / Find original history, then Read transcript to inspect imported messages; use Linked Research to follow supported source links. In Research, use Imported origins and its read/open-original actions where available. The manuscript and unrelated drafts should remain intact. An explicit follow-up through the ordinary chat composer should create a normal new response, not rerun import.
5. **Try the other category combinations.** In separate disposable selections, import Sources only and Notes only using suitable real files. Expect only the chosen destinations. Source-only imports retain supported origin references without creating unchecked chats; references without an accepted conversation need not have an Open original message link. Notes should preserve literal text/labels and remain editable through the normal Notes editor/Save note action. If all material is already present or none is usable, expect a concise result and disabled Accept, not a new-import success notice.
6. **Cancel and resume normally.** During an ordinary analysis click Cancel once. Expect Stopping, then the populated form with protected findings retained. View available results should show usable saved findings when offered. Continue analysis should send only never-attempted work after your click. If an outcome naturally needs attention, use the offered Check status, Finish recovery or Try saving again: expect local recovery without an automatic ChatGPT resend. Start new import, when offered for settled recovery, should start a fresh form while retaining prior originals/history. Do not manufacture failures.
7. **Save and reopen.** Use ordinary project Save, then close/reopen the disposable project. Expect accepted content to persist. With an older unfinished import copy, expect the same compact form/saved summary or contextual recovery, preserved older decisions and no automatic analysis/acceptance. Valid protected older findings can prepare locally through View available results. An independent copy should retain content but no copied execution grant. Naturally encountered uncertain acceptance should reconcile its exact command without duplicates. Acceptance itself does not Save the selected project file.
8. **Judge the layout and keyboard experience.** With long filenames/titles, a narrow window and 200% zoom, expect wrapped text, one scrolling import body and reachable footer actions. Use Tab/Shift+Tab, file removal, Enter/Space on buttons and Escape; expect focus to stay in the dialog and return sensibly after processing/results/cancellation/closure. Enter while composing instructions must not submit. With reduced motion enabled, expect no processing spinner or dialog animation. If you use a screen reader, expect progress, errors and complete requested-category totals to be announced without duplicate progress announcements. Report actual appearance/focus/announcement problems.

Report any unnecessary step, missing material, incorrect count, duplicate content, lost relationship or inaccessible control. Active Re-Analyze and file reformatting remain future work; real omissions will guide extraction improvements.
