**Implementation complete — awaiting user testing.** This is the consolidated acceptance walkthrough for IU01–IU05. The assistant ran only format/lint/typecheck, not runtime testing. Use real files and disposable project copies, especially for older-project migration and Save. No fault injection or automated suite is needed.

## Connected-account Submit fix: focused retest

If a real connection or saved-account issue is reported, expect a visible global notice with the reason and next action before opening Import.
2. Open Import in a disposable writable project, choose the same supported file and categories, and confirm the model. ## Complete revised flow

1. **Launch and open Import.** Launch the updated app through your normal local workflow (`npm run dev` for the development checkout) and open a disposable writable project. Click Import. Expect a compact modal with selected files, AI conversations/Sources/Notes, optional instructions, the connected account's model dropdown and Cancel/Submit. A fresh form has no categories checked. If disconnected, Connect ChatGPT should transfer to the existing account dialog; reopen Import afterward and expect preserved choices.
2. **Choose files and Submit.** Add one small supported conversation file or file set, select AI conversations and Sources, optionally add instructions, and choose an available model. Adding more files should accumulate them; removing a file should remove only its selected row. Canceling the native picker should leave the existing form intact. With files and a category selected and ChatGPT ready, Submit should begin in-place preparation/analysis without another consent, preview, budget or individual-item screen. No accepted project content should appear yet.
3. **Read the summary, then Cancel.** Expect Ready to import, actual conversation totals/titles/message counts and source totals, with only a short relevant omission notice. Re-Analyze should show Coming later and do nothing. Cancel, the close icon or Escape should return to the populated setup. After a healthy full result, expect no routine recovery button row; unchanged Submit should show the same findings without another ChatGPT analysis. Account/model preference changes preserve saved findings and do not trigger analysis themselves.
4. **Accept and inspect ordinary content.** Accept the usable summary once. Expect Importing, then dialog closure and a brief dismissible success notice, with no extra report or forced navigation. Open ordinary Chats: use Read / Find original history, then Read transcript to inspect imported messages; use Linked Research to follow supported source links. In Research, use Imported origins and its read/open-original actions where available. The manuscript and unrelated drafts should remain intact. An explicit follow-up through the ordinary chat composer should create a normal new response, not rerun import.
5. **Try the other category combinations.** In separate disposable selections, import Sources only and Notes only using suitable real files. Expect only the chosen destinations. Source-only imports retain supported origin references without creating unchecked chats; references without an accepted conversation need not have an Open original message link. Notes should preserve literal text/labels and remain editable through the normal Notes editor/Save note action. If all material is already present or none is usable, expect a concise result and disabled Accept, not a new-import success notice.
6. **Cancel and resume normally.** During an ordinary analysis click Cancel once. Expect Stopping, then the populated form with protected findings retained. View available results should show usable saved findings when offered. Continue analysis should send only never-attempted work after your click. If an outcome naturally needs attention, use the offered Check status, Finish recovery or Try saving again: expect local recovery without an automatic ChatGPT resend. Start new import, when offered for settled recovery, should start a fresh form while retaining prior originals/history. Do not manufacture failures.
7. **Save and reopen.** Use ordinary project Save, then close/reopen the disposable project. Expect accepted content to persist. With an older unfinished import copy, expect the same compact form/saved summary or contextual recovery, preserved older decisions and no automatic analysis/acceptance. Valid protected older findings can prepare locally through View available results. An independent copy should retain content but no copied execution grant. Naturally encountered uncertain acceptance should reconcile its exact command without duplicates. Acceptance itself does not Save the selected project file.
8. **Judge the layout and keyboard experience.** With long filenames/titles, a narrow window and 200% zoom, expect wrapped text, one scrolling import body and reachable footer actions. Use Tab/Shift+Tab, file removal, Enter/Space on buttons and Escape; expect focus to stay in the dialog and return sensibly after processing/results/cancellation/closure. Enter while composing instructions must not submit. With reduced motion enabled, expect no processing spinner or dialog animation. If you use a screen reader, expect progress, errors and complete requested-category totals to be announced without duplicate progress announcements. Report actual appearance/focus/announcement problems.

Report any unnecessary step, missing material, incorrect count, duplicate content, lost relationship or inaccessible control. Active Re-Analyze and file reformatting remain future work; real omissions will guide extraction improvements. The [acceptance record](../validation/import-IU05.md) keeps clean code checks separate from these still-pending observations and broader release gates.

## Larger conversation file: focused retest

1. Launch the updated checkout through your normal local workflow (`npm run dev`), open a disposable project copy and reopen Import with `cultural-analysis.conversation.json`. Select AI conversations and Sources, then Submit. Expect automatic preparation and sequential analysis without the former 64-request “too large” refusal or any manual file-splitting step. Larger imports can take longer and use more of your connected account's allowance; the app should remain in its existing processing UI.
2. Let analysis finish normally. Expect the short summary, then Accept. In ordinary Chats and Research, inspect original messages and supported source origins. Counts and extraction quality are observations to report, not assumed from file size. The original file should remain unchanged.
3. If you choose Cancel during ordinary analysis, expect stopping and retained results. Explicit Continue analysis should send only never-attempted remaining work; reopening alone must not send requests. If an account or storage limit naturally interrupts processing, expect retained findings and contextual recovery, not a false completion claim.
4. Only if a real selection naturally exceeds the full analysis limit, expect a message naming 1,024 requests, explaining that text/metadata/links determine fit and that no analysis was sent. The guidance should recommend fewer files, complete conversation exports with their sources, or valid ordered message-group exports for one very long conversation. Do not manufacture a huge fixture. The separate native file limits remain 25 MiB per file, 100 MiB per selection and 100 retained files; meeting those limits alone does not guarantee analysis/storage/account capacity.

## Stopped import and Save: focused recovery retest

1. Relaunch the updated checkout through your usual workflow (`npm run dev` for development). Open a disposable copy of the affected project. Use Return to import on its operation notice, or the ordinary Import button after reopening. Expect the populated import modal, not project details. Opening must not send another analysis request.
2. Read the retained status or click Check status. Expect the available specific failure category and next action. If it reports zero usable findings, do not expect new Chats/Sources; project Save alone does not accept an import. Report the exact message shown here so an unknown provider/format failure can be addressed based on evidence.
3. If Finish recovery or Try saving again is offered, use it and expect local settlement without a resend. If Continue analysis is available after recovery/account readiness, click it to analyze unread material only. It must not silently retry a failed response. If no material remains or you want to retry the entire input, Start new import begins a fresh explicit selection while keeping older originals/history.
4. When usable results exist, View available results should show the short summary. Accept should add the counted material and close Import. Inspect ordinary Chats and Research for accepted content and supported links. Report missing items or a failed/empty result; no particular extraction count is assumed.
5. After analysis/recovery is settled, choose Save As in the disposable copy. Expect the existing filename if assigned, otherwise a filename derived from the project title. Choose a new location, let Save finish, and expect saved status if no newer edits/import changes occurred. Save again only if there are genuinely newer changes. Close/reopen that saved file; accepted items should persist, while an unaccepted import should remain recoverable through Import.

Keep the original affected project. A larger archive can contain protected originals and intermediate analysis even when nothing has been accepted; do not delete working data to reduce it.

## Context-changed rejection: fresh-import retest

1. Relaunch the updated checkout through your normal workflow (`npm run dev` for development). Open Import in a disposable project copy. Choose **Start new import** for the stopped selection, then add the same original file again. This retains old history but starts a fresh analysis of all selected content; Continue skips the parts previously rejected by the app and is not the full-file retry for this defect.
2. Select AI conversations/Sources and one available model, then Submit once. Expect processing to pass the former immediate context-changed rejection. No account reconnection or model cycling should be necessary just to pass the corrected template check. If another failure occurs, report its exact message.
3. If analysis finishes with usable findings, expect Ready to import. Accept, inspect ordinary Chats/Research, then Save. The summary/Accept result and extraction quality remain user-owned observations; source checks do not establish their success.

## Rejected response format: fresh-import retest

1. Relaunch the updated checkout through your usual workflow (`npm run dev` for development), and open a disposable copy of the affected project. Open its retained Import summary. If it still has zero findings after a failed response, expect Import summary and an explanation that analysis failed to produce usable findings, rather than a claim that the file contains no content. Accept stays disabled. Opening alone must not send requests.
2. Cancel back to setup and choose **Start new import**, then add the same conversation JSON, select AI conversations and Sources, select Sol 6.1, and Submit once. Expect a fresh analysis using corrected field instructions without file splitting or per-message review. Continue analysis is not the full-file retry: it skips the already-rejected response. Old originals/history remain retained.
3. Let analysis finish. With usable findings, expect the conversation/message counts and source total, then an enabled Accept. Accept should close the modal and make those findings available in ordinary Chats/Research. Inspect the imported content and supported relationships. Report any remaining error or empty summary; successful provider output is not yet established.
4. Save the disposable project, close and reopen it. Expect accepted findings to persist; reopening must not resend analysis. Keep the original affected project.

## Analysis progress: focused retest

1. Let any current import finish, or Cancel and wait for stopping/local recovery to settle. Relaunch the updated checkout through your usual workflow (`npm run dev` for development). Use a disposable project copy for a new import; do not retry a successful import solely to obtain progress telemetry.
2. Submit selected files/categories with an available model. After preparation, expect a progress bar and completed/total request count. While a request is active, expect waiting or receiving-response activity, response character count when text arrives, and elapsed time for that request. The count/bar advances only when a valid result has been saved. A model can think before sending text, and requests may take different amounts of time; the display must not invent a smooth percentage or ETA.
3. If you choose Cancel, expect stopping and retained findings, with no further requests dispatched. Any already-sent request may already have consumed usage. Reopening alone must not restart inference. Continue remains an explicit action for unread material.
4. On normal completion, expect the existing short summary and Accept flow. At narrow width/200% zoom or with reduced motion, expect readable progress and reachable Cancel, with no progress animation. A screen reader should announce request completions, not every character/time update. Account allowance remains available through your provider's usage dashboard, not this progress bar.
