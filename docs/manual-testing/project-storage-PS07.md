# PS07 manual guide — Inactive local working copies

**Implementation complete — awaiting user testing.** Required code checks do not establish runtime acceptance. See the [record](../validation/project-storage-PS07.md) and [eligibility, records and limitations](../formats/working-copy-removal-v3.md). Use disposable projects and ordinary operations only. Do not edit internal records, manufacture leftovers, interrupt writes, fill disks or run automated suites.

Stage PS07 complete. As a user:

1. When I run `npm run dev`, create a fresh disposable project A, add ordinary writing/research/citations and Save it to an accessible `.collie` file, the existing Save controls work normally. I keep that file and may make a separate Backup. I use a project without AI history, migration originals or prior cleanup actions for the eligible path.
2. When I open another project B and visit **Settings → Data and recovery → Remove local working copy**, I can select inactive A. B is excluded. Review shows A's saved-file path, original working folder, verified removal size/file count and metadata that remains. Review itself removes nothing. If it refuses eligibility, I follow its explanation and leave removal acceptance pending rather than altering internals.
3. When I choose **Cancel review**, no content is removed. A fresh review requires a new confirmation. Merely choosing a project, navigating, starting the app or seeing a size notice never removes anything.
4. When I review A again, acknowledge the checkbox and choose **Remove local working copy**, the result reports confirmed removed file counts/lengths and explains retained records. A leaves the local project library; small original metadata/empty folders remain, and the saved `.collie` and Backup are unchanged. Inventory/recovery refresh while Data is visible; file length is not a promise of an identical disk-space gain.
5. When I choose **Show removal history**, A's original outcome and saved-file reminder remain visible. **Open project file…** asks me to select the file through the normal picker and shows the existing validated-file choice. When I choose **Open project**, it creates a new local workspace for that saved project. My saved writing, research, citations, managed files and project history return. Search reconstructs locally when used. Editing follows the existing access/designation controls; removal grants no additional access.
6. When I restart normally after confirmed completion, the old removed scope stays out of the library and its removal history remains. The newly opened local copy behaves normally. Reopening a file never automatically deletes the retained metadata skeleton or repeats the old removal.
7. When I review a disposable never-saved project, removal is unavailable with Save guidance. When I make ordinary local edits after Save, switch away and review that project, it refuses until those edits are saved. When I select a naturally AI-linked project, it refuses to remove the original workspace; original conversation/output recovery remains available.
8. On disposable data only, when I rename or move its external saved `.collie` in Finder/Explorer while Collie is idle, the next removal review refuses the unavailable destination. Restoring its original location permits a fresh review if all other proof remains valid. If a review expires or ordinary project activity changes its proof, confirmation refuses stale removal and offers outcome checking before another review.
9. Only if a real busy job, lost reply or interruption occurs naturally, I use **Check outcome**. It reads the original receipt and never repeats deletion. An incomplete result states what is confirmed and leaves remaining files protected. I leave timeouts, storage failures and native interruption acceptance unobserved unless they happen; I do not force them.
10. When I navigate with the keyboard or resize the window, the project selector, checkbox, full paths, confirmation, history pages and outcomes remain usable. Existing Archive remains reversible organization, Reset remains retained recovery, and the PS04–PS06 controls keep their separate purposes. All editor and pending-operation guards still apply.

Initial eligibility is intentionally limited. Projects containing migration/export recovery, independent snapshot payloads, unknown files or prior PS04/PS06 cleanup records remain protected. Do not delete those originals to obtain eligibility. Record unavailable cases honestly. PS08/compression, AI import, broader AI-linked removal, CA03 and release acceptance are separate work.
