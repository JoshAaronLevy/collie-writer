# RF02 — Save and Open manual guide

**Implementation complete — awaiting user testing.** Format, lint and node/web typechecks passed separately from these unperformed runtime checks. Use disposable projects and files, especially for replacement and recovery. Start Collie Writer with your usual development launch (`npm run dev` in the configured project environment); the assistant has not launched it. Do not use irreplaceable work for these steps.

1. **First and repeat Save:** Create a disposable project, type a short passage, and use the toolbar Save control. The native picker asks for a `.collie` location. After completion, its status/tooltip and Project actions agree on **Saved to [filename]**. Edit again: the file status becomes **Unsaved changes**. Save updates that same file without asking for a location again. Where the operation lasts long enough to observe it, progress and cancellation remain available; edits made after capture may still need another Save.

2. **Consistent status:** Check the current project's row in Projects, its file section in Project actions and its summary in Data and recovery. They use the same file-status wording for the same state. An inactive project's **Last saved to…** is a record, not a claim that its file is currently reachable. The toolbar's accessible label/tooltip reflects saving or retry when applicable. The full file-controls panel no longer repeats below every workspace.

3. **Save As and Backup:** Use Save As to write a second disposable filename; subsequent Save targets that filename and the old file remains. Then use **Make a backup…** from Save options with a fresh third filename. Backup leaves the Save destination unchanged. Attempting Backup to an existing filename must not replace it. Use **Show file** in Project actions to confirm the assigned destination.

4. **Normal close:** Make another edit, allow local saving to finish, then quit normally without using Save. Reopen Collie Writer and the same project. The edit remains available locally; the selected file still has unsaved changes. Saving it clears that state only after file completion.

5. **Ordinary Open:** If you have a disposable `.collie` from another computer/profile whose project is not already in Projects, select it with **Open project file…**. After validation it opens directly, with no second **Open project** decision. Canceling the native picker leaves the current project unchanged. This branch remains unverified if such a file is unavailable; do not remove working data to manufacture it.

6. **Existing local version:** Open a disposable file whose project already exists locally. One focused dialog identifies the selected file and saved date. **Use local version** opens the retained local work; **Open file as a copy** creates a separate project whose first Save asks for a location. Each preserves the other version. Cancel or Escape abandons the opening action without replacing current work. **View saved version…** in Project actions and Restore backup retain their deliberate version choices.

7. **Replacement and an unavailable location:** On disposable files only, Save As to an existing unrelated `.collie` file. The native replacement confirmation appears automatically; Cancel keeps the existing file, and confirming replaces only the inspected version while retaining its previous bytes. If an assigned file becomes externally different, the affected-state message explains ordinary Save's replacement consequence before you act. If its location is unavailable, local work stays accessible and file actions offer Locate or Save As; a failed Save must not show **Saved**. Any already-observed unconfirmed Save should offer Retry for the retained request, with Save As blocked until settled. Do not force a crash or manufacture a failure to exercise this branch.

8. **Keyboard and layout:** Navigate Save options and a version-choice dialog with the keyboard, then try a narrow window and increased zoom. Labels, file paths and actions remain readable/reachable; Escape cancels the choice. After canceling, focus returns usefully; after opening, the selected project is usable. RF01 recovery actions still remain within Project recovery, without a second version dialog appearing over it.

Report the action, visible wording and observed result for any mismatch. Native file behavior, data fidelity, interruption/recovery, focus and accessibility remain unaccepted until these observations are supplied.
