# AC05 — Project-aware conversations

Implementation complete — awaiting user testing. Use a disposable project copy for migration, merge/trash, Save As, backup/restore or independent-copy checks. These are manual actions, not automated tests. Use existing real material; leave unavailable scenarios pending rather than generating bulk fixtures.

1. Save and quit normally, stop the old development process, then run `npm run dev`. Open a disposable existing project. Writing, sources, saved conversations, AC04 memory and local drafts should remain; opening must not send anything.
2. In AI → New chat with Project context, ask about a distinctive passage in another chapter/section. For a small project, the reply should have access to other writing without attachments. Inspect the message's sent context and Context → Project material → Last sent coverage: actual bodies/passages, identities and partial coverage should be visible. On a large project, judge relevance without assuming every page was read.
3. Ask about a real decision in another active chat. A relevant completed exchange should be eligible and labeled as prior discussion, not source evidence. Archive that other chat and start a fresh chat: its exchanges should be excluded from automatic recall. Under Context, find and explicitly pin the archived chat; the next Project context Send may include the saved snapshot.
4. Ask about existing research with relevant notes, saved inspection excerpts or existing extracted page text. Sent context should distinguish bibliographic metadata, user notes and extracted/transcribed/corrected excerpts, with source/version IDs and page/hash/offset provenance when page text is selected. A metadata-only source must not be described as an inspected article. No URL/PDF should be fetched or extracted by this Send.
5. Ask the assistant to identify or discuss a source already in the project. When its exact source ID/DOI/URL/ISBN appears in the completed answer, Project references should show In Research and Open source. Title-only suggestions should say Possible existing source and offer Review match. Open the referenced record. On a disposable copy, merge/trash it normally: matching should follow a valid replacement or show Removed source without restoring anything.
6. Open Context → Project material, find a writing item/note/source/excerpt and pin it. Inspect the snapshot. Change the underlying item, Send again, and inspect the retained pinned revision. Refresh snapshot and Send: the new revision should be used. Exclude an item: the next project selection should omit its automatic material. Earlier conversations/captures remain unchanged. Excluding a writing item also removes its live overview contribution.
7. In Research → Sources, choose a saved active source and click Discuss in chat. A new chat should open with a prefilled, editable draft and a source pin. Nothing sends until Send; any prior chat draft remains intact. Unsaved research changes should still follow the existing save/navigation guards.
8. Switch to This chat only, then Message only and Send in each scope. Inspect the snapshots: project material/pins must be absent from both; Message only also excludes current-chat history. Open a different project and ask a similar question: no records or pins from the first project should appear.
9. In a naturally larger project/chat, Send may show Preparing context before the ordinary answer. Stop during preparation: the original draft must remain and must not send afterward. Inspect memory/originals; changed covered revisions should invalidate old overview coverage. No more than two preparation requests should run for one Send.
10. Save, quit, restart and reopen; inspect pins, exclusions, original messages, memory and exact contexts. Export with sent context to a new filename and inspect provenance/selection history. On a disposable copy use the normal independent-copy or backup/restore route and inspect the same content. No action should replay inference.
11. Use a narrow/zoomed pane and keyboard navigation. Optional Context controls should remain scrollable; normal chat remains header, transcript and composer. IME composition must not accidentally Send or change a pin. A real size/stale/storage error should keep the draft/selections and offer a useful next action.

Report actual answer relevance separately from context selection and persistence. No matches means only that Collie did not establish a saved match. Web search, adding new references to Research and citation insertion from chat are later stages, not acceptance requirements for AC05.
