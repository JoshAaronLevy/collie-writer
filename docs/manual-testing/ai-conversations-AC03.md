# AC03 — Returning to chats and drafts

Implementation complete — awaiting user testing. These are manual actions for Josh, not an automated suite. Use a disposable project for discard/archive/Save As actions. Do not manufacture failures, fill quotas or edit recovery files. Drafts are local to this device and exact working copy; sent history remains portable.

1. Save your work, quit the existing development app normally, stop its old development process, then run `npm run dev` and reopen the project. This loads the changed main, preload and worker code. Existing saved conversations should remain readable; reopening alone should not send messages. The prior AC02 completion correction still needs a successful live user observation.
2. In AI, open or create two chats. Leave different unsent text in each, choose **This chat only** in one and **Message only** in the other, and switch using Back/the conversation list. Each chat should retain its own text and context choice. The list should show recent message previews and draft markers, without a routine global unsent-draft warning.
3. Quit normally immediately after editing a draft, then relaunch and reopen the same working project. Both drafts and choices should return after local recovery. Nothing should send automatically. Switching to another project and back should also preserve them without exposing one project's drafts in the other.
4. Open **Chat options → Saved drafts on this device** (or Saved drafts in the list). Copy a draft and inspect View full draft. On the disposable project, cancel Discard once, then deliberately confirm it. Cancel should retain the text; confirmation should clear only that draft and its context choice, leaving sent messages intact. Close/reopen to confirm the intentional discard remains.
5. Archive a chat with a draft. It should remain available through Archived history and Saved drafts, with its text recoverable and no automatic Send. Restore the chat and continue editing the same draft. If an unavailable chat is naturally shown in Saved drafts, its text should still offer View/Copy/Discard and should not be assigned to a different chat.
6. In an existing longer conversation, use **Load earlier messages** and scroll upward. Existing visible text should stay at its reading position as earlier exchanges are added. After navigating further back, **Jump to latest** should return to the latest exchange. If suitable long history is unavailable, leave this observation pending rather than generating bulk messages.
7. Use **Chat options → Find in this chat** for a phrase from an older exchange. Select a match: that exchange should open without changing the composer draft/context. Continue search should advance if more history remains, including when a batch has no matches. Switch chats while a read is pending if encountered naturally; the new selection should remain correct and finish loading.
8. Copy an older assistant message and export the transcript to a new filename. The export should include saved history beyond the visible window and omit unsent drafts; exported context remains an explicit option. Rename a chat, send a new message when ready, and confirm its custom title is retained.
9. Use keyboard navigation and a narrow/zoomed pane. Back should return focus into the list; choosing an active chat should focus its composer without stealing focus after you deliberately move elsewhere. Header icons, Find, Saved drafts and composer should remain usable. IME composition must not send or discard text accidentally.
10. Send a short follow-up in a chat containing a completed exchange while viewing older history. The response should stream and complete through the AC02 flow; history paging/Find should not limit context. Type a next draft during streaming and switch away/back: that text should remain yours, never an implicit send queue. Stop, failures and local-only historical attempts retain their existing labels and actions.

If a real protection problem occurs, text should remain in memory with Retry draft protection and review/copy access. Normal close or project replacement must not silently discard unprotected new text. If only an existing draft file cannot be read, editing stays unavailable, the file is kept and normal close remains possible. Do not delete a working folder or saved-draft file to clear an alert; report the visible message and action that preceded it. Capacity and storage-error behavior remain unobserved unless encountered naturally.

Report failures with the action, expected/actual behavior and whether the app was fully restarted. Screenshots are useful for focus/layout/scroll issues; omit private writing or credentials. No broad release acceptance follows from these checks.
