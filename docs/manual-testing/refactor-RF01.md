# RF01 — Project recovery

**Implementation complete — awaiting user testing.** Code checks are recorded separately in the [implementation record](../validation/refactor-RF01.md). Use disposable projects and copies for file-location or recovery scenarios. Do not damage a working database, delete recovery files, force a crash, or use valuable originals to manufacture a failure. Skip naturally unavailable scenarios and report them as unobserved.

1. Launch the updated development app yourself with the pinned Node 24.21.0/npm 11.19.0 toolchain and `npm run dev`. Open Projects. Healthy projects remain available. Retained versions or a healthy earlier reset alone do not cause a recovery warning.
2. If a recovery warning is present, choose **Review recovery**. **Project recovery** opens directly over the current screen. It checks the existing records automatically and names the affected project when known, the actual problem or unknown cause, and useful actions. It does not navigate to settings or ask you to operate reconciliation stages.
3. If an interrupted Save/Backup can be confirmed from existing evidence, observe its confirmation and the disappearance of that matching issue. Other unresolved issues remain. No new Save, AI request or import acceptance should occur merely from opening the dialog. If no such operation exists, record this case as unobserved.
4. Choose **Later**, then reopen recovery. Unresolved problems are still present. Closing the dialog does not claim repair. Your current manuscript, research drafts and existing project remain available. Keyboard focus returns to the initiating control when available, or the current content region when that control disappeared.
5. For a disposable saved project whose selected file is unavailable, review its warning and choose **Save a copy…**. Choose an unused filename. The dialog reports a separate saved copy; the original Save location remains unchanged. Selecting an existing filename must keep that file and explain the conflict. Cancelling the picker creates no copy. An unresolved earlier file condition can remain listed after a successful copy.
6. For a naturally encountered issue with retained versions, expand **Available versions** and choose **Inspect version**. A readable version shows its actual title and recorded date before **Recover a copy**. Cancel keeps the originals. Confirming opens an independent project with its own identity; its first ordinary Save asks for a location. Compare writing, Research, Notes, conversations and imported originals with the intended version. A missing/invalid version reports the problem rather than pretending recovery succeeded.
7. For an unreadable project without an established usable local copy, use **Open backup…** with a disposable known backup. The same dated independent-copy choice appears. The unreadable original is retained, and its unresolved warning may remain. If you have no relevant issue, skip this scenario.
8. Open **Diagnostic details** for an unresolved issue. The text identifies the issue, project/workspace and operation when known, cause and phase. **Copy diagnostic details** copies only that displayed text; if clipboard access is unavailable, the text remains selectable. Nothing is uploaded.
9. If a healthy earlier reset exists, open Data and recovery → **Recovery history, backups and retained versions**. It is history, not an alarm. Known project titles appear before **Restore projects**; unavailable names are explicit. Restore only a disposable batch when you intend to return all listed projects to the library.
10. With a recovery dialog open, use Tab/Shift-Tab, narrow the window, increase zoom to 200%, and try reduced motion. Long content scrolls within the dialog; controls and Later/Done remain reachable. Switching to an inspected version keeps keyboard access inside the dialog. Returning to writing preserves the draft and composition/undo behavior.

If local writing protection fails naturally, the notice must say recent changes may be unsaved and saving on this computer could not be confirmed. Keep the window open and preserve visible text. **Retry local protection** reuses the existing protection owner. If a Save is genuinely pending or another writer still owns work, recovery should show the blocker rather than bypass it or promise a new safe copy. Do not create these failures deliberately.

Report what you observed, exact visible copy for any unexpected blocker, and which conditional scenarios were unavailable. RF02 and later stages wait for a separate request.
