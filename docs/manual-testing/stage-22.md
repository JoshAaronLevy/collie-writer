# Stage 22 user-owned guide

**Stage 22 is partial.** Microsoft EXE preparation is implemented; MAS is blocked on missing native product code. Neither store is submitted or accepted. The steps below describe expected outcomes for implemented paths, not recorded passes. Do not attempt a MAS purchase/file workflow: no usable MAS build or native adapter is supplied.

As a user:

1. When I launch development with `npm run dev` using the [pinned setup](../../README.md#setup-for-the-user), it should still identify itself as Development, offer untimed free editing and explain that purchase/restore is unconfigured. Help → Check for updates should explain that updates are unconfigured. No Apple or Microsoft purchase/restore UI should appear.
2. When I create two disposable projects, choose each project's own Save location and reopen them, their content should remain separate. Canceling first Save should retain local recovery without assigning a destination. Stage 22 does not change the project format or remove existing work.
3. After I provide authentic signing/identity setup and produce a Windows production candidate using the [Microsoft owner instructions](../release/microsoft-exe.md), installing its retained EXE with `/S` on a disposable clean Windows 11 x64 installation should require no installer pages or downloads beyond any necessary UAC prompt. I record the exact artifact, publisher and actual signature coverage; missing or failed evidence keeps the Store submission blocked.
4. When I open that production app, it should identify itself as Direct because the proposed Store listing distributes the same product. Once I have backed up disposable local work, installing the exact same retained production artifact through the other authorized acquisition route should preserve the same profile and work. I should not get a second Store-specific project library. Actual Store acquisition remains pending until separately authorized submission/availability.
5. When I request an update from that app with an approved newer signed candidate available, Collie's direct-production flow should ask before download and restart, protecting pending writing before installation. The EXE route does not use MSIX Store-managed updates. Without an available candidate, I leave update acceptance pending.
6. Only after authentic direct commerce and separate transaction authorization, when I restore the same direct purchase through either EXE acquisition route, the same nonfiction capabilities should apply. Reading, individual exports, backup, recovery and free designation should remain available after a legitimate entitlement change. Microsoft account ownership or an Apple purchase should not unlock this direct channel. Use the [Stage 20 guide](stage-20.md) for available purchase/refund/renewal/offline/lifetime paths; do not manufacture grants or clock changes.
7. With disposable work and a separately saved backup, when I uninstall and reinstall the Windows production product, selected project files should remain untouched, and the configured retained local data should be available. Opening my backup on another supported installation should recover an independent project without importing credentials or license state. OS/user app-data deletion can still destroy unsaved recovery.
8. When I review the [channel record](../validation/stage-22.md) and [listing drafts](../release/store-listings.md), Microsoft should remain not submitted and MAS should remain blocked on native implementation. Missing seller/support URLs, artifacts, policy/native evidence or review approval must not appear completed. A pending store does not change the separate direct-release decision.

Report version, platform/architecture, step and visible outcome without private writing, paths or purchase credentials. MAS acceptance still needs a later implementation handoff covering signed native Save/cancel/empty-file/reopen/moved-bookmark/replacement/cloud/output flows and Apple purchase/restore/refund/renewal/offline updates. Those are pending requirements, not functions to exercise in this checkout.
