# IM07 — user manual guide

**Implementation complete — awaiting user testing.** This stage adds one real, bounded ChatGPT analysis request and protected proposal storage. Multi-part processing, editable proposal review and final import remain IM08–IM10. Earlier stage acceptance is not inferred.

Use a disposable project or an independent copy, and existing small supported files you are comfortable sharing with your selected ChatGPT account. Keep an untouched saved project when checking migration. Save your work and quit the old app normally, then launch the updated development app with your usual `npm run dev` workflow. The assistant has not built, launched or exercised it. Schema 26 migration keeps the original database through the existing migration owner.

1. **Open the disposable project → Import → select a small existing text/Markdown note or supported small JSON export → choose its categories → Inspect selected files locally.** Expect retained originals and local previews. No ChatGPT analysis should start from selection, inspection or reopening the dialog. For the first request, prefer a short note; the complete cultural collection needs IM08.
2. **Use Manage ChatGPT to select your own account and model, then return to Import and select Review analysis sharing.** Expect selected file/record/exclusion counts and a one-request ceiling. Expand Exact shared content and analysis instructions and page through the content. Expect the selected file names, original text, metadata and your instructions, with no manuscript or unrelated project context. Nothing is sent by review. Oversized/empty/capacity-exhausted selections should explain the refusal before any send; nothing should silently be shortened.
3. **Approve the sharing checkbox and click Analyze with ChatGPT once.** Expect the intake dialog to close before Import analysis opens. Expect real preparation/running/protection states. If the provider completes a valid proposal, expect a saved proposal summary with item/relationship/issue and identified-record counts. If the provider returns invalid JSON or unsupported references, expect an invalid-proposal status and retained response text instead. Either result keeps Confirm import unavailable and adds nothing to Chats, Research or Notes. Report the actual live outcome; a clean code check does not establish model compliance.
4. **While analysis is active, dismiss progress with Keep for later and reopen it through Import → Open analysis progress or AI work → View request.** Expect the same request and its current saved progress, with no new send. Page the retained response when available; large text should stay inside the bounded reading area. Continue ordinary writing and confirm the manuscript/caret/undo state is preserved.
5. **For another request you explicitly choose to make, use Stop analysis while it is running.** Expect an honest stopped/uncertain outcome with any received text retained, or an already completed result if completion won the race. Stop must not claim refunded usage or confirmed remote cancellation. Do not expect a valid partial proposal or an automatic retry. Failed/stopped work can be acknowledged through the existing AI work saved-result dialog; the saved analysis must remain readable afterward.
6. **If an ordinary account/network/local-write issue occurs, inspect the progress message and shared Manage ChatGPT diagnostics.** Expect the actual account/provider problem to stay distinct from invalid proposal JSON and local protection failure. Check saved outcome is local recovery. Retry local protection must not resend. If the submission reply is uncertain, Check saved outcome first; the explicitly labeled Retry exact submission may send an unsaved request only while its original approval remains valid. A saved attempt must not be sent again. Do not inject failures or edit databases to exercise these branches.
7. **Return to Import and change a category/file choice or instructions, then inspect again.** Expect a fresh sharing review requirement. Open the older attempt from Saved analyses; expect the old result to retain its original content and be marked as belonging to a changed selection. Changing account/model also requires a fresh review. Leave a sharing review idle for more than four minutes; expect renewed review before sending.
8. **After work settles, Save the project, close normally and reopen it; use Import → Saved analyses.** Expect the saved attempt/output/proposal and protected originals to remain readable, with no automatic inference. Try an independent copy of the disposable saved project if desired; it should retain evidence without gaining the original execution's authority. Research/Notes/Chats/manuscript still gain no imported rows in IM07.
9. **Use keyboard navigation, Escape and a narrower window.** Expect one modal at a time, named controls, a reachable Stop/recovery route, paged text and useful focus return. If a modal handoff is deferred because the window is unfocused, reopen progress explicitly; it must not steal focus later.
