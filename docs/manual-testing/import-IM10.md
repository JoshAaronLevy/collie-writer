1. **Launch your normal updated development app** (`npm run dev` if that is your usual workflow) and open a disposable project. Open Import and an existing selection with protected analysis. Expect Review analysis plan / progress to reopen saved work without sending anything. For new analysis, use the existing explicit account/model/finite-request consent flow and pause/finish it before review.
2. **Review a small batch** containing a chat with several messages, a new source, a source deliberately linked to an existing source, and a note if those categories are present in your selected data. Correct titles/metadata, acknowledge losses and save inclusion/exclusion decisions. Expect ordinary Chats/Research/Notes to remain unchanged until final confirmation. A chat title longer than 160 characters must require correction.
3. **Prepare final confirmation, inspect counts and dismiss it.** Expect exact destination IDs/counts/new-versus-reused sources and exclusions. Reopen the review; expect the same preview and no accepted content. This action must make no ChatGPT request.
4. **Click Confirm import once.** Expect Import completed and an immutable receipt with counts matching the preview. Only included records appear; skipped records remain retained originals. The manuscript stays on its current item with its text, caret and undo history. Completion does not claim that the `.collie` file has been saved. The button must not permit another acceptance while busy or after completion.
5. **Use Open imported transcript in the receipt report, then Read transcript.** Expect separate ordered original messages, preserved consecutive roles, original dates, paged text/Find and retained provenance. Exported internal/system material must not masquerade as a new request or answer. 6. **Use Open in Research for a new and a reused source and for a note.** Expect the import dialog to exit before navigation. New source fields should match the reviewed correction and remain unverified. The reused source must keep its existing metadata/verification. A note should contain original literal text with the reviewed title/tags/categories and imported authorship disclosure. No citation or manuscript content is inserted automatically.
7. **Open Import again and choose the completed selection.** Expect completed status and Check completed import to return the same receipt/destinations, with no extra chats, sources, notes, AI requests or project-file Save. Re-including them must block confirmation. Resolve any material previously excluded from the first import explicitly. A fully duplicated review may be confirmed with zero additions; expect no duplicate entities. If a fresh export contains changed content under an accepted chat/message identity, expect a review conflict requiring exclusion, not an overwrite or automatic append.
9. **On another disposable selection, prepare a preview and change ordinary project data before confirming.** Expect the old head to make the preview stale and require a new local preview and explicit confirmation. Change/remove/merge a reused source through the ordinary UI; expect renewed source review. No reanalysis should be triggered by these local choices. Keep unsaved source/note/chat forms open while trying preparation/confirmation; expect their retained owner to request protection or resolution, with the draft preserved.
10. **Stage disposable file copies, then move only those external copies elsewhere before confirming.** Expect retained staged bytes to support review/confirmation; receipt lookup must not ask for the original paths. If analysis is already protected, disconnecting network access should not prevent local confirmation in a still-writable project. Do not change the app's protected originals or working database.

Check completed import must return historical evidence and never execute it again. Make a later ordinary edit and check the receipt again; its original counts/head/time must remain unchanged. Repeat Save after a normal source/note edit to observe initial imported provenance surviving later revisions.

Expect either the original completed receipt or a definite not-applied result permitting an explicit retry of that same preview. An unavailable lookup must leave the command pending and block another confirmation. If editing access is lost, completed reports/outcome lookup remain read-only; a new acceptance must be unavailable. After restart, choose the saved selection and use its report/review. Do not manufacture crashes, disk errors, corrupt files or access faults.
