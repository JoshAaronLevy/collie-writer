# PS02 manual guide — Categorized storage inventory

October 5, 2026. **Implementation complete — awaiting user testing.** Format, lint and node/web typecheck passed cleanly; see the [record](../validation/project-storage-PS02.md). Runtime acceptance has not been observed.

Use ordinary disposable projects/files or copies of projects that already contain genuine research, citation assets and saved conversations. No new AI request is required. Do not change permissions, corrupt journals, generate workloads, fill disks or delete data to manufacture cases. The assistant has not launched the app or observed these outcomes.

Stage PS02 complete. As a user:

1. When I run `npm run dev` myself and open Settings → Data and recovery, I see the PS01 working/selected-file explanations plus **Storage inventory**. Nothing is measured by the new inventory until I choose **Measure storage**. Existing recovery actions remain separate.
2. When I measure storage with several ordinary projects, I see working, application and known-external totals, measurement times and expandable groups. Expand a project that already contains research: the project database, managed originals/images, citation files, search cache and retained copies appear separately when those files exist. A shared database is counted once, with writing/research/conversations/history explained together. Missing categories do not imply content has been deleted.
3. When I expand a project with existing search data or previous normal Saves, rebuildable search data is visibly distinct from source originals, writing and retained recovery. There is no Clear cache/delete action. Each category shows its location, per-scan volume and measured-file/unknown counts. **Clear picker history** in the separate recovery panel remains only a folder-hint action.
4. When I inspect shared AI/application groups, encrypted data without established ownership is explicitly shared/unattributed. If already loaded AI ownership is available, related operation files appear with that project's data and the shared AI folder as their actual location. The report does not sign in, run AI, load every chat or claim that all AI storage belongs to the selected project.
5. When I inspect recorded selected/previous/backup groups from disposable saved projects, their locations and file sizes are additional to the working total. External entries explicitly say their current contents/ownership and cloud status were not inspected. Repeated references/identities are counted once; independent copies can each consume file-size bytes. Changing the project I have open does not transfer other projects' storage to it.
6. When I refresh, a new scan replaces the prior one and its measurement times update. If more than 25 groups exist, Previous/Next page lets me browse them while the top totals remain for the whole measured report. If the bounded scan stops early, it says incomplete; it does not present the measured subset as a full-library total.
7. When I choose **Cancel inventory** while a scan is still running, it becomes a partial/cancelled report and keeps measured data. When I start another scan and navigate back to Write, leaving Data and recovery requests cancellation and the retained editor stays available with its writing. When I return, I can refresh again. A small scan may finish before I can cancel; a completed report is expected in that case. No Save/file picker should be triggered by measuring or cancelling.
8. If a recorded location is naturally unavailable, its entry is unknown/incomplete, not a zero-byte file. If a limit/reporting failure naturally occurs, retained measurements remain qualified and refresh/cancel remain available. Leave these observations pending when they do not occur; do not manufacture failures or offline data.
9. When I use keyboard navigation or a narrow window, disclosures, page controls and category headings remain reachable/readable, with long paths wrapping and table scrolling available. After reporting, my writing/research/citations/saved conversations and existing recovery/original-project links remain usable.

Report what you observed, including complete/partial/cancelled state and any category/path that seems wrong. File-length reporting does not promise actual disk allocation or reclaimable bytes, and ordinary concurrent writes can change sizes. Native I/O latency, large-library performance and runtime behavior remain unverified until observed. Stop at PS02; warnings, clearing, retained-content removal and AI-powered import are separate stages/features.
