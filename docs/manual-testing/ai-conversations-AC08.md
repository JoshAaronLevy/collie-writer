# AC08 — Integrated conversations walkthrough

**Implementation complete — awaiting user testing.** This is the current combined AC01–AC08 walkthrough. Older guides remain historical records; normal chatting uses one Send, not a request-review screen. No runtime observations are claimed below.

Use a disposable project copy with real writing, research and a few saved chats. Save and quit normally, stop the old development process, then run `npm run dev` yourself. Preserve the original project and local recovery. If a scenario needs material you do not have, record it as pending rather than generating bulk conversations or filling usage limits.

## Chat and continuity

1. Open Write → AI → New chat. Expect a focused, compact composer and a header with adjacent Back/New chat icons. Type a short project question, select an available model and Send. Expect a streaming answer that finishes without a false failure. Follow up on a specific detail: expect continuity without selecting history or approving a request form. Effort is intentionally hidden on the current route; no API key is needed.
2. While an answer streams, type your next draft without sending it. Scroll up: the transcript should stay where you are reading; Jump to latest should return to the newest text. If you load older messages or open another chat, active project work should offer **Open response** and **Stop**, without implying that the account disconnected. Stop should retain partial text and an honest stopped/uncertain outcome. Nothing should queue or resend automatically.
3. Leave different drafts in two chats and switch between them. Expect each draft and context choice to remain. Rename one chat, search by title, use Find in this chat to open an older exchange, Copy a response and export its transcript. Save, quit normally and restart: saved chats and device-local drafts should return without new inference. Archived chats remain readable/exportable and can be restored; they cannot receive new messages until restored.
4. If a naturally long conversation needs memory, Send may briefly show Preparing context. The first-use explanation should disclose that preparation can use additional requests. Context → Memory should retain summaries and their originals; edit a summary only if desired. Stop during preparation should retain your prompt and prevent the final message from being sent. If no suitable long conversation exists, leave memory acceptance pending.

## Project awareness and research

5. With Project context selected, ask about distinctive material in another chapter, a relevant saved source and a decision in a different active chat. Inspect the message menu → **View message context** and Context → Project material → Last sent coverage. Expect relevant, project-scoped material with honest partial coverage. Metadata-only sources must not be treated as inspected articles. Assess answer quality separately from whether the intended material reached the model.
6. Change the current chapter/section and send another message. Its context should use the current writing. Try This chat only and Message only: project material should be absent; Message only also excludes conversation history. Exclude a project item and confirm it is absent from the next snapshot. Archive another chat and confirm fresh automatic recall excludes it; deliberately pinning an archived chat may include its snapshot. Switch projects: neither project should borrow the other's writing, research, drafts or discussions.
7. Explicitly enable Search the web and ask a modest public research question. Expect a permitted live search with retained, openable references. Existing Research matches should say In Research; title-only suggestions require review. Extra retrieved pages stay under a disclosure. If search is refused or the answer has no confirmed search, the UI must say so; a text-only alternative must be an explicit new Send. Record the refusal as an unresolved research milestone, not a successful substitute.
8. Choose Add to Research on a new web reference. Review title/URL and enter only metadata you know. Dismiss or Keep for later, then resume from the chat menu: edits should remain. Continue and save; expect an ordinary Research source and Open source/Cite controls. No original file, inspected excerpt or verified quotation should appear automatically.
9. Select a short book reference in a completed answer, including across bold/italic text or a link label. Save reference should appear. Review its plain-text title and supported source type; original answer text retains the canonical Markdown passage. Save it. Repeat with matching metadata and choose Use existing: expect one source with unchanged existing metadata/verification, plus the explicit chat link. Select a shorter passage if it exceeds the 2,000-unit reference limit; generated citation badges/image placeholders are not source text.
10. From Research → Usage and context → Saved from conversations, choose Open conversation for an older saved reference. Expect the original exchange to load and come into view, even outside the most recent transcript page. It should not focus the composer or send anything. Returning from a removed/merged source must retain honest source-state labels and the original provenance.

## Writing, ownership and everyday use

11. Place the manuscript caret at the intended position, choose Cite beside a saved reference, review the existing citation form and Apply citation. Expect a real manuscript citation at the captured position; Cancel inserts nothing. Changed/replaced writing or an unavailable source must refuse a stale handoff. Existing dirty Research forms and manuscript undo must survive source saves and read-model refreshes. Export with the normal bibliography settings: expect the cited source in the output, subject to the existing missing-metadata notices.
12. Archive the originating chat, Save the disposable project, quit and reopen. Expect sources, provenance, citations, full saved transcripts, memory and project-context settings to remain. Create a Backup, restore into a separate location and use the normal independent-copy workflow; compare those same records. Copies must not carry account credentials, live execution rights or unsent device-local drafts, and opening/restoring must not start AI requests.
13. Only for naturally encountered failures, inspect the inline error and existing error-details/account dialog. A pending local action should offer Retry saved action after it stops working; routine processing should not show a retry button. Uncertain source saves must retain exact fields/operation identity for Retry this save; successful reconciliation must not duplicate a source. Read-only projects should still show saved chats and exports. Do not modify local databases, inject faults or force-quit important unsaved work for this walkthrough.
14. Use keyboard navigation, Shift+Enter, Enter/Cmd-or-Ctrl+Enter, input composition, a narrow pane and increased zoom. Expect no accidental IME Send, named icon controls, usable dialog focus/return, readable source details and reachable composer actions. At short heights the composer and, if necessary, pane can scroll; normal-height chatting should keep transcript and composer usable. Judge both appearance and whether the next action is obvious.
