# IM03 manual guide

**Implementation complete — awaiting user testing.** This stage gathers and protects files and choices locally. It does not inspect conversation/source semantics, analyze with ChatGPT or accept project content. Required code checks are recorded separately in the [implementation record](../validation/import-IM03.md).

Use a disposable new project or **Duplicate project / Open independent copy**; keep an untouched `.collie` backup of older material. Keep the original conversation files untouched. No developer-console calls or automated suites are needed.

Stage IM03 complete. As a user:

1. Close the old development process normally and launch this checkout with your usual setup and `npm run dev`. Create/open the disposable writable project. In Write, activate the Import icon (its accessible name is **Import chats, research or notes**). Expect a dialog naming that project, content-type checkboxes, instructions, file limits and a whole-original retention disclosure before selection. Analyze with ChatGPT is unavailable.
2. Check **AI chats**, **Sources & research** and/or **Notes**, enter short instructions and choose **Select files…**. Select several JSON conversation files from one folder using the native multiple-selection controls. Expect names, sizes, selected totals and protected/readable UTF-8 notices. The files say content has not yet been inspected; file count is not conversation/source count.
3. Choose **Add files…** and select files from another folder. For the eventual supplied collection, repeat across all conversation folders under `/Users/joshlevy/Desktop/Cultural Analysis App/api/data/conversations`, including those outside `cultural-analysis`. Expect new originals in the same destination selection and unchanged earlier files. The app should not scan other files/folders automatically.
4. Add one already-selected file again (or a copy with exactly the same bytes). Expect a duplicate notice without another retained entry. Uncheck a retained file; expect lower selected counts/bytes and a “Removed from selection” label, with its original still listed. Add those same bytes again; expect the duplicate notice and the file still unchecked. Check its retained entry to deliberately reselect it.
5. Update categories/instructions, use **Keep for later**, navigate between Write and Research, then reopen Import from a Research heading or Project actions. Expect the same destination, selected files, checkboxes and instructions. Try the dialog close button/Escape after another settings edit; expect protection before dismissal and the edit retained on reopen. When composing instructions with an IME, finish composition before keeping/closing.
6. From the dialog's **ChatGPT and analysis availability** disclosure, choose **Manage ChatGPT**. Expect intake to dismiss before the usual shared connection/account/model dialog opens. Close it and reopen Import; expect unchanged retained choices. Selecting files and reopening Import should produce no analysis response or new project chat/source/note. Analyze stays unavailable even when connected.
7. With an existing selection, open Add files and cancel the native picker. Expect a cancellation notice and unchanged files/choices. Use the picker's All files filter to select an existing unsupported PDF/DOCX/ZIP/image. Expect an unsupported-format notice, no added original and continued use of the existing selection. An existing empty/non-UTF-8 text file should receive a readable-file refusal; a readable but malformed JSON file can stage because syntax inspection belongs to IM04.
8. Keep for later, then Save the disposable project using ordinary Save. Expect Save to finish; close normally and reopen the project, then reopen Import. Expect the exact selected/removed files and settings, with no need to select input paths again. Inspect chats, Sources and Notes: staged originals must not appear as accepted content, citations or manuscript sections. Reopening must not resend AI work.
9. Use **New selection** after protecting current choices. Expect a separate empty selection, while the Saved selections chooser can return to the earlier one. Discard a disposable selection with **Discard selection (keep originals)**. Expect its discarded label, no editable selection controls, and retained original names. Start/return to another selection; expect its files unaffected.
10. Using only the disposable project, make an unsaved manuscript edit, add/remove an import file, then dismiss Import. Expect the manuscript text, selection and undo history retained; the import head refresh must not replace it. Save and reopen to check both the edit and protected import selection.
11. Use keyboard Tab/Shift+Tab in the dialog and close it after protection. Expect focus trapped within intake, named controls and focus returned to the visible opening Import button without jumping into manuscript text. Resize/zoom and inspect long names: expect reachable controls and a scrollable file list. Repeat from Research and Project actions; actual accessibility/layout acceptance is yours to report.

If a real local failure occurs, keep the window/project open and use **Check saved outcome**. Expect a read of durable outcomes without another picker or dispatch. **Retry local protection** repeats only the exact unapplied local change; a failed file whose original changed must refuse until **Abandon failed file** reconciles it, then select the intended file anew. Files listed as “not staged” require explicit reselection. Completed originals remain retained. Do not delete working folders, recovery, migration copies or retained assets to resolve an error; no forced failures are required for this guide.

Report the action, visible error and expected/observed outcome without sharing private chat/manuscript bytes or credentials. Stop here; IM04 requires another request. None of these steps establish live import analysis or broader release acceptance.
