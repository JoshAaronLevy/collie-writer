# R2-01 — Quiet startup and predictable navigation

October 7, 2026. User-owned manual acceptance; no runtime results recorded.

Use a disposable project with at least two Chapters/Sections and enough text to scroll. Keep real projects and saved files out of data-risk observations. With the repository's pinned Node 24.21.0 / npm 11.19.0 toolchain selected, launch the development app yourself using `npm run dev`. The assistant has not launched it or run automated tests.

1. **Reopen writing.** Open the disposable project, click into a paragraph below the top, then close normally and relaunch. The same project/item and saved writing position return. Neither the writing-region border nor an active typing caret should appear automatically; click or use keyboard navigation to enter the editor deliberately. Normal keyboard focus indicators remain visible.
2. **Watch ChatGPT startup.** With an already connected account, let background preparation finish. There is no routine Setting up ChatGPT banner and no automatically opened connection dialog. The header's ChatGPT status remains available. If the account is intentionally disconnected, that alone produces neither an error notice nor an automatic dialog. Actual failures remain actionable; a healthy account is not required for local writing.
3. **Navigate between pages.** Scroll down in Write, open Settings, switch Settings subpages, and visit Projects, Research, Export and Project actions. Ordinary page transitions start at the top with the page's navigation visible. Return to work and a generic Back to Write also start at the top, with no delayed jump to the previous passage. Clicking an already active ordinary destination does not reset its scroll. A blocked navigation leaves the current work and viewport intact.
4. **Switch writing items.** In each of two Chapters/Sections, choose a different paragraph and scroll position. Switch between them, then reopen the project from Projects. Each saved writing position returns without automatically moving keyboard focus into the text. Type only after deliberately entering the editor. The manuscript and its applicable undo history survive ordinary page navigation; undo across replaced item editors is not promised.
5. **Follow a deliberate target.** Use an existing Search result or history/passage link. The requested passage is revealed even if its item has a different saved position. An unavailable exact passage reports its problem instead of choosing different text. If the disposable project already has citations/footnotes or saved proofreading results, include their passage links. Return to work or generic Back afterward must follow the page-top rule rather than replaying that old passage target.
6. **Use the account dialog deliberately.** Open Manage ChatGPT from the header, then dismiss it. It opens only on request, has no Don't show this automatically again checkbox, and returns focus appropriately without a page jump. If you choose to start a real sign-in, its progress and available Cancel remain reachable after dismissing the dialog. Closing the dialog does not cancel account work or erase an uncertain result.
7. **Keep later interactions in control.** Navigate, then scroll or choose another visible control promptly. No delayed destination callback should take focus or move the page after the newer interaction. Open/dismiss an existing dialog and switch away from/back to the app: hidden or background content must not steal focus. Existing Return to pending draft actions should still reveal the draft that needs attention.
8. **Repeat at narrow width and with the keyboard.** Narrow the window until the Outline/Manuscript pane switch appears; repeat startup, item switching, Settings navigation and return. Opening/resizing the app must not force typing focus into the manuscript. Tab still reaches its controls and editor. If an input method is available, finish composing text before navigation; composition and modal focus traps must remain protected. Check at 200% zoom and in your usual light/dark or contrast mode.
9. **Observe real exceptions only.** If connection status cannot be read, account/output protection needs attention, or a genuine connection failure occurs, use the notice's Manage ChatGPT/Check status controls. Required recovery must remain visible even if background work is busy. Do not manufacture failures or remove account/project files. Record unavailable cases as unobserved.

Report the step, visible result and any naturally observed problem. Native account timing, layout/scroll behavior, accessibility and passage navigation remain unaccepted until Josh supplies observations. R2-02 toolbar/status changes and R2-03 outline/width changes are not part of this stage.
