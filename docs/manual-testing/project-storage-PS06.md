# PS06 manual guide — Completed local artifacts

**Implementation complete — awaiting user testing.** See the [implementation record](../validation/project-storage-PS06.md) and [supported/protected classes](../formats/local-artifact-retention-v2.md). Required format/lint/typecheck results are code checks, not runtime acceptance. Use disposable projects and ordinary existing operations only. Do not create artificial leftovers, edit internal journals, stop processes mid-write, fill disks or run automated suites.

Stage PS06 complete. As a user:

1. When I run `npm run dev`, open a disposable project and perform ordinary Save/Backup operations, the existing file controls still complete normally. In **Settings → Data and recovery**, I see separate **Previous Save versions** and **Completed local artifacts** reviews. Neither selects or removes anything automatically.
2. When I choose **Review completed local artifacts**, I see exact paths, sizes, owning operation/snapshot-job references and eligibility/protection reasons for bounded discovered files. An empty review is normal: successful operations normally delete these redundant temporary copies already. If no eligible leftovers occur naturally, I record removal as unobserved and continue with the non-removal steps.
3. When naturally accumulated eligible leftovers exist in this disposable project, I select one exact file and choose **Cancel review**. The review closes without removing it. A fresh review still finds it unless normal file activity changed it. With more than four files, **More files** and **Previous files** change pages and clear selection.
4. When I review again, select an eligible file and choose **Permanently remove selected local file**, only that file is removed. The result keeps its operation/job identity and reports removed, changed or unknown honestly. It does not promise Undo or an exact free-space gain. Other files, the selected `.collie`, explicit Backup, original operation receipts and empty directories remain retained. Inventory/recovery refresh when Data is visible.
5. When I return to writing, research, citations, existing saved conversations and history, my content remains available. Using the existing guarded Open controls on the retained destination/Backup still opens its saved project. Cleanup does not repeat Save, import, export or AI work. If a local candidate was removed, it is no longer offered as a present recovery candidate; other present recovery candidates still use their normal inspection controls.
6. When I expand **What stays protected**, incoming files without consumption receipts, uncertain/leased snapshots, exports, migration/reset recovery, original content and AI outcomes have clear explanations. Existing inventory still counts their bytes, including unknown/unclassified entries. Any naturally present unsupported/changed files in the review remain non-selectable. Do not manufacture these cases.
7. If an eligible review is available, when I leave it open, make an ordinary writing change or Save, then try that old confirmation, its stale committed head/destination proof refuses removal. **Check removal outcome**, if offered, reads the original outcome; then I can make a fresh review. Expired reviews likewise need a new review. No replacement file is silently substituted.
8. Only if a real long-running file/snapshot/export job or uncertain reply occurs naturally, review/removal refuses unsettled work or waits for the actual background file check. **Check removal outcome** never repeats deletion. An unresolved marker or reappearing file stays protected. Leave interruption, timeouts, storage failures and restart recovery unobserved unless they actually occur; do not force them.
9. When I use the previous-version review after the new local-artifact review, its protected newest/current/Backup rules and separate Cancel/confirmation still apply. Switching pages or moving between settings and writing retains my editor and selection is never carried to another review. Pending cleanup outcomes retain existing close/project/access protection.
10. When I navigate the reviews with the keyboard or resize the window, headings, file choices, full paths, disclosures and outcome messages remain usable. No cleanup is triggered merely by startup, a size warning, navigation or typing.

Initial support is deliberately narrow: completed, single-consumer snapshots tied to the current acknowledged Save generation or an exact still-valid Backup. There may be no eligible files in a normal project. Leave deletion acceptance pending in that case; do not change storage internals to make a demonstration. CA03/CA07/CA08, PS07–PS08, AI import and release acceptance are separate work.
