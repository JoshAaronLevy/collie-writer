# PS05 manual guide — Previous Save versions

**Implementation complete — awaiting user testing.** Required code-check results are in the [record](../validation/project-storage-PS05.md). The user owns all runtime observations. Use disposable projects and saved-file destinations only. Do not edit internal journals/receipts, manufacture corrupt archives, force timeouts/crashes, fill disks or run automated suites.

Stage PS05 complete. As a user:

1. When I run `npm run dev`, open/create a disposable project, make a first Save, then make ordinary writing changes and Save three more times to the same selected file, each Save completes normally. My current file and retained previous versions exist under the established Save contract. I can also make an explicit **Backup** to a different disposable filename; it remains separate.
2. When I open **Settings → Data and recovery → Previous Save versions → Review previous Save versions**, the app reads the current project's records and inspects saved archives. I see exact paths, snapshot dates, file lengths and ownership/identity details. Nothing is selected. The newest previous version is protected; current files and explicit backups cannot be selected for removal. Ordinary older verified copies can be selected.
3. When there are more than four previous copies, I use **Older versions** and **Newer versions** to change pages. Each page is a fresh review and clears selection. I inspect the oldest page first if I want to remove several copies; a retained newer replacement is required for each removal. Large, unsupported or unverified files show retained/incomplete results rather than an unsafe removal control.
4. When I select an eligible older version and choose **Cancel review**, the preview disappears and nothing is removed. Reviewing again still finds that version unless ordinary project/file activity changed it.
5. When I select the oldest eligible version and choose **Permanently remove selected previous version**, exactly that reviewed file is removed. The result identifies it and reports confirmed removal or an honest changed/unknown result. It does not promise Undo or an exact physical-space gain. The newest previous version, its replacement proof, selected project file, explicit backup and other versions remain retained. Inventory and recovery discovery refresh; the intentionally removed path is not offered as unexplained missing recovery.
6. When I return to Write, Research, citations, existing saved chats and History, local writing and saved content remain available. When I use the existing guarded open/inspect/restore controls on the current file and a remaining previous version, they still open through the normal identity/conflict choices. No AI request is needed. Normal close protects local edits without initiating selected-file Save.
7. When I leave a review open, make an ordinary writing change or Save, return and confirm that old review, stale head/destination/file proof refuses removal. If the action needs reconciliation, **Check removal outcome** reports its original receipt or that no durable receipt was found, after which I can request a fresh review. No different file is silently substituted. Expired reviews likewise need a new review.
8. If a real long Save/Backup/Open/export/snapshot job is still active, when I attempt review/removal it waits for a background file check or refuses active work; an idle-looking caller timeout is not deletion authority. Leave timeout/loss behavior pending unless it occurs naturally. If an outcome really becomes uncertain, **Check removal outcome** reads the original action and never repeats deletion; restart retains its pending request. Unresolved records and reappearing files remain protected.
9. Only if a disposable history already includes an ordinary Save As over a different project's file, changed destination/grant, unavailable old location or naturally unreadable retained copy, when I review, that case remains protected with an ownership/authority/inspection explanation. Do not alter internal files or create artificial failures to produce these cases.
10. When I navigate by keyboard or resize the window, the single-selection controls, full paths, snapshot disclosures and result messages remain usable. Navigation retains my editor. Post-action inventory/recovery refresh waits for visible Data if I left the panel. No automatic deletion happens at launch, while typing, from age or from a storage warning.

Current scope is acknowledged previous Save copies in the current destination/grant chain, one version per confirmation. Archive inspection is capped at 512 MiB per archive (32 MiB database image), with additional documented [bounds](../formats/retained-versions-v1.md). A missing replacement or uncertain earlier removal can keep an older copy protected indefinitely. CA03 remains unimplemented outside PS05's narrow worker-owner boundary; PS06–PS08 and AI import were not advanced. Report observed results separately from passing code checks.
