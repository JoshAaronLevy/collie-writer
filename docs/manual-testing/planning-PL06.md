# PL06 — Combined Plan-to-Write walkthrough

Implementation and required code checks are complete; runtime acceptance is pending. Perform these actions yourself. Use disposable projects/copies for migration, insertion, replacement and Undo.

1. Launch using your normal `npm run dev` setup. Open a disposable project with recognizable existing prose. In Plan, import material through Submit → Accept, add a note, and collect material in a topic. Expect one shared library, retained originals and no generated manuscript text. Set one item aside: its original should remain available while ordinary planning/drafting excludes it.
2. Connect an eligible own-account ChatGPT model. Discuss the topic, or choose Suggest an outline and Send explicitly. Review the coverage, edit chapter titles/assignments and apply the outline. Expect the same chapters in Plan and Write, with existing prose preserved. Entering Plan, changing scope and Save should send no AI requests.
3. In Write, select a chapter and inspect Chapter material. Expect its direct/inherited notes, sources, excerpts and chats. Place the cursor within prose and open AI → Help me write → Connect these points (or Help me start / Continue here). Expect an editable prompt, Preview for insertion enabled and a scope naming the visible chapter. A pre-existing unsent prompt should remain in its old chat.
4. Send explicitly. Inspect View sent context: expect the chapter title/purpose, bounded nearby/selected writing, chosen material scope and honest coverage. Expect Review writing preview only after a completed answer. The manuscript should remain unchanged. Change the material scope explicitly and repeat if desired; chapter navigation should not silently change the shown scope. A new Help me write starter should choose the newly visible chapter.
5. Open Review writing preview, edit a sentence and choose Insert here. Expect the edited plain text at the captured cursor and the original AI response unchanged. Move the cursor before inserting another response: expect the captured target to stay fixed, not follow the cursor silently. One ordinary manuscript Undo should remove the insertion while the response and edited preview remain. Later ordinary typing should have its own Undo boundary.
6. Select ordinary prose, choose Preview for insertion with a custom replacement request, and Send. Expect Replace selection on the preview. Apply and Undo: only the captured prose should change, and Undo should restore it. Try a selection containing a citation or footnote: expect a refusal asking for a narrower prose selection, with the existing reference intact. Generated reference suggestions should remain text until you use the normal citation workflow.
7. Request another passage, then change the target chapter's writing before insertion. Expect a clear refusal retaining both the newer writing and generated preview. Put the cursor at a new position, choose Use current cursor or selection, review its chapter/action label, then insert. Expect no additional AI request. Repeat after changing chapters; an old target must not silently insert into the new chapter. Repeated clicks on a used target should not duplicate its insertion.
8. Edit a preview without inserting it, hide it, change chat and reopen it. Expect the edited preview to remain, separately from the original answer. Close normally and reopen the same working project: edited previews should recover on this device, but insertion should require Use current cursor or selection. Chat options → recovered drafts should expose retained preview text for copying if needed. A larger response should allow local shortening to the stated insertion limit without resending.
9. Insert a passage, Save, close and reopen the disposable `.collie` project; then open an independent disposable copy. Expect the outline, library, chats, analyses/proposals, captured writing context and accepted manuscript text to travel together. Uninserted preview edits are device-local drafts and should not be claimed as portable content. No request or insertion should restart automatically; the copy must require an explicit new insertion target.
10. Disconnect AI and repeat reading, manual organization, writing and insertion from a saved completed response. Expect those eligible local actions to remain usable; new sends should show the actual connection remedy. Under read-only access, retained material/responses remain readable and editing/insertion stays unavailable. Repeat the core flow with keyboard navigation, a narrow window and 200% zoom; finish any IME composition before sending/inserting. Existing proofreading availability should remain unchanged.

Report the step, visible error and actual outcome. Format/lint/typecheck success does not establish native, provider, editor or portability acceptance.
