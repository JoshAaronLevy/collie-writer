# RF05 — Clear project actions

Implementation complete — awaiting user testing. Use disposable projects and copies throughout. These observations are user-owned; source inspection and code checks do not establish native or visual acceptance.

Stage RF05 complete. As a user:

1. **Launch normally** (for development, run `npm run dev` with the pinned toolchain). Open a disposable project and open the menu beside Save. Project details, Save As, Make a backup, Duplicate project, Archive and Open backup are direct actions. In Projects, each row has the same project actions plus Open project and Remove local copy. The former multi-section Project actions page is gone.
2. **Open Project details, change the title, then choose Cancel changes.** Reopening shows the saved title. Repeat and choose Save details: the dialog closes, the project title updates, and the current writing, section and undo history remain. The filename stays unchanged; ordinary Save updates the project file. Clearing a required title gives a field error and keeps the dialog open. A project open for reading has disabled fields and Done instead of a save action.
3. **Choose Save As and cancel the native picker.** The save location stays unchanged. Repeat with a new disposable location: the original file remains, and later Save uses the new location. If you deliberately select an existing unrelated disposable file, the existing native replacement confirmation appears; Cancel preserves it. Save As retains its existing replacement policy; the old separate Move action is retired.
4. **Choose Make a backup and select a new filename.** A separate backup is created and ordinary Save still uses the assigned project file. Choosing an existing filename cannot silently replace it. Cancelling the picker leaves the project and destination unchanged.
5. **Choose Duplicate project.** A separate project opens with the retained content; the original remains available in Projects. The duplicate's first Save asks for its own location. Editing the duplicate does not change the original. For a project with imports or saved conversations, use a disposable copy and check that retained originals, relationships and saved findings remain available without new AI requests or acceptance.
6. **Choose Archive project, then Cancel.** The project remains active. Repeat and confirm: the dialog explains that files are kept, and Projects → Archived contains the project. Open its menu and choose Unarchive project: it returns to All active. Archiving the current project preserves its writing and section; archiving an inactive row first opens that selected project through the normal admission guards.
7. **Choose Open backup and select the disposable backup.** A focused restore dialog offers Restore a copy and Cancel. Restore opens a separate project; existing local work and files remain. Its first Save asks for a location. View saved version, when offered, retains the existing local-version versus separate-copy choices. Settings → Storage still provides the existing retained-version recovery actions.
8. **Use the Import navigation item or Import document menu action.** The document-import page still offers its existing document importer, and ImportButton still opens the retained project-import setup. Project details no longer requires navigating to this page. Opening import does not itself accept content or authorize AI analysis.
9. **Use only the keyboard and increase zoom.** Menus and dialogs have clear labels, focus stays within an open dialog, and the details fields scroll while Save details and Cancel changes remain reachable. Escape or the close control cancels unsubmitted detail edits. After closing, focus should remain on a visible, useful control; report any unexpected focus jump, especially after a library action changes projects or removes an archived row.

If an uncertain details Save occurs naturally, the exact request and form remain retained: fields and dismissal stay unavailable while Retry Save retries that request. Other navigation, Save and project replacement remain guarded. Do not inject faults to create this state. A confirmed details error offers a contextual reload; it must not silently discard edits. An uncertain file Save still uses its existing exact recovery flow, and other copy/location actions remain unavailable until resolved.

Native Save/backup/restore, old-operation recovery, imported-content portability and accessibility remain pending user observations. No release acceptance is inferred.
