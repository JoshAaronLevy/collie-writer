# PS04 manual guide — Clear search cache

**Implementation complete — awaiting user testing.** Required code-check results are in the [implementation record](../validation/project-storage-PS04.md). Runtime, filesystem and accessibility acceptance remain pending. Use a disposable project copy with ordinary existing writing/research; do not alter internal files, manufacture corruption, interrupt processes or fill disks to produce an edge case. Existing saved chats may be observed without sending an AI request.

Stage PS04 complete. As a user:

1. When I start development with `npm run dev`, open my disposable project and visit **Search**, local indexing becomes available. I search for a known phrase and wait for indexing to finish. I can then visit **Settings → Data and recovery → Clear search cache**; the panel names my current project. It does not prompt for an AI account or start a network request.
2. When I choose **Review search cache**, I see the exact local search filenames, estimated file lengths, eligibility and retention reasons. Writing/source databases, originals, citations, chats, history and backups are not eligible. **Cancel review** removes only the preview. A new review still finds the same eligible cache unless ordinary search/project activity changed it.
3. When I confirm **Clear reviewed search cache**, the result distinguishes confirmed removals, sidecars already absent after SQLite closed, retained files and unknown outcomes. The inventory refreshes; it does not promise a matching physical free-space gain. Staying in Data and choosing **Refresh storage inventory** does not recreate the search cache. A new cache review has no eligible current index after successful removal.
4. When I return to **Write**, Research, citations, existing saved chats and History, my retained writing and saved content remain available. Returning to Search recreates its index locally and again finds the known phrase after indexing finishes. Existing cancellation/rebuild controls remain available; interrupted/cancelled jobs are not automatically replayed. First Save, existing destination Save and normal local-protection/close behavior remain unchanged.
5. When I review a project before opening Search in this app session, an existing unloaded current index stays retained with instructions to open Search first. If there are no search files, the result says so and confirmation is unavailable. To clear a different project's cache, I open that project first; an old review cannot clear it.
6. When I leave a review open, make an ordinary writing change and return to confirm it, a changed project head requires a fresh review. If prompted, **Check outcome** first reports that no durable receipt was found for the old action, then I can review again. Expired reviews behave similarly. Do not substitute files or inject failures to exercise these guards.
7. Only if retained search copies already exist naturally, when I review them, a confidently verified sidecar-free copy within the inspection limits can qualify. Unreadable, oversized, sidecar-bearing or unknown copies stay retained with a reason. Do not manufacture retained files for this step; leave unavailable cases pending.
8. Only if a real interruption or uncertain reply occurs, when I return to Data (including after an ordinary later restart), the saved exact action offers **Check outcome**. It reports the original receipt without repeating deletion; unknown items remain honestly unknown. A new clearing requires a separate visible review. Existing close/project-change guards keep an unconfirmed action attached to its owner. Leave such observations pending unless naturally available.
9. When I use keyboard navigation and a narrow window, review/confirm/cancel/outcome controls remain reachable, result statuses are announced, and the file table scrolls without losing filenames or reasons. Moving between Data and writing preserves the editor; a post-clear inventory waits for visible Data if I navigated away.

Current limits: one active project's cache per action; up to 128 listed search entries / 2,000 visited directory entries; up to four sidecar-free retained files of 32 MiB each inspected; five-minute review expiry; 128 durable receipt-folder entries. Uncertain/limited files are retained. No prior Save versions, migration originals, recovery copies, AI records or managed content are cleared. PS05–PS08 and AI import remain separate requests. Report actual observations; do not infer acceptance from code checks.
