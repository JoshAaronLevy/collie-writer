# I09 — User-owned local journey walkthrough

**Implementation complete — awaiting user testing.** No assistant checks, builds, launches, screenshots or automated tests were performed. These are user actions with expected outcomes, not reported results. Use the optional sample or disposable personal projects and output folders. Never delete app data, disturb real manuscripts, interrupt real saves or change real purchase state to exercise an edge case.

Stage I09 complete. As a user:

1. From this checkout, with the existing pinned dependencies already installed, run `npm run dev` yourself. Open the app. Expect normal guided setup or safe returning-project/library behavior, visible citeproc attribution and no AI/network sign-in requirement. If it cannot launch, report the visible error rather than running a validation suite.
2. In Projects, create a disposable nonfiction project with title, author and optional description. Continue without AI. Expect Write with its project/outline sidebar and a short three-point orientation. Dismiss the tips, close normally and reopen; expect the dismissal to persist on this device, while the guide remains in App menu → Explore the tutorial. A focus-mode layout intentionally hides the tips.
3. Edit a sentence. Use Save, then cancel the first native picker. Expect local writing/recovery to remain and no destination to be assigned. Save again to a disposable `.collie` path. Expect local protection and selected-file status to remain distinct; no cloud-upload completion is claimed.
4. Open Save options in Write, Research, then Settings with the project still open. Expect Save As, separate Backup, Locate moved file where a destination exists, and File details. Cancel any unwanted picker. Make a separate backup if desired; expect it not to change the active Save destination. Project actions still provides Move, Duplicate, Archive and Restore.
5. Open Export. Expect Sections and options first, with active writing selected, one output format in free mode, paper/output name and title-page choices. Open Selected order and change section order or remove a selection. Expect only selected active text sections to be included; a missing/inactive recipe selection must be resolved, never silently substituted.
6. Choose DOCX and Protect drafts and review export. Expect a captured-section summary and preflight issues before the native picker. Incomplete source metadata requires this review’s acknowledgment; broken source references or unsupported compilation block publication. Expand Citation style and bibliography preview to inspect or correct real citations/sources through its navigation links.
7. After preflight, return to options and change paper, format, order, title-page/description choice or output name. Return to Review: expect a fresh review requirement and cleared acknowledgment. Edit writing or project details through their normal owners and return: expect the old capture to be unusable. Preparing again uses the newly protected head.
8. Choose a destination and cancel its native picker. Expect the review and writing to remain. Choose a fresh destination and export. Expect Export results with the format state, path, errors/losses where applicable and a retained report disclosure. Export must not acknowledge the `.collie` project file as saved.
9. Open the result yourself in an appropriate reader. Observe title/byline, selected order, citations, tables/images/notes if present, paper and title-page behavior. Repeat individually for PDF, Markdown and plain text as useful. Description belongs only in explicitly chosen DOCX/PDF properties, never on pages or in Markdown/text. Record actual output/reader differences; fidelity and PDF pagination remain unaccepted until observed.
10. Using disposable outputs, retry the normal export flow with an existing filename. Expect the old output to remain and the file result to explain the collision. For an explicitly chosen DOCX replacement, expand the replacement disclosure, choose DOCX, confirm natively and expect the previous file to remain beside it. Do not use real publication files for this scenario.
11. While a sufficiently long export is running, navigate to Research or another disposable project. Expect global progress/cancel to remain attached to the original job. View export result should return to its original project and focus that result. Cancelling may keep completed output; each file result must state its outcome. Completed notices are collapsed globally. If the export finishes too quickly to cancel, record that observation instead of forcing a failure.
12. Only if authentic paid access is already available, save/load a recipe and export multiple formats to a disposable folder. Expect one captured revision, per-format outcomes and retained successes when a collision or cancellation affects other files. Otherwise record the paid-path scenarios as **not observed — authentic access unavailable**. Free mode must still load an existing recipe and export one format at a time; do not create substitute grants.
13. In Project actions → Import writing, choose your own short disposable text/Markdown file. Expect preview and loss disclosure, optional original-byte retention and a new section after confirmation. Existing sections stay intact. An uncertain import or recipe/style operation should offer its exact retry rather than silently allowing a project switch that drops it; only record such failures if naturally encountered.
14. In Settings, visit Appearance & accessibility, AI connections, Collie access, Data & recovery, Updates and About/licenses/support. Expect clear separate homes. Change theme, zoom, contrast or motion; they apply immediately. AI remains honestly unavailable. Free-project designation and reading/export/recovery remain the existing local rights; no paid activation is fabricated.
