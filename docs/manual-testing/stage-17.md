# Stage 17 manual acceptance guide

Use disposable projects and output folders. Launch Collie Writer using your normal local workflow; the assistant has not launched it or generated an export. Save a copy before trying import/history or migration scenarios. You can use existing disposable writing with notes, citations, a bibliography, an image and non-Latin text.

Stage 17 complete. As a user:

1. When I select a few writing sections, choose Letter or A4, and preview the compilation, I should see one captured revision, section order, content counts, metadata warnings and any blocking references before choosing outputs.
2. When I select PDF, Markdown and plain text, choose a new output folder and export, I should see separate file results with the same captured revision. Opening the PDF should show page-sized output, page numbers, my non-Latin text, citations, bibliography and real notes at the relevant page bottoms. I should inspect long and boundary notes for clipping; this remains the D5 acceptance gate.
3. When I open the Markdown file, I should see visible citation and bibliography text, numbered `[^n]` notes and relative image links into the adjacent asset folder. Moving the Markdown file together with its asset folder should keep its image links usable. Plain text should show readable note/citation markers and image labels, with layout/style and image-pixel losses named in the per-file report.
4. When I save a named compilation recipe, move a referenced section in the outline, and load the recipe again, I should see the same section IDs and chosen order, paper and formats. If I archive one referenced section in a disposable copy, the recipe should flag it as missing or inactive until I revise the selection.
5. When I run a four-format batch into an empty folder, I should see DOCX/PDF/Markdown/text results per file. If I start another batch using the same names and continue past the collision prompt, prior files should remain untouched and each collision should be reported as skipped. Choosing a new name should produce new files. If I cancel while a long batch is rendering, already completed files should remain and later formats should be marked cancelled.
6. When I choose a small UTF-8 text or Markdown file for import, I should see its proposed new section, preview excerpt and explicit mapping losses before committing. After import, I should see a new draft section without any existing section being replaced. I should be able to choose whether the original bytes are retained in the project; the current UI does not expose those bytes for direct inspection. Raw HTML in Markdown should be rejected without changing the project.
7. When I use an existing disposable manuscript near 200,000 words, I should time DOCX and PDF exports separately, note output size and responsiveness, and inspect notes, images and citations in the resulting files. These timings and native viewer observations are user evidence; none has been recorded by the assistant.
8. When I save and back up a disposable project containing a recipe and an imported section, then restore or duplicate it into a separate local copy, I should still see the recipe selections and imported section there; the selected export files should remain outside the project backup.
