# IM09 manual guide

**Implementation complete — awaiting user testing.** Use a disposable writable project and copies of selected files. The Cultural Analysis App contributes only the JSON files you select from `api/data/conversations`, across all conversation folders. No other repository context is imported. Earlier stage acceptance is not inferred.

1. **Launch your normal updated development app** (`npm run dev` if that is your usual workflow), then open the disposable project. Open Import → Review analysis plan / progress. Use the IM08 consent flow for any analysis you choose to run. Expect saved valid results and honest unfinished/failed counts; reopening alone sends nothing. Stop/pause analysis before editing review.
2. **Choose Review proposed import.** Expect a local review inside the retained progress dialog, with Chats/Sources/Notes/Issues pages, per-file fully identified counts, original group counts and undecided/blocking totals. Analysis progress remains available in its disclosure. No source/chat/note has been created.
3. **Review and rename a chat.** Inspect its original facts, path, variants and whole original transcript. If the model suggested a title, expect a separately labeled inferred suggestion. Enter your title correction, select Include and save it. Expect the saved title/counts to update while original message text stays unchanged. An included chat without included messages must block confirmation.
4. **Use the explicit chat-and-messages action after acknowledgment.** Expect the disclosed number of fully identified, unambiguous, still-undecided messages from that exact envelope to become included in one saved decision. Existing exclusions must stay excluded; unfinished/conflicting messages must remain undecided. Review one message individually and expect its original role/order/path/body to be immutable.
5. **Exclude another chat/message with a reason.** Expect that exclusion to persist and dependent included messages to show an issue until explicitly excluded or mapped to their exact included envelope. No hidden dependency is included. A blank exclusion reason must prevent a valid saved choice.
6. **Review a source, correct its metadata and save.** Expect ordinary title/type/author/publication/identifier controls, original facts and unknown/loss notices. The corrected fields must be protected in the review; nothing has appeared in Research yet. Unsupported/unfinished coverage stays blocking despite acknowledgment. If a field is rejected, expect the draft to remain available; Reconcile saved review should distinguish an applied request from one that was not applied, allowing correction after the latter.
7. **Choose Use this existing source** from a suggestion or title search. Expect the active source ID/revision to be retained, with an explanation that metadata/verification stays unchanged. Trashed candidates cannot be selected. If multiple included source groups share a strong identifier, expect a blocking conflict until duplicate occurrences are excluded or deliberately linked to the same existing source.
8. **Inspect rejected/search/internal/unsupported material in Issues.** Expect retained-only status and its original decision/locator. Choosing Include cannot override the original eligibility or unchecked categories. For sources-only selection, no chat needs to be imported just to keep the originating-message locator; for chats-only, no Research source is created.
9. **If you selected notes, correct a note title and its tags/categories.** Inspect the exact literal text and authorship/conversion notices, acknowledge losses and save. Expect reviewed labels and a supported literal body, never a generated note or silently authenticated authorship. Notes remain outside the ordinary Notes list until final acceptance exists.
10. **Dismiss/reopen progress and review.** Expect saved decisions to reload unchanged. An unsaved correction remains in the same window after dismissal, with Save/Discard controls. Changing projects/closing with an unsaved or uncertain correction should require resolving it; dismissal must not silently apply/discard it. Save the choice before normal close, then reopen the project and review to check native persistence.
11. **Deliberately prepare a partial review.** Include a completed independent source/note or chat with supported messages, then disclose and authorize outstanding exclusions with your reason. Expect all undecided/blocked eligible groups and dependent messages/empty chats to become explicitly excluded in a saved revision. Check Issues and the excluded counts. Fully unfinished material cannot become included, and an empty accepted subset cannot produce a final preview.
12. **Prepare final confirmation once all eligible groups are included or explicitly excluded and blocking issues are resolved.** Expect other unsaved project owners to be protected or ask for attention. The preview must show the exact project, new/reused-source distinctions, chat/message/note counts, exclusions and frozen destination IDs. Confirm import must remain disabled. Preparing/dismissing the preview must leave ordinary Chats/Research/Notes unchanged.
13. **Reopen a saved preview, then change a review choice or ordinary project data.** Expect the same preview IDs on reopening; a new choice clears it, and a project-head change makes the old preview stale. If you change/remove/merge a reused source in ordinary Research, expect renewed local source review before another current preview, without AI retransmission. Use disposable data for this scenario.
14. **Save the disposable `.collie`, close/reopen normally and make an independent copy through the existing UI.** Expect protected originals, selected analysis, review choices and historical preview to survive. A copy or reopening must not send or import anything automatically. Observe keyboard labels, dialog focus containment/return, IME composition, narrow/zoomed scrolling and accessible pages.
