As a user:

1. With the existing Node **24.21.0** / npm **11.19.0** setup and installed dependencies, I run `npm run dev` myself. In an **editable disposable project**, I open Write and choose **Proofreading** under the AI companion's **AI assistance** selector. 2. I write a short en-US paragraph with deliberate mechanics errors, select a passage and choose **Review selected passage**. The review shows exactly the included runs and exclusions. No request is sent. **Save review locally** is available after review; **Run reviewed request** is disabled with an availability explanation. Choosing **Review current section** captures that protected section instead.
3. I save the review locally, including two quick clicks if desired. One **Saved locally · not sent** review appears with no generated findings. The notice distinguishes working-project protection from updating the chosen project file. I use normal project **Save** to update that file; the unsent review never queues itself for later inference.
4. In my disposable section I include ordinary formatted text and, if already convenient, a table, quotation, citation or footnote. The section review identifies unsupported content and shows only supported text runs. Bold/link boundaries remain separate runs. A section exceeding 128 runs, 64,000 context units or the 80,000-unit complete request/schema budget asks for a smaller selection without trimming or batching. I use my own text, without scripts or fabricated provider output.
5. Optionally I use **Connect Codex…** / **Open connection settings**, then **Continue with ChatGPT**, or explicitly **Resume Codex connection** for a saved account. I explicitly refresh models and select a reported model in **Choose model and view availability**. Settings, Conversations and Proofreading show the same selection. Missing models remain explained. These are real account actions under my normal subscription/spending settings; the existing isolation blocker still prevents Run. Account details are in the [CD02](codex-CD02.md) and [CD03](codex-CD03.md) guides.
6. With an unsaved proofreading capture open, I change the selected model, refresh its catalog or resume/change the account through ordinary controls. The original text and exclusions remain, but approval becomes stale. **Review this capture again** restores review against the original protected source if it still matches. **Check connection status** alone leaves the review intact when identity/generation is unchanged.
7. I edit the captured writing before saving the reviewed request. Submission refuses the stale revision and keeps the capture. Re-reviewing that old capture does not silently replace its text; I choose the intended passage/section again. Hiding the companion or visiting Research and returning preserves an undecided capture under the existing draft guards.
8. After saving or explicitly clearing unsaved captures, I close normally and reopen with `npm run dev`. My saved reviews and context remain readable without resuming Codex. On an already read-only disposable project, saved reviews remain readable while new reviews and correction decisions are unavailable. I can also return to Conversations and locally review/save a prompt with the shared controls.

It protects/reconciles the same operation without sending inference again. I do not induce failures, edit journals/credentials or create simulated results.

Ignore/Undo ignore changes the decision without editing prose. If I have no such records, this step remains unobserved; no findings are invented for it.
