# RF03 — Storage manual guide

**Implementation complete — awaiting user testing.** Required format, lint and node/web typechecks are separate from these unperformed observations. Start Collie with your usual configured development launch (`npm run dev`). Use disposable projects and saved files for every deletion step. Do not delete working folders, manufacture interrupted operations or use irreplaceable work to create a scenario.

1. **Locations and space:** Open a disposable project, then Settings → **Storage**. Its local working folder and selected project file are visible, with Show buttons for the available locations. Space measurement begins without a review procedure. Local project data, application data and free disk space appear above maintenance actions; unavailable values say unknown and partial readings are labeled incomplete. **Refresh space information** updates them. **Stop measuring** keeps a partial report. There is no category/file dashboard, Reset local work or picker-history cleanup.

2. **Clear search cache directly:** On the disposable project, use **Clear search cache** without opening Search first in this session. A previously created, verified cache clears through this one action, or a concise message explains that no verified cache is available. Opening Search afterward rebuilds as needed. Writing, research, original files, citations, chats and history remain available. A fresh project with no search cache should not create one merely to clear it.

3. **Older saved versions:** Make several ordinary Saves with different short passages in the same disposable project file. Return to Storage and refresh versions. Eligible older copies appear by project title, date and size; the newest previous copy and unverified copies have no deletion button. **More older versions** reaches further pages when present. **Delete version…** asks about one dated file and identifies its path. Cancel keeps it; **Delete selected version** deletes that exact eligible copy and refreshes the list. Current writing, the selected file and the newest previous version remain available. There may be no eligible copies when the required ownership/replacement proof is unavailable.

4. **Temporary files:** Use **Check temporary files**. A normal completed Save often leaves nothing eligible; in that case there is no Clean button. If naturally occurring redundant leftovers are available, **Clean temporary files** cleans only verified files from completed Save/Backup work and reports a confirmed count. **Stop** ends further work after the current check/deletion settles. Project content, originals, unresolved recovery and small operation records remain. Do not create artificial leftovers for this step; leave it unobserved if none exist.

5. **Local copy and refusal:** In Projects, open one project's Actions → **Remove local copy…**. Its title identifies the target. The currently open project asks you to open another project first; an unsaved or protected project explains its specific blocker and offers no removal confirmation. Import-bearing, migration-bearing, AI-linked, newer local or unsupported operation history must remain protected. Use another disposable project to make the target inactive. If it is eligible, one dialog identifies the saved file, local size and consequence: that saved file is needed to reopen. Cancel keeps the local project. Confirming removes eligible local content and the library entry, keeps the saved `.collie` and small records, and shows the confirmed removal count. Opening the saved file afterward follows the existing validated Open flow.

6. **Existing recovery and uncertain outcomes:** Open **Recovery history and backups** only when needed. Existing backup/copy inspection and historical Reset recovery still offer their existing restoration actions. If you already have an unconfirmed cache/version/temporary-file/local-copy action, **Check … outcome** reads its original receipt without repeating deletion. An unfinished local-copy dialog can be closed and reopened from its existing **View operation** notice. Reopening the app restores that pending action; it must never automatically resume removal or temporary-file cleanup. Do not force a crash or fabricate a failure to exercise these branches.

7. **Drafts, keyboard and layout:** Leave unsaved writing in another project while using the storage actions on a disposable target. Return to it: the editor's text remains. Try keyboard navigation, Escape/Cancel in deletion dialogs, a narrow window and increased zoom. Paths wrap, controls remain reachable and focus remains usable after canceling or deleting an item. About and other settings links now consistently call this page **Storage**.

Report the action, visible wording and result for mismatches. Any unavailable eligibility, native deletion/reopening, existing interrupted outcomes, focus and accessibility scenarios remain unaccepted until observed.
