# R2-02 — Compact commands and quieter writing

October 7, 2026. User-owned manual acceptance; no runtime results recorded.

Use a disposable project and disposable Save/backup destinations. Select the repository's pinned Node 24.21.0 / npm 11.19.0 toolchain and launch the development app yourself with `npm run dev`. The assistant has not launched the app or run automated tests.

1. **Inspect Write.** Open the disposable project. Return to work is absent while already in Write; the Manuscript eyebrow, Save and local protection disclosure, and Project dropdown are gone. The main title and optional subtitle remain. When there are no actual notices or operation results, no empty session-status strip adds space above the title. Existing header/content padding remains.
2. **Use the compact controls.** Open Settings with the gear, App menu with the hamburger, and Research with the book icon. They open the same destinations/menu as before. Export keeps its label. From another destination, Return to work remains available and follows the existing guarded return route. Ordinary page transitions still follow R2-01's page-top behavior.
3. **Discover names and keyboard behavior.** Hover over the new icons long enough for their descriptions, then reach them with Tab. Names/descriptions and visible focus indicators identify each command. Open Save options and App menu with the keyboard, choose an item, and dismiss a menu with Escape. The menus remain opaque and focus returns appropriately. An unavailable Save remains discoverable but does not run when activated.
4. **Save a disposable project.** In a new disposable project, select the disk icon and choose a disposable `.collie` destination in the native picker. Edit and Save again. The split control stays compact, with separate disk and chevron targets. While saving, a static hourglass badge identifies the busy state and the primary action is unavailable. Save options remains usable; View file progress and actions leads to the existing file controls. If the operation finishes too quickly to observe, record the busy state as unobserved.
5. **Inspect progress and cancellation when available.** During a file operation, open its progress/actions view. It shows actual phases and the existing Cancel action when cancellation is still allowed. After the cancellation boundary it describes finishing instead. Required replacement choices remain actionable. Complete or resolve any operation before continuing; Save is still distinct from local protection and cloud upload.
6. **Reach project details and history.** Use Save options → File details and project actions while idle. Change the disposable project's title/subtitle, return to Write, and confirm the new metadata appears without losing the manuscript or its applicable undo history. Use the existing project navigation outside Write to reach History. No new history shortcut is part of this stage.
7. **Inspect shared styling.** Visit Write, Settings and Research, and open editor Style/Insert/More tools, outline view, Save options and App menu. Idle toolbar/navigation buttons and dropdown triggers are transparent; primary Create/New chat/Send/confirmation actions retain filled styling. Selected pages, pressed commands, expanded triggers, hover, unavailable and keyboard-focus states remain distinguishable. Menu, tooltip and dialog surfaces remain opaque. Repeat in light/dark and high-contrast modes, reduced motion, a narrow window and at 200% zoom. Save's static badges retain their meaning without animation.
8. **Observe real failures only.** If Save becomes unconfirmed naturally, its warning badge and Retry pending Save name identify the retained request; retry must not become Save As, and conflicting Save As/Backup/Locate actions remain unavailable. If local manuscript protection fails naturally, a visible Retry local protection action remains available with the existing guards. Actual file/storage/access/draft errors keep their notices and recovery actions. Do not induce failures or alter account/project files; report unavailable cases as unobserved.

Report the step, visible outcome and any naturally occurring problem. Native Save/Cancel behavior, exact rendering, focus, screen-reader announcements and contrast remain awaiting Josh's observations. R2-03 outline collapse, wider editor and outline-row changes are not implemented here.
