Stage 9 complete. As a user:

1. With disposable projects or copies of existing `.collie` files, run `npm run dev`. Create/open a project; its writing should remain available, with Outline and History controls. Older working data should migrate through retained copies, without modifying the selected archive merely by opening it.
2. Add a part, a chapter and several sections using **Add outline item…**. Use **Move…** to nest the chapter under the part and sections under the chapter. Titles, status and synopsis should persist after switching sections; invalid parent kinds should be unavailable or rejected.
3. Reorder sections by dragging one before another, then repeat with keyboard-operated **Up**, **Down** and **Move…** controls. The displayed order should change while writing and formatting stay with their sections.
4. Write several paragraphs with headings, a list or a table, then protect the writing. Keep a named checkpoint such as “Before reorganization.” Split the section at a listed block boundary; the two sections should contain the original blocks in order, with complete lists/tables kept together.
5. Merge one section into another. The target should contain its original writing followed by the source writing. Enable **Show archived, trashed and merged items**; the merged source should offer a link to its replacement.
6. Archive or trash a section or containing chapter, show removed items, and restore it. Its writing should remain readable while removed and editable after its own and its parents’ states are restored. Trying to remove the last active section should leave the entire change unapplied.
7. Edit over at least 35 seconds, let local protection finish, and refresh history. Coalesced **Human editing** checkpoints should appear. Select the named checkpoint and expand changed items; earlier and current text, outline placement and metadata should appear side by side.
8. In a section with several paragraphs, remove a whole paragraph including its paragraph break, protect the edit, and refresh history/targets. Removed block identities should remain visible. Use **Repair target…** to choose an existing block explicitly; the chosen target should be labeled, and opening it should navigate to that section/block without changing its text.
9. Compare and restore the named checkpoint, confirming the restore. The earlier manuscript and outline should return. Refresh history and restore **Before restore**; the later writing should return too. Both restores should leave the chosen file needing Save until a file save succeeds.
10. Save, close/reopen, and create a backup of the disposable project. Restore the backup to an independent project; its outline, retained checkpoints, text, tables and any existing managed images should remain available. Changing that copy should not change the original.
11. Refresh history and review retention sizes. New history should have no eligible cleanup. If this project already has automatic checkpoints older than 30 days, review their removable size and cancel once; nothing should change. After keeping a separate backup, confirmed cleanup should retain manual/pre-change checkpoints and current writing. Do not change the computer clock to manufacture old history.
12. Repeat essential outline/history actions using only the keyboard and try increased zoom. Controls, comparison text and confirmation choices should remain reachable and readable. Report any focus, layout, preservation or responsiveness problems before proceeding to Stage 10.
