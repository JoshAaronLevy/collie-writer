# R2-03 — More writing space and a clearer outline

October 7, 2026. User-owned manual acceptance; no runtime results recorded.

Use a disposable project with two or more writing items and some nested items. Select the repository's pinned Node 24.21.0 / npm 11.19.0 toolchain and launch the development app yourself with `npm run dev`. Begin in a wide window and exit focus mode if it was previously remembered. The assistant has not launched the app or run automated tests.

1. **Hide and show the outline.** In Write, use the panel icon before the companion controls. Hide outline removes the pane and its resize strip, giving that space to the manuscript. Show outline remains available and restores the pane, its prior width, selected item, branch expansion and filter choice. The project/item selection does not change and no Save dialog appears.
2. **Try all pane combinations.** Open Notes or Sources, hide/show the outline, then close the companion and repeat. The manuscript fills the remaining space in all four combinations without an empty outline/companion column. Resize the outline, hide it, and reopen it; its chosen width returns. In a larger window, the manuscript grows beyond the former centered width limit. Existing images/tables should remain contained.
3. **Use focus mode.** With your preferred outline and companion choices, enter and exit focus mode. Both panes disappear temporarily; exiting restores those choices. On desktop, Show outline remains available during focus mode; selecting it explicitly exits focus mode and reveals the outline. Narrow windows use the existing Exit focus mode control instead.
4. **Check session memory.** Hide the outline, visit Settings or Research, and return to Write. The outline remains hidden and ordinary page scrolling follows R2-01. Exit focus mode, close normally, and relaunch: in a wide window the outline starts expanded again. Its saved width and companion preferences remain available; collapse itself is session-only.
5. **Keep writing and focus.** Type a short passage, use the outline toggle, then deliberately return to the editor and use Undo. The text and applicable undo history survive. A pointer toggle should not force typing focus into the editor or create a Save operation. With keyboard focus in the outline, use the pointer to hide it: focus should move to the surviving toggle. Tab skips the hidden outline and its removed resizer. Ordinary local draft protection still follows its existing behavior.
6. **Use the outline controls.** Add item occupies most of its row and has a plus icon. The adjacent compact Outline view icon opens an opaque menu with the existing removed-item and expand/collapse commands. Add a disposable Chapter/Section, then inspect a nested item with a long title. Row actions and branch toggles remain separate, titles wrap, and selected titles/metadata have space beside the selection marker.
7. **Check labels and forms.** Routine rows show their item kind without draft/review/complete suffixes. Item details and manuscript Details still show and edit editorial status. On a disposable item, archive and restore it through the existing row actions and removed-item filter; removed state remains visible. Open an Add item or Item details dialog, enter temporary text, and resize the window. The same form remains open with its values and original target. Background outline/focus controls do not act through the modal; cancel explicitly when finished.
8. **Check narrow and zoom layouts.** Narrow the window or use 200% zoom until the Outline/Manuscript switch appears. It replaces the desktop outline toggle. Open Outline even if the desktop choice was collapsed, then widen the window again: the desktop choice returns. If focus was inside the outline when it became hidden, the Show outline toggle receives it, unless a dialog/composition/background guard prevents focus movement. Menus and long titles remain usable. Repeat keyboard navigation and your usual light/dark/high-contrast settings.
9. **Check composition and retained work.** If an input method is available, attempt a layout change while composing, then finish composition and try again. The layout change waits for deliberate activation after composition, with no lost text. When a modal is open or the app is in the background, the new focus-return path must not steal focus. Existing pending-draft, Save and recovery controls remain available; record unavailable scenarios as unobserved.

Report the step, visible result and any naturally observed problem. Actual layout, native focus, screen-reader descriptions, IME and accessibility remain unaccepted until Josh supplies observations. R2-01 and R2-02 manual acceptance remain separate; completing this implementation does not establish release readiness.
