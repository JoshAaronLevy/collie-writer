## Method and field map

The stable types live under [`codex-rs/app-server-protocol/schema/typescript`](https://github.com/openai/codex/tree/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript). A method classified as network-capable must not be called by ordinary Collie status polling. The runtime can do work independently of an individual RPC, so a local handshake is not a process-wide no-network guarantee.

| Method / event | Selected fields and interpretation | Network / later owner |
| --- | --- | --- |
| `initialize`, then `initialized` | `InitializeParams`: `clientInfo` with app name/title/version and capabilities. Initialize once per child; correlate bounded RPC IDs. | Handshake is local; child startup itself may network. CD02/03. |
| `account/read` | `GetAccountParams.refreshToken: false`; response `account` and `requiresOpenaiAuth`. Accept only managed ChatGPT account type. Email/plan are presentation, not stable authority or funding proof. | **May network**: pinned account processor discovers workspace routing and can recover authorization. Explicit login/resume reconciliation only; normal `ai.status` reads main's cache. CD02. |
| `account/login/start` | `LoginAccountParams` selects only `type: chatgpt`. Response must have matching type, `loginId`, `authUrl`. No `apiKey`, external-token or device-code fallback. | Browser/auth networking. Main correlates app attempt ID to runtime login ID and opens only validated HTTPS `auth.openai.com` authorization URLs. Codex owns loopback callback. CD02. |
| `account/login/completed`, `account/updated` | Completion: `loginId`, `success`, bounded/sanitized failure; updated auth mode/plan. Require matching live attempt and authoritative subsequent state. No raw URL/token/error forwarding. | Notifications do not themselves request network; they report an explicit auth lifecycle. CD02. |
| `account/login/cancel` | `CancelLoginAccountParams.loginId`; response status is cancellation disposition, not evidence that a late login cannot exist. | Local cancellation; already-issued auth traffic can finish. CD02 must settle the exact attempt and refuse stale adoption. |
| `account/logout` | Empty successful response; then account-updated notification. | **May network**: pinned source uses `logout_with_revoke` and related cache refresh. Local logout must be distinguished from global/confirmed remote revocation. CD02/07. |
| `model/list` | `limit`, `cursor`, `includeHidden: false`; `data`, `nextCursor`. Read `model`, `displayName`, `inputModalities`, supported/default effort. Bound pages and reject loops. | Online-if-uncached catalog in source; background online refresh also exists. Explicit connection/resume/model refresh owner only. Catalog is not funding or next-request acceptance. CD03. |
| `thread/start` | Selected model, isolated `cwd`, approval/sandbox, explicit instructions, `ephemeral: true`. Response has `thread.id`, model/provider, `instructionSources`, sandbox and other metadata. | Treat as network-capable config/model/session preparation, although it is not `turn/start`. One fresh thread per reviewed attempt. CD03. |
| `turn/start` | `threadId`, selected model, one text `input`, applicable sandbox/approval, optional main-owned `outputSchema`. Use documented default effort unless a captured option is implemented. | Remote inference and possible runtime-managed auth recovery/retry. Receipt alone is not turn completion. CD03/04/06. |
| `turn/started`, `item/agentMessage/delta`, `item/completed` | Correlate thread/turn/item IDs, including early notifications. Deltas have `delta`; completed agent messages have `text` and nullable `phase` (`commentary` / `final_answer`). Null phase is unknown. | Receive actual output only. Preserve displayable text separately from an unambiguous completed structured result; do not concatenate progress into JSON. CD03/06. |
| `turn/completed` | Inspect the actual terminal `turn.status` and error. Only completed success can reach structured-result validation; partial/failed/unknown output stays inert. | Incoming event, not billing rollback. CD03/04. |
| `turn/interrupt` | Exact `threadId`, `turnId`; acknowledgment is distinct from terminal interrupted state. | Local request can affect an already remote turn. No refund/no-dispatch claim. CD03/07. |

Specific type sources: [account/read](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript/v2/GetAccountParams.ts), [login](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript/v2/LoginAccountParams.ts), [fresh thread](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript/v2/ThreadStartParams.ts), [turn and output schema](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript/v2/TurnStartParams.ts), [message phases](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript/v2/ThreadItem.ts).

The [account processor](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server/src/request_processors/account_processor.rs), [workspace-routing read](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server/src/request_processors/account_processor/workspace_routing.rs), [catalog processor](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server/src/request_processors/catalog_processor.rs), and [model-refresh worker](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server/src/models_refresh_worker.rs) are the stronger evidence for side effects. The worker refreshes immediately and on a 4-minute-30-second loop. Stable published account types omit some routing fields present in the source; CD02 must reconcile the actual selected stable RPC contract, not assume extra fields are always available. Never read raw auth files just to compensate for a missing identity field.

## Credential namespace and lifecycle

The selected design is `cli_auth_credentials_store = keyring`, `forced_login_method = chatgpt`, an isolated stable Codex home under the verified Collie development working root, and one session-owned child at a time. No `auto` fallback, default-home copying, `ACCESS_TOKEN`, API key, login-method fallback or commercial client ID is allowed. Main metadata cannot substitute for authenticated state on restart: show saved-needs-resume until an explicit resume establishes it.

Pinned [auth storage](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/auth/storage.rs) derives the direct keyring key from the canonical Codex-home path's SHA-256 prefix (16 hex characters), prefixed `cli|`, under service `Codex Auth`. Therefore a stable distinct canonical home provides a supported distinct namespace on the direct backend. The direct keyring path fails on unavailable storage; only the separately implemented auto backend falls back to a file. The alternate secrets backend uses encrypted local secrets with a keyring-held key. [Backend selection](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/config/auth_keyring.rs) depends on the `secret_auth_storage` feature; CD02 must establish the effective backend and fail if secure isolation is not available. Do not infer that every platform/config uses the direct backend. CD01 creates no home, token or keyring entry.

Codex owns managed refresh. Its [auth manager](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/auth/manager.rs) serializes refresh internally; this is not authority to run multiple independently rotating children. Use one owner and close idle children through main shutdown. An idle authenticated process is distinct from unfinished work. Browser login's [server implementation](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/login/src/server.rs) defaults to the OpenAI auth issuer and constructs its own authorization URL/callback; Collie must not impersonate the built-in client or reconstruct/forward that URL in renderer navigation.

## Isolation capability map and remaining engineering

| Control found in pinned source/types | Required interpretation |
| --- | --- |
| `ephemeral` thread, explicit base/developer instructions, `project_doc_max_bytes` | Supported basis for fresh context and suppression. CD03 must trace every instruction, memory and content persistence path; ephemeral does not prove absence of all logs. |
| `forced_login_method`, strict keyring mode, managed auth requirements | Necessary auth confinement. Effective managed policy takes precedence; fail on incompatible policy rather than bypassing it. |
| `shell_tool`, `unified_exec`, `view_image`, `multi_agent`, `multi_agent_v2`, apps, hooks, plugins and recommended-plugin feature controls | These are independent surfaces. Empty plugin/MCP maps are not demonstrated discovery suppression. The feature/extension registry and model-driven tools also need constraints. |
| `web_search`, sandbox policy, shell environment policy | Tool network and provider network are separate. A read-only sandbox alone allows reads and is not a no-tool guarantee. |
| `instructionSources` and unexpected server requests | Defense in depth after setup; not proof that undisclosed context/tools could not run before the event. |
| `disabledPluginIds` | Pinned response documentation says this list does not yet filter plugin capabilities. Do not use it as enforcement. |
| Stable `SandboxPolicy` | The published 0.160.0 type has `readOnly` with `networkAccess`, not current web examples' restricted-read root fields. Do not send invented fields or claim a root restriction from them. |

Sources: [feature registry](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/features/src/lib.rs), [tool construction](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/core/src/tools/spec_plan.rs), [config layering](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/config/src/loader/README.md), [sandbox type](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript/v2/SandboxPolicy.ts), [thread response](https://github.com/openai/codex/blob/rust-v0.160.0/codex-rs/app-server-protocol/schema/typescript/v2/ThreadStartResponse.ts).

The config loader includes system, project, user, managed/cloud and MDM layers; some managed sources outrank CLI overrides. Tool construction includes model-driven utilities even outside shell/MCP. Full isolation is unresolved engineering, retained as a real refusal. CD03 must establish supported suppression/containment before dispatch; if the pin cannot do it, select a justified exact replacement with its dependency/notices changes then. This document establishes suitability for the CD01 protocol foundation, not certification of a ready text-only runtime. No runtime probes or generated schemas were used.
