# AI provider eligibility — I01 evidence and route decision

**Read October 1, 2026. Specification complete; no provider approved or enabled for Collie.** This is a dated reading of official documentation, not legal certification, a provider approval, an account inspection, or native/funding acceptance. No SDK was installed/invoked, no account was registered or signed in, no inference was sent, and no provider was contacted.

The [improvement plan](../../app-improvement-plan.md) requires the writer's own eligible subscription, browser sign-in, no copied API key, and no purchased-credit/top-up fallback. This record preserves that product requirement. A coding-oriented runtime is acceptable for writing; usefulness remains a future user assessment. The [experience specification](../design/app-experience.md#s03--optional-ai-connection) defines the UI without asserting that any connection works today.

## Disposition

**OpenAI remains the preferred first provider.** The documented conditional integration selected for further work is **approved Sign in with ChatGPT authentication plus isolated Codex app-server execution**. Retain the preference for `@openai/codex-sdk` if its pinned release explicitly supports the eventually approved authentication route; no such SDK bridge is established here. Do not invent a `login()` method or pass an arbitrary OAuth token through an undocumented adapter.

I01 is complete with these dispositions. I10 cannot be called an implemented provider integration until the relevant gates below are resolved. I02–I09 do not depend on them. Grok Build is a later candidate; Claude needs permission clarification/approval; Google's consumer route remains deferred. A runtime existing is different from Collie being allowed and able to ship it.

**Endpoint naming is not billing proof.** The documented subscription OAuth route can use the public Responses endpoint; this is distinct from sending a user's paid API key. Conversely, seeing a Codex process or ChatGPT token is not enough to prove that credits cannot be consumed. Do not prohibit the documented endpoint merely because it includes `/v1`, and do not permit an API-key fallback because it uses the same endpoint. [Subscription inference contract](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

Conditional engineering sequence for I10/I11, after permission/funding gates:

1. Record the actual commercial route, applicable terms, supported platforms, auth registration, and approved branding. The published open-source dynamic registration is evidence of protocol shape, **not authorization to register paid Collie through it**.
2. Main owns the sign-in attempt, approved browser destination, callback listener/transport, and validated result. For the documented local flow, state, nonce, PKCE, exact loopback redirect, ID-token validation, granted scopes, issued client identity, and stable host identity are distinct requirements. Keep them separate from renderer state. The commercial route must explicitly establish which contract applies. [Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).
3. Store each validated account/client registration separately in protected device-local storage. Serialize refresh for rotating sessions, and report unconfirmed remote revocation honestly while clearing local access. Do not mix same-email registrations. [Accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions).
4. Start an isolated child with only the approved configuration and short-lived credential transport. The documented app-server adapter passes the token through a child environment and configures Responses; it does not require the old Codex-managed login. Its model catalog is not entitlement proof. [Adapter](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server).
5. Refresh before a request when needed. The documented environment-token configuration requires app-server restart to pick up a renewed token. Resume only if retained context still matches the user's selected scope. The preview route requires streamed, non-stored requests and explicit history; it has unsupported fields, including `max_output_tokens`. Do not invent a request parameter to impose a bound the route does not support. Use supported limits/context boundaries and record cancellation's limitations. [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).
6. Expose only bounded app operations. App-server documents `turn/interrupt`; preserve partial output and distinguish requesting cancellation from receipt of a terminal outcome. Do not expose its arbitrary execution methods through preload. [App-server lifecycle](https://learn.chatgpt.com/docs/app-server).

Do not send a model probe during sign-in. An account-specific model catalog may inform choices but is not a guarantee that the next turn will succeed. Eligibility authorizes an attempt only after the required funding/session evidence; the service still authorizes each actual request. A refusal preserves the local draft and is not retried automatically.

For the approved Sign in with ChatGPT route, the current branding action is “Continue with ChatGPT”; guidance includes a first-use plan explanation and usage management. I11 must reconcile the actual approved UI requirements with Collie's no-credits/no-upsell policy. Never copy illustrative “buy credits” controls into Collie. [UI/UX guidance](https://developers.openai.com/siwc/ui-ux-guidelines).

## Funding semantics and the unresolved control

**Required by Collie:** for every submitted operation and each internal continuation/model/tool request, the provider enforces that only the user's included subscription allowance can fund it. At exhaustion, the request must stop/refuse without using purchased credits, shared paid balances, top-ups, or API-key billing. This must hold during concurrent usage and account-setting changes, not merely at a balance preflight.

OpenAI documents a user control permitting other apps to use credits after plan limits. That is relevant evidence of a funding choice, but these pages do not establish how Collie can bind and authoritatively enforce the disabled-credit state for the complete operation. Do not substitute a checkbox in Collie, a screenshot of provider settings, or a zero balance observation for the required guarantee. [Provider usage controls](https://learn.chatgpt.com/docs/sign-in-with-chatgpt).

Acceptable future evidence could be an official included-only request capability or a provider-enforced client/account policy whose scope, readability, change semantics, and handling of internal calls establish the same guarantee. Record its exact supported field/policy and response semantics when supplied. **No such field is invented here.** A dollars/tokens budget is not automatically an included-only funding selector. Stop/cancel cannot undo already consumed allowance or prove that no credits were charged.

For Grok, existing credits being used after the weekly allowance is exhausted makes no-API-key authentication insufficient. For Claude, the paused credit announcement must not be used either as current metered-only policy or as proof of included-only commercial rights. Each adapter requires its own evidence; approval of OpenAI does not carry across providers.

Use an app-owned runtime directory/profile distinct from developer/user Codex, Claude, Grok, or Google homes. Never change the machine's global environment or default provider settings. For an approved child, build a documented allowlist of environment/config values, excluding ambient API keys, alternate endpoints, cloud billing, imported hooks/plugins/MCP, and unrelated instruction files. No project workspace is an agent working directory. A read-only filesystem sandbox alone is insufficient: initial writing features do not need arbitrary file reads either.

Keep access/refresh/ID tokens, client/account/workspace/host IDs, runtime files, and opaque resume handles out of portable projects, exports, renderer state, logs, and support previews. The renderer may receive a bounded recognizable account label where needed, never secret credentials. Tokens are not placed in argv or diagnostic URLs. Secure-store failure makes the connection unavailable rather than enabling plaintext fallback.

The worker persists human-readable user/assistant messages, exact approved context/provenance, proposals, and decisions. It does not make inference requests or read credentials. Copy/restore creates independent project identity and no live provider-session authority. Local history remains readable/exportable while disconnected; local organization uses edit rights and needs no inference session.

## Distribution and desktop channel requirements

I01 has selected no provider package version and downloaded no runtime. An enabled adapter must later record exact package/binary versions, OS/architecture support, upstream license/notice locations, redistribution basis, signature provenance, runtime resource locations, and update policy. Prefer an approved bundled runtime for predictable desktop UX; an installer script or executable found on PATH is not a trustworthy distribution contract. If redistribution is unavailable, record the dependency and its UX consequence rather than adding a silent downloader.

Direct macOS arm64/x64 and Windows x64 are the intended first targets, subject to each chosen runtime's actual support. Existing signing/notarization/native gates remain. Microsoft Store's selected EXE route uses the same direct artifact and requires its independent review; it does not grant provider rights. MAS remains unsupported/blocked by existing native requirements and is not enabled by a working direct provider. Linux/WSL instructions in upstream documentation do not expand Collie's product scope.

Disable runtime self-update/background downloads through supported configuration or hold packaging unresolved. Grok documents `--no-auto-update` for headless/ACP use; this is useful evidence, not a complete packaging decision. [Headless integration](https://docs.x.ai/build/cli/headless-scripting).
